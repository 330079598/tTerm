# 第三方代码登记

本文件登记从 Alacritty、nyaterm、gpui-kit 等仓库复制进 tTerm 的代码。规则见 [README 执行规则第 6 条](README.md#2-执行规则)，要点如下：

- 每个复制进来的文件在文件头注明来源仓库、来源提交、原路径、许可证与修改说明，并在本表登记。
- 不得复制 Zed 中 GPL 许可的 crate（`terminal`、`terminal_view`、`editor`、`workspace`、`ui` 等）的代码。终端部分可以阅读 Zed 源码借鉴思路，但不复制，见[技术选型第 5 节](tech-selection.md#5-终端)与[决策 008](decisions/008-zed-terminal-reading.md)。
- 复制进来的代码同样受 AGENTS.md 的大小限制；超限文件在合回 `GPUI` 之前拆分，不加入基线。G1 之前的验证分支可以暂不拆分，见 P0-09。
- tTerm 使用 MIT 许可，复制进来的 Apache-2.0 文件仍属 Apache-2.0：保留原许可声明，在文件头注明修改，发行包中附带 Apache-2.0 全文与第三方声明（P4-25、P5-02）。
- 来源仓库有 `NOTICE` 时一并保留其内容。nyaterm 在固定提交上没有 `NOTICE`。

登记细节：

- P0-19 没有复制外部第三方实现。`crates/tterm-gpui/examples/p0_19_drag_out/native.rs` 改编自本仓库 MIT 代码 `src-tauri/src/drag_out/windows.rs`，提交 `ede176759023f3f33af251815a7177d896bfa677`；文件头已注明原路径、提交与修改。`nyakang/zed` 的文件导出补丁仅参考 P0-07 的评估，没有复制源码、注释或测试，也未引入补丁。

- Alacritty 在该提交没有 `NOTICE` 文件；仓库中的 `LICENSE-APACHE` 与 `LICENSE-MIT` 是许可文本，复制进来的文件仍按 Apache-2.0 使用，发行包附全文的要求见 P4-25、P5-02。
- 测试文件（`*/tests.rs`）是由本卡按行为新写的，不复制 Alacritty 的测试代码；URL 的用例数据取自 Alacritty 的两个 URL 测试，其余是本卡构造的。每个期望值在测试里注明依据。
- `crates/tterm-terminal/src/hint/path.rs` 不来自 Alacritty：Alacritty 只识别 URL 与 OSC 8 链接，没有裸路径规则；这里的路径规则是 tTerm 自己写的，因此不登记来源。

### Lucide X icon (P0-24 Dialog)

Generated by `scripts/generate-lucide-icons.mjs` from `lucide-react` 1.48.0 (`dist/esm/icons/x.mjs`). The SVG is ISC licensed by Lucide and is used as a single-colour GPUI alpha mask.

P0-24 Dialog 返工另生成 `triangle-alert.svg`（React 的 `AlertTriangle` 别名），同样来自 lucide-react 1.48.0 的 `__iconData.node`，ISC 许可。脚本解析完整 `__iconData`，以兼容带 `aliases` 的图标。

P0-24 Dialog 第 4 轮另生成 `info.svg`（Lucide Info），由同一脚本读取 lucide-react 1.48.0，ISC 许可，用于生产 Info Dialog。
