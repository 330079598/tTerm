# React 参照端页面状态清单（W0-05 初稿）

本清单是 P3/P4 逐屏比对的 React 参照端目录。状态来自 `src/components/`、`src/routes/` 和 `src/contexts/` 的条件渲染、异步分支、事件监听和 `invoke` 调用；没有把业务状态藏在夹具里。每行都给出触发状态所需的数据和交互。`[平台]` 表示必须在相应系统核对，`[人工]` 表示当前工具只能人工判断（窗口模糊、系统装饰或真实文件选择器）。

## 读法与证据约定

- `数据` 写出组件实际读取的 `invoke` 命令、事件、本地设置或类型；命令返回值必须在夹具中以 `src/types` 的真实类型标注。
- `交互` 写出进入该状态的最短操作，例如“点击传输按钮”“悬停第 2 行”“按 Escape”。悬停、拖拽、原生文件/目录选择器和系统窗口装饰需要在捕获脚本中增加动作或列入 `[人工]`。
- `平台/模糊` 只在有平台差异或窗口模糊时填写；空白表示普通客户区。`macOS/Windows` 采用 `parity/screens.json` 的平台块，Linux 按 `ui-parity.md` 5.3 人工截图。
- `ui.*` 是 P0-24 已完成的原语屏，保留原 ID 并标记“已完成（P0-24）”。

## 组合数与工具缺口

基础状态预计约 170 个（本稿 150–180 的中位估计；最终以夹具注册测试的 ID 数为准）。每个状态需要浅色/深色 × 默认/孤岛 `ui_style` × 100%/125% 三个自动维度，窗口模糊开/关再作为人工维度，因此自动截图约 `170 × 2 × 2 × 2 = 1,360` 张；若把模糊也复制成截图文件则是 2,720 张，报告仍按状态合并。

现有实现的支持情况：

- `src/parity/main.tsx` 已读取 `?theme=` 和 `?scale=`，并调用 `applyUiScalePercent`；`capture.mjs` 把清单的单一 `uiScalePercent` 传给每屏，故 125% 不能从清单选择。
- `parity/screens.json` 只有全局 `theme`、`uiScalePercent`，没有 `ui_style`、状态级组合或 blur 字段；`fixtures.ts` 也没有风格/缩放维度。
- `src/parity/tauri/core.ts` 能按 command 返回值、reject、pending 和参数分支；事件 mock 能 `listen/once/emit`，Channel 只能由测试主动 `sendChannelMessage`，没有按屏幕自动推送事件的描述文件。原语屏之外的 command 都会进入 `__PARITY_MISSING__`。
- `capture.mjs` 已支持 `--platform macos|windows`、WebKit/Edge、DPR 2/1；没有 Linux 自动截图，也没有真实 Tauri 窗口模糊采集。

实施计划需要把 `screens.json` 升为“每个状态的 `themes`、`uiStyles`、`scales`、`blur` 元数据”，让 `capture.mjs` 为组合生成稳定文件名；`main.tsx` 在挂载前写入 `data-ui-style` 并把 125% 传给 `applyUiScalePercent`。夹具格式增加 `events`（事件名、payload、延迟）和 `channels`（Channel 消息序列），仍由真实 `src/types` 类型约束。模糊只记录是否需要 `[人工]`，不进入 SSIM/颜色比较。
