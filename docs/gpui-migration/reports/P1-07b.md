### Tauri 入口与扫描

执行：

```sh
rg -n 'tauri::|AppHandle|TauriEventSink::new' src-tauri/src/sftp -g '*.rs'
```

完整结果见附件，每类剩余用途如下：

- `archive.rs`、`base.rs`、`delete/commands.rs`、`download.rs`、`edit.rs`、`permissions.rs`、`search.rs`、`upload/commands.rs`、`external/mod.rs` 的 `#[tauri::command]`：30 个 IPC 入口，均在入口清单。
- 上述文件的 `use tauri::State` 或合并导入：只供入口注入 Arc<AppServices>。
- `search.rs` 的 `use tauri::ipc::Channel`：仅用于 command 参数，入口包装成现有 TauriSearchResultSink 后交给服务，未改变结果流协议。
- `external/mod.rs` 的 `use tauri::{AppHandle, Manager, State}` 和 `sftp_external_edit_open` 的 AppHandle：仅在入口读取已初始化的 AppPaths，再传具体值。
- 同文件 `sftp_external_edit_list` 与 `sftp_external_edit_release_tab` 的 AppHandle：只在入口读取 Arc<AppServices>。这两个 async command 返回 Vec，Tauri 对包含生命周期的 State 参数要求 Result 返回，保留原 IPC 返回类型，故在入口用 AppHandle 读取服务。
- `search/contract_tests.rs` 的 InvokeResponseBody 与 tauri::Error：既有搜索 IPC 契约测试，验证 JSON 和 Channel 错误被忽略的行为。
- `search/real_sshd_tests.rs` 的 Channel / InvokeResponseBody：既有真实 sshd 测试适配器，收集并检查搜索结果，保留原断言。

生产代码中的非入口方法零匹配；SFTP 中 `TauriEventSink::new` 零匹配。全部 operations、连接层、删除批次与 watcher 没有 Tauri 类型。

## 偏差

- 第 1 轮确认点由本轮用户明确授权：允许修改所有非入口定义，P1-07d 已合并，外部编辑直接注入 AppPaths 和现有 OpenTargets。本轮未修改 services 字段、未新建平台 trait；P1-07c 的模块没有改动。
- 连接层、with_sftp 宏、SftpHost、删除批次和各 API 入口签名互相依赖。按本轮“每个提交可独立编译”的要求，将整条依赖接线放在一个提交，再单独提交回归测试。没有纯位置移动或 rename，不存在夹带逻辑修改的纯移动提交。操作提取到各自 operations 文件，原文件均未超出大小限制。
- 必要跨模块改动：`connection_context.rs` 新增 SFTP 具体依赖组装器；`agent_integration/remote.rs` 两个入口组装 SftpContext，传给 SftpHost；`background/mod.rs` 的关闭入口、`platform/tray_native.rs` 的菜单／托盘回调、`lib.rs` 的窗口／退出回调传具体 ExternalEditState。`lib.rs` 的启动清理与 reaper 同步传 AppPaths / runtime / pool，初始化顺序不变，路径未就绪时仍跳过清理。
- 外部编辑打开入口将 AppPaths 的读取结果作为 `Result<AppPaths, String>` 交给服务，只在创建新 session 的原位置传播错误；复用旧 session 与输入校验的错误优先级保持原样。
- 保留两个 Vec 返回入口的 AppHandle，原因见扫描说明；其余不再需要的 command 参数数量 allow 已删除，没有新增 allow / expect。原下载批次入口仍有 8 个参数，保留既有 command 例外。
