# P1-11f 主题纯逻辑移植到 Rust（macOS）

## 结论

完成（核心逻辑）：主题定义、调色板派生、外部主题导入、695 个内置主题的目录、自定义主题规范化与预设创建都已移植到 Rust；17 个 TypeScript 用例逐条转写，未带 TS 测试的模块用真实 TS 模块生成期望值后覆盖。未合并、未 push，未改动 `src/` 与 `src-tauri/`。

## 改动

- `92c81fdf` `:recycle: share the theme color layer from tterm-terminal`：新增 `tterm-terminal` 的 `theme` 模块（持久化字符串、颜色数学、JavaScript 兼容辅助函数），`palette.rs` 改为通过 `PaletteText` 派生，关键词高亮改用共享的 `color_to_hex` 并删除私有 `keyword_highlight/color.rs`。
- `eb528568` `:sparkles: port the theme catalog, imports and custom themes to tterm-core`：新增 `tterm-core` 的 `theme` 模块（预设、目录、派生、导入、自定义主题、预设创建），以及全部 oracle 与对照测试。
- `scripts/migration/P1-11f-oracle.mjs`：用 `typescript.transpileModule` 直接加载 `src/` 中的真实模块，生成 `docs/gpui-migration/reports/P1-11f-evidence/node.json`。
- `crates/tterm-terminal/src/theme.rs`、`crates/tterm-terminal/src/theme/js.rs`、`crates/tterm-terminal/src/theme/tests.rs`：`ThemeColors`、`PaletteText`、`OptionalText`、HSL/RGB/Hex 解析与格式化、透明度、JS `trim`/`Number`/`Math.round`/数字转字符串、UTF-16 `slice`。
- `crates/tterm-core/src/theme/{definitions,catalog,derivation,import,custom,utils,types}.rs` 及各自的 `tests.rs`：预设、目录、方案派生、五种主题文件格式、自定义主题规范化/合并/预设创建。
- `crates/tterm-terminal/src/palette.rs`：保留既有 `Rgba`、`TerminalPalette` 的绘制形式；`TerminalPalette::from_theme` 现在转调 `PaletteText::from_theme_colors`，不再维护第二套颜色数学。

### crate 划分

| crate | 内容 | 理由 |
| --- | --- | --- |
| `tterm-terminal` | `ThemeColors`、`PaletteText`、`OptionalText`、`THEME_COLOR_KEYS`、`TERMINAL_PALETTE_KEYS`、`Hsl`、`HslRgb`、`Rgba`、`TerminalPalette`、颜色解析/混色/HSL/亮度/对比度、`js_*` 辅助函数 | 绘制终端和关键词高亮都需要这些颜色类型；`tterm-terminal` 不能依赖 `tterm-core`，所以共享类型放在被依赖的一方。 |
| `tterm-core` | 六个预设、内置主题目录、方案到调色板的派生、外部主题导入、自定义主题规范化/合并、`createCustomThemeFromPreset` | 这些是应用层的主题业务，`tterm-core` 已经依赖 `tterm-terminal`，方向正确。 |
| 共享正则引擎 | `regress = =0.12.0`（`tterm-terminal` 原本已带 `utf16` feature，`Cargo.lock` 中已有该版本） | 需要 ECMAScript 的 `\s`/`\w`/`\d`、`i` 折叠与 `$` 语义，不能用 Rust `regex` 近似。 |

## 偏差

1. **时钟注入。** `createCustomThemeFromPreset` 和 `normalizeCustomThemes` 在 TS 中直接调用 `Date.now()`（同一对象内调用两次）；Rust 改为接收 `now: i64`，由一个值同时填入 `createdAt`/`updatedAt`。测试用 oracle 中的固定 `1700000000000`；真实调用方传当前毫秒即可。这样可测且不引入系统时钟依赖。
2. **目录加载是同步静态数据。** TS 的 `loadThemeCatalog` 返回 `Promise`，通过动态 `import()` 做代码分割，失败时把缓存置空以便重试。GPUI 原生端不需要 WebView 的代码分割，Rust 用 `include_str!` 在编译期嵌入目录，`load_theme_catalog` 同步返回 `Result<&'static [CatalogTheme], &'static str>`；编译期错误不能运行时重试。目录内容仍是同一份 `src/assets/themes/catalog.json`，695 个主题的 digest 已核对。
3. **懒派生颜色用 `OnceLock`。** TS 的 `colors` 是对象 getter；Rust 的 `CatalogTheme::colors()` 返回 `&ThemeColors`，首次调用派生并缓存。TS 测试里的 `Object.getOwnPropertyDescriptor(...).get` 断言没有 Rust 对应物，改为指针身份 + 值相等；派生结果本身逐字节一致。
4. **导入结果的 JSON 字段顺序。** `ImportedScheme` 的字段名、可选字段省略和值都与 TS 完全一致；但 TS 的特殊颜色属性顺序取决于主题文件里首次出现的行序（例如 Alacritty 用例先写 `text` 再写 `cursor`），Rust 结构体按固定的“name、palette、background、foreground、cursor、cursorText、selectionBackground、selectionForeground”序列化。JSON 对象消费方不依赖键顺序，导入结果也不会直接写入数据库（`ThemeImportDialog` 先用它派生调色板）；持久化的自定义主题顺序另有逐字节测试。
5. **未知命名键的顺序。** `serde_json::Map` 未开启 `preserve_order`，所以一个保存的主题若含多个未知命名键，Rust 写回时按排序后的顺序输出；前端自己写的主题只有 28 个已知颜色键和可选的终端已知键，这些路径逐字节一致。数字索引键按 JS 的枚举规则排在最前（已由字符串展开用例覆盖）。
6. **非声明类型的成员不被保留。** TS 的 `normalizeCustomTheme` 只检查 `id`/`name`/`colors` 的真值，因此理论上会保留数字 `id`、数字 `description`、字符串 `createdAt` 等；Rust 类型要求字符串/整数，非字符串的 `id`/`name` 会被丢弃，非字符串的 `description`/`baseTheme` 变成缺失，非整数的 `createdAt`/`updatedAt` 使用 `now`。前端只会写声明类型，且 `src-tauri` 的存储同样按类型读取；这是对损坏数据的收紧，已在此记录。
7. **字符串展开的代理对。** JS `{ ..."😀" }` 产生两个属性，值是孤立代理项 `"\ud83d"`/`"\ude00"`；Rust 字符串无法表示孤立代理项，`spread_entries` 用 U+FFFD 代替这两个单元，但键的数量和顺序仍按 UTF-16 单元计算。中文、组合字符等 BMP 输入与 TS 逐字节一致（见 `normalizedStringJson`）。孤立代理项的 JSON 也无法被后端 `serde_json` 读回，因此这类数据本来就不能持久化。
8. **`mergePresetThemeWithOverride` 的非规范覆盖。** 正常覆盖完全一致；若覆盖来自一个含 `null`/未知键的损坏自定义主题，Rust 合并时使用其类型化的 `colors`/`terminal`（`null` 变成默认值，未知键保留在类型侧），不会像 TS 的展开那样把 `null` 原样复制到合并结果。预设主题不持久化，且损坏数据不会由前端产生。
9. **`ThemeColors`/`PaletteText` 反序列化是严格形状。** `ThemeColors` 表示已解析的 28 个字符串 token，`PaletteText` 的必需字段也要求字符串；保存的主题必须通过 `normalize_custom_themes` 读取，后者接受缺字段、显式 `null` 和未知键（`PaletteText` 的 `cursorAccent`/`selectionForeground` 仍可显式 `null`）。这样避免了把“部分颜色”误当成完整主题。
10. **`catalogThemeFromScheme` 的 `name: null`。** TS 模板字符串会得到 `"catalog:null"`，Rust 的 `Option<String>` 把 `null` 与缺失都视为 `"undefined"`。目录 JSON 的每个主题都有字符串 name，此差异只在手写损坏数据时出现。
11. **`rgb_to_hex` 的 NaN。** 该函数在主题模块内只接收正则/有限数学产生的数字；TS 对 `NaN` 会输出 `#NaNNaNNaN`，Rust 的 `as u8` 会输出 0。这里明确把 NaN 排除在契约外，边界测试覆盖了负数、超过 255 和半整数。
12. **非法调色板转绘制形式。** `PaletteText::to_terminal_palette` 对无法解析的颜色回退到黑色；导入路径在进入这里之前已校验颜色，保存路径的非法值不会让程序 panic。

## 遗留问题

- Windows/Linux 的真实 GUI 主题应用与系统外观切换属于 P3-05；本轮只验证了纯逻辑和 macOS 本机构建/测试。
- 本轮未修改 `src-tauri`，因此没有通过真实 Tauri command 做数据库往返；持久化形状用 TS 的真实 `JSON.stringify` 与后端的 `serde_json::Value` 形状对齐，待 P1-07/P3-05 接线时再做端到端检查。
- 内置主题目录是 `src/assets/themes/catalog.json` 的编译期副本；主题库更新后需要重新编译，`the_catalog_digest_matches_the_oracle` 会提醒 digest 变化。
- 64 个被忽略的 zmodem/sshd 互操作测试需要真实 `sz`/`rz`/sshd，本轮没有为本机安装这些外部二进制。
