### 评估者修订

1. **Windows 上的路径都经过 ConPTY。** 本机的 WSL、系统 `ssh` 和 Windows 程序都经过 ConPTY，有些协议问题（鼠标、焦点报告）可能出在 ConPTY 而不在原型。某个协议在原型中不对时，先看 Tauri 版在同一路径（本地标签中运行同一条 `wsl.exe -d Ubuntu -- ...` 命令）是否也不对：两边都不对的，记为“与 Tauri 版一致，疑为 ConPTY 或路径限制”，不算原型缺陷，严重程度按对用户的影响另评。
2. **能自动的不要列为人工。**
   - 备用屏幕不需要输入：探针的 `--alternate-screen` 按时间分段执行：先在主屏幕打印标记行，等 3 秒；进入备用屏幕并画满一屏，等 5 秒；退出备用屏幕，等 3 秒后结束。三个阶段各截一张图，证明进入时清屏、退出后主屏幕内容原样恢复。vim、less 退出后的主屏幕恢复也按同样方式截图。
   - 宽字符、组合字符、emoji 不要通过 `--exec ... python3 -c "..."` 传递：多层引号容易出错。改为探针的 `--unicode`：打印一张固定的样例表，包括 CJK、全角标点、组合字符（`é`、`ä`、韩文组合字母）、emoji（单码点、`VS16` 变体、ZWJ 序列、肤色修饰、国旗）、制表符与框线字符。每行末尾放一个竖线 `|` 作为列尺，宽度算错时竖线就会错位。打印完不退出，等 Ctrl+C，截图时屏幕上没有 `[Process exited]` 干扰。
   - 鼠标探针支持指定模式组合，例如 `--mouse 1000`、`--mouse 1002,1006`、`--mouse 1003,1006`，没有 `1006` 时按 X10 编码解析。界面上显示当前开启的模式。
3. **全屏程序优先在 WSL 中运行**，它更接近 tTerm 用户连接 Linux 服务器的场景：vim 用 WSL 的 `vim`，并打开一个有语法高亮的文件（例如 `vim -c 'syntax on' /etc/bash.bashrc`），Windows 的 Git vim 作为补充。neovim 写作 `--exec wsl.exe -d Ubuntu -- nvim --clean`，不要写 `--exec nvim -- --clean`。
4. **less、man 选一定存在的内容。** WSL 的 Ubuntu 可能是精简安装，`/usr/share/doc` 下的文件与 man 手册页可能缺失。先用 `ls` 或 `man -w` 确认，less 可以用 `/etc/services`；man 手册页缺失时如实记录，不要换成别的命令冒充。
5. **vttest 列出具体章节与预期**，不要只写“主要章节”：至少 1（光标移动）、2（屏幕功能）、3（字符集）、6（终端报告）、8（VT102 插入与删除）、11 中的 xterm 颜色与鼠标部分。用 `vttest -l <日志文件>` 记录日志，日志放在 `docs/gpui-migration/reports/assets/P0-15/` 下。vttest 每屏都写了“应该看起来像什么”，人工清单中照抄这些说明作为预期。
6. **人工清单写成独立一节，按操作顺序排列。** 每一项写明：在原型中运行的命令、操作步骤、预期现象或预期字节（按 xterm 规范）、在 Tauri 版中怎样做同一项（本地标签中运行同一条命令）、结果填在哪里。同一条命令下的操作合在一起，减少反复启动。
7. **Claude Code 与 Codex 只截启动后的界面。** 如果启动时询问是否信任当前目录，截图后直接关闭窗口，不要替用户回答。
8. **提交的 gitmoji：** 探针脚本用 `:hammer:`（开发脚本），不用 `:sparkles:`。文件头注明它只能在 Linux 上运行（经 WSL 或 SSH），以及用法与退出方式。

本阶段只准备可复现的场景、证据格式和人工操作清单；确认后再执行。所有 GPUI 原型运行都使用独立数据目录 `com.stone.tTerm.gpui-dev`，构建前设置 `$env:CARGO_TARGET_DIR = 'D:\\code\\rust\\tTerm-build-P0-13'`，从仓库根目录运行 `cargo build -p tterm-gpui`，并使用该目录下的 `debug\\tterm-gpui.exe`。不启动或操作 Tauri 开发版窗口；Tauri 对照均记录为 `[人工]`。本机为 Windows，因此 macOS 与 Linux 场景在没有实际运行证据时标记“未验证”。每个场景结束后用 `Process.CloseMainWindow()` 关闭原型并确认没有残留进程。截图使用 P0-14 的 PowerShell `System.Drawing.CopyFromScreen` 方法，保存到 `docs/gpui-migration/reports/assets/P0-15/`，截图前调用 `SetForegroundWindow` 并确认窗口未被遮挡。

## 偏差

- **WSL 探针路径与当前 worktree 不符（已确认）。** 评估者已确认所有探针命令统一使用 `/mnt/d/code/rust/tTerm-P0-15/scripts/terminal-probe.py`；旧路径 `/mnt/d/code/rust/tTerm/scripts/terminal-probe.py` 不作为本卡证据。
- **截图脚本错误已修正。** PowerShell 7 缺少可直接编译 `System.Drawing.Common` 的引用，Windows PowerShell 5.1 的 `ArgumentList` 和函数参数 `$args` 也曾导致无参数启动。相关截图均未作为证据；最后改用 Windows PowerShell 5.1、显式引用 .NET Framework `System.Drawing.dll`、`.Arguments` 字符串和 `$argv` 参数重拍，并逐张打开核对。
- **WSL man 依赖不完整。** `ls -l /etc/services` 成功（12990 字节），`man -w man` 输出 `/usr/share/man/man1/man.1.gz` 同时报告 `man: can't resolve man7/groff_man.7`。仍按任务卡运行 `man man` 并截图；该警告记录为环境限制，不替换为其他手册页。
- **vttest 日志只有启动部分。** 自动部分只启动并截图，未进行菜单选择。已提交的 [vttest.log](assets/P0-15/vttest.log) 只记录了启动时的 DA1 查询（`ESC [ 0 c`），原型应答 `ESC [ ? 6 c`（VT102）；各章节的日志要等决策人按人工清单进入章节后才会生成。启动截图不能当作章节通过。这个日志放在了报告提交里，没有放进截图提交。
- **评估者修改了报告并补拍截图。** 第三轮评估后，应决策人要求，由评估者（Claude）直接修正报告，不再退回执行者，评估的独立性因此减弱。修正的内容有：ZWJ 与肤色两行实测的竖线列；Git vim 截图中的 `E349` 改为不能复现的观察，并换成评估者重拍的截图；新增焦点报告不外泄的检查；本条之前的 vttest 日志说明；“改动”中的提交哈希。评估者的复现脚本使用 Windows PowerShell 5.1 和 `PrintWindow`，不把原型切到前台也能截图。

## 人工清单（交给决策人）

每项先在 GPUI 原型中运行命令，再在 Tauri 本地标签中运行同一条命令；结果填回上面的兼容性表“现象/证据/与 Tauri 版对比”列，并保留截图和探针字节。

1. **vim/neovim/tmux/htop/less/git log。** 使用表中同一命令。vim：进入插入模式输入一行、保存、退出；预期文本插入、光标移动、状态栏和主屏恢复。neovim：输入、撤销、退出；tmux：创建窗口、切换窗格、退出；htop：上下移动、排序菜单、退出；less：Space/PageUp、`/pattern` 搜索、`q`；git log：Space/PageUp、`/commit` 搜索、`q`。Git vim 启动后先不按键，点击其他窗口再点回来，看底部是否出现 `E349`；原型和 Tauri 各做一次。每项记录原型和 Tauri 是否一致。
2. **备用屏幕主屏恢复。** 运行探针 `--alternate-screen`，观察 1 秒主屏标记、5 秒清屏备用屏、10 秒返回；预期返回后主屏标记仍在。与 Tauri 运行同命令对照，填三张截图结果。
3. **鼠标 X10。** 运行 `--mouse 1000`，单击、释放、滚轮；预期 X10 为 `ESC [ M` 后三个字节，各坐标/按钮字节加 32。探针逐行记录 `RX` 原始十六进制和 `MOUSE button=... modifiers=... x=... y=... action=press/release`。在 Tauri 同命令重复。
4. **鼠标 SGR 拖动。** 运行 `--mouse 1002,1006`，左键按下后拖动再释放、滚轮；预期 `ESC [ < b ; x ; y M`，释放为 `m`，拖动只在按键期间上报。在 Tauri 同命令重复。
5. **鼠标 SGR 全量。** 运行 `--mouse 1003,1006`，移动鼠标但不按键、拖动、滚轮；预期悬停也有 SGR `M` 事件。在 Tauri 同命令重复。
6. **括号粘贴。** 运行 `--bracketed-paste`，粘贴 `one\ntwo`；预期收到 `ESC[200~`、UTF-8 内容、`ESC[201~`，不把换行直接执行。Tauri 同命令重复。禁止 SendKeys、AutoHotkey 或其他模拟输入。
7. **应用光标键。** 运行 `--application-cursor`，按 Up/Down/Left/Right/Home/End；预期 DECCKM 下 SS3 `ESC O A/B/C/D/H/F`（具体键按 xterm 规范），与普通模式 CSI `ESC [ A/B/C/D/H/F` 对照。Tauri 同命令重复。此项与 P0-13/P0-28 已知真实 GPUI 事件遗留重叠，若两边一致标“已知”。
8. **焦点报告。** 运行 `--focus`，点击其他窗口再点击原型；预期失焦时收到 `RX 1b 5b 4f`（`ESC[O`），聚焦时收到 `RX 1b 5b 49`（`ESC[I`）。Tauri 同命令重复。未开启 1004 时不发送，这一项评估者已经自动检查过（`focus-no-leak.png`）。
9. **vttest。** 运行兼容性表中的同一条命令（`vttest -l` 后面用 `/mnt/d/...` 绝对路径；相对路径会落在 WSL 的主目录里）。依次进入：1 光标移动（光标按箭头移动、定位测试落在预期位置）；2 屏幕功能（清屏、滚动、擦除区域符合说明）；3 字符集（每种字符集字形可辨识）；6 终端报告（报告值与窗口尺寸/光标位置一致）；8 VT102 插入与删除（插入/删除字符和行保持其余文本位置）；11 xterm 颜色（颜色块顺序和色值正确）与鼠标（按提示启用模式并收到事件）。把 vttest 每屏写出的“应该看起来像什么”原文抄入日志备注，并在 Tauri 同命令重复。
10. **Claude Code / Codex。** 只启动并截图；若询问信任当前目录，截图后直接关闭，不回答、不发送消息。Tauri 对照 `[人工]`。
11. **Unicode。** 在 Tauri 中运行 `--unicode`，对照标尺记下每行竖线所在的列；原型实测见兼容性表，ZWJ 与 Skin tone 两行在第 44 列，其余各行在第 40 列。另外看 Combining 行的 `한` 是否组合成一个字，以及 `╭╮╰╯` 是否为圆角。
