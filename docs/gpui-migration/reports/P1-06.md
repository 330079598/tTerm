### 接口与文件布局

选择**同步、对象安全、Send + Sync** 的 SessionSink；它是 tab 级输出 endpoint，不是 async runtime，也不接管 reader、batcher 或重连策略。高频字节仍走 Raw Channel，低频事件走已有 EventSink。下列为拟新增签名（类型定义由所属领域提供，无 `pub use`）：

```rust
// crates/tterm-core/src/session/sink.rs
use crate::events::ssh::SshConnectionProgressPayload;
use crate::events::EventSink;

/// Receives one tab's output and lifecycle reports from its existing workers.
pub trait SessionSink: EventSink {
    /// Sends one already batched chunk; may wait for output acknowledgements.
    fn send_bytes(&self, bytes: Vec<u8>) -> Result<(), String>;
    /// Reports existing connection progress without adding state transitions.
    fn state_changed(&self, progress: SshConnectionProgressPayload) -> Result<(), String>;
    /// Reports the existing optional final reason; does not close output flow.
    fn exited(&self, reason: Option<String>) -> Result<(), String>;
    /// Acknowledges parsed binary bytes after the command checks the nonce.
    fn ack_output(&self, bytes: usize);
    /// Unblocks output during permanent tab teardown, without waiting for a join.
    fn close_output(&self);
    /// Records successful input for the existing immediate-echo fast path.
    fn note_input(&self);
    /// Checks the existing 150 ms input answer window.
    fn answers_input(&self) -> bool;
}

// crates/tterm-core/src/session/mod.rs
pub mod sink;
#[cfg(any(test, feature = "test-support"))]
pub mod recording;

// crates/tterm-core/src/lib.rs 增加 pub mod session。
// src-tauri/src/core/state.rs 的字段替换：
// pub sink: Arc<dyn tterm_core::session::sink::SessionSink>,
```

`EventSink` 已要求 Send + Sync，故无需重复声明。state_changed 直接用 P1-03 移动的已有 SSH progress payload（串口也复用这一 wire 契约），不另造 Connecting/Connected 等会导致重复消息的新状态机。退出的 None 对应 JSON null；reader 的 Recoverable/NonRecoverable/connected_duration 是内部重试分类，继续由 supervisor 决定是否真正调用 exited，不传给前端也不吞掉。`ack_output` 不接受 tab/nonce，因为 endpoint 本身绑定 tab；command 必须继续在原位置校验 nonce，不能用 trait 掩盖校验。


不把现有 batcher 整块移入 core：本卡先完成接口替换，`TerminalOutput` 保留在 Tauri 一侧，仍存 Channel、OutputFlow、last_input；它与 TauriSessionSink 的依赖只有单向委托，不持 sink，不形成 Arc 环。worker 单独持 `Arc<dyn SessionSink>`。PtySession 暂保留 `output: TerminalOutput` 以原样 reattach，并增加同实例的 sink handle 用于 ack/close；没有 duplicate flow 或第二份状态。P1-07a/P1-09 再抽公共 flow/batcher/服务，本卡不宣称整个 PtySession/TabConnection 已经脱离 Tauri。

`ChannelContext.app` 除事件外还用于 SSH 认证、远程 OS、cwd 与日志。这些依赖暂显式落在已有 Tauri 编排层 `TabConnection.app`（并传到 SSH 建连入口），reader 用 ReaderLog，ZMODEM 用 EventSink；不在 SessionSink 放 app getter，不用 Any/downcast。`ChannelContext` 及字段类型的结构检查必须确保不含 Tauri 类型；ActiveSession 的现有 writer/input/port/task 不含 Tauri。此过渡安排需确认，不能借本卡扩大为 AppServices/PromptBroker 实施。

`RecordingSessionSink` 放 core 的 `session/recording.rs`，仅 test/test-support 编译，记录原始 bytes、typed event 和 ack/close/input 调用，不开 UI、不隐含立即 ack。背压集成测试在 Tauri batcher 测试里组合 recording sink 与**生产 OutputFlow**，使假的 recorder 不重新实现水位算法。记录器只用于有限测试数据，不能拿无限增长的 Vec 记录器做内存性能比较。新增依赖为零；core 的嵌套 serde 类型移动由 P1-03 处理，现有 serde 足够，JSON/wire 测试留在已有 serde_json 的 Tauri 包。

### 三条读取链路和不变的边界

| 路径     | 当前顺序（迁移后逐步保持）                                                                                                                                                                                                                                                                           | 调用线程与锁                                                                                                                                                                   |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 本地 PTY | spawn_local_pty → input.track_output → blocking reader（64 KiB read buffer）→ 原始日志 → send pipe.try_forward → ZMODEM receive.process → outgoing 回写 → arm send 并 return → passthrough → sender 入队 → batcher → Raw Channel；EOF finish/join → exit_tx → supervisor                             | reader OS 线程。active.blocking_lock 只包 outgoing.write_all，结束后才 arm/输出；reader 自己的 sender Mutex 目前包 send/finish，可继续保持但不得扩大                           |
| SSH      | shell-integration early_output 独立日志/解码后直送；普通 Data：原始日志（UTF-8 时）→ send pipe → ssh_query_handler（失败回退 raw）→ ZMODEM receive → outgoing.write_all → arm send/continue → passthrough → charset decoder/解码日志 → sender；ExtendedData 直接日志/解码/输出，不经 query 或 ZMODEM | Tokio task，send/finish 在现有 run_blocking helper 内；多线程 runtime 用 block_in_place，其他 runtime 原位执行，保持现有行为。writer_stream 是该任务私有，不为 sink 新加共享锁 |
| 串口     | SerialReader（closed/tap：XMODEM 可先占用输入）→ track_output → 共用 reader/send-pipe/ZMODEM → SerialOutput 编码、hex/text、换行过滤 → 过滤日志 → 同一个 batcher                                                                                                                                     | reader OS 线程；active 锁只在协议回写期间持有。reopen 的 spawn_blocking、500 ms 设备轮询和 SerialTap 顺序不改                                                                  |

三者共用 `terminal/io_batcher.rs:12–36` 的参数：16 条 `sync_channel`，128 KiB flush threshold，512 KiB 单条 Raw IPC 上限；8 ms batch window，不被后续到达不断延长；150 ms 内输入响应在安静一窗后立即发，非输入响应也等一窗。UTF-8 不完整尾部跨 flush 保留，final flush 原样排空；超大容量回收条件不改。所有 counter/tail 仍在 sender.send 入队前，不能移动到真正发送后。

水位是“发送前若已有未确认量 **>= 1 MiB** 则等待”，不是 `unacked + next <= 1 MiB`；最多还可超出一个不大于 512 KiB 的 chunk。16 条队列是消息数上限，不是总内存 1 MiB 的承诺；生产者块、pending 和 IPC 均另占空间。reserve 使用 Condvar，等待时释放 flow Mutex；5 秒超时且未确认计数没有变化才清零并恢复，ack 用 saturating_sub，close 只解除等待并不丢弃已经排队数据。不要改成严格配额、超时丢输出或遇 closed 直接拒发。

`ack_pty_output` command（`core/commands.rs:390–402`）本身没有 5 秒等待；超时在 sender 的 OutputFlow。前端 `outputAck.ts:2,5` 为 64 KiB 或 **20 ms**，xterm parsed 回调才计 binary bytes；字符串 event 不 ack；dispose 丢掉剩余 pending 的现状不改。reconnect 共享 flow；reattach 换 Channel 并 reset 旧 flow，旧页面迟到 ACK 的现有处理也保留，不在本卡添加 epoch 协议。
