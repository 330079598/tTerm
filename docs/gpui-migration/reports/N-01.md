### 报告协议和目录回退规则

带元数据的新报告为 `OSC 777 ; tterm-agent ; agent ; state ; session ; direct|broadcast ; percent-encoded-cwd BEL`，Windows 与 Unix 一致。没有 session 的原状态报告仍兼容，旧的仅带 session 报告保守视为广播，不能建立续接记录。工作区仍只有原先新增的 `connection.agentResume` 可选字段，没有新增持久化字段或 schema。

- **direct**：会话 ID 直接记为本标签续接会话，不需要键盘 Enter。Claude 的 `terminalSequence` 属于 direct；Windows helper 和 Codex Unix 进程寻址找到本终端时同样 direct。
- **broadcast**：只能更新本标签已经记录的同工具、同 session ID，不能因按键、标签先后顺序或同目录建立归属。已保存的本标签记录可作为初始已知归属；ended/idle/prompt 清除后广播不能重新认领。未知广播完全忽略。
- **cwd**：只读取 stdin JSON 的顶层 `cwd`，不以正则截取嵌套 `tool_input` 的同名键。首次 direct 报告优先使用 live shell 目录，否则使用 hook cwd；同会话后续报告不会将启动目录改成工具执行过程的目录。目录必须非空、长度不超过 16384 字节（前端也限制长度）、不含 C0/C1/DEL 控制字符；JSON 转义正确解码后校验，协议用 UTF-8 百分号编码，分号、百分号、引号均不会分裂 OSC。恢复时仍经 Rust 构造器重新校验与 shell 转义。
- `hook_input.awk` 是随钩子分发的 POSIX awk JSON 读取代码，无新增主机运行时或 Cargo/pnpm 依赖。测试在本机 Windows 的 Git sh/awk 执行这些脚本；不是 Linux Cargo 跨目标检查，也不连接真实服务器。Windows helper 使用已存在的 percent-encoding 依赖。
- 原有钩子 command 变化使 Claude/Codex 旧集成显示 `Outdated`，更新后才输出新协议。无法从 direct 输出确定初始归属的共享后台会话会保守跳过记录；不能靠广播猜测补齐，这是本轮确认的安全规则。

### 其他 shell 的同形字符检查

POSIX sh/bash/zsh 的引号分隔符是 ASCII 单/双引号；fish 单引号内特殊字符为 ASCII 单引号与反斜杠，已有分别转义；cmd 以 ASCII 双引号界定目录，并保守拒绝 ASCII `" % & | < > ^ !`。它们均未把 PowerShell 的四种弯单引号视为分隔符。本轮 `other_shells_keep_unicode_quote_lookalikes_literal` 固定弯单/双引号和全角引号保持字面值的输出，未发现同类同形字符分隔问题。该结论基于上述语法及构造测试；本轮只有 Windows PowerShell 原生解析器得到实际验证，bash/zsh/fish 的真实 shell 执行、cmd 实际执行仍未验证，不将字符串断言冒充平台实测。
