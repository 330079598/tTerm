## 安全性

只绑定 `127.0.0.1:0`。每次启动用操作系统随机源生成 32 字节令牌：Windows `BCryptGenRandom`，Unix `/dev/urandom`，失败则禁用接口。缺少或错误令牌在进入 UI 队列前拒绝；比较固定长度的全部期望字节、累积差异而不在首个不匹配字节返回，使用 `black_box` 保留逐字节计算。长度不是秘密，超长请求先拒绝。

令牌默认位于 `%LOCALAPPDATA%/com.stone.tTerm.gpui-dev`；没有读写正式或 Tauri dev 数据。Windows 继承该用户目录的 ACL，实际 `icacls <token-file>`（完整路径见 smoke.txt）输出：

```text
NT AUTHORITY\SYSTEM:(I)(F)
BUILTIN\Administrators:(I)(F)
home-pc\stone:(I)(F)
Successfully processed 1 files; Failed processing 0 files
```

没有其他普通用户的 ACE。Unix 文件从创建时起为 `0600`。同一用户下有权限读取令牌的进程可以使用接口，不能声称它们无法使用；这正是授权边界。其他普通本地用户不能读取令牌，随机猜中不可行。SYSTEM 和管理员是系统信任边界内的主体。

接口没有运行 shell、启动程序、任意文件读写或网络转发 RPC。`text=` 只是向已经存在的原型终端/输入框输入；持有令牌的同一用户本来就能运行命令，因此在终端里输入命令没有扩大该用户能力。发送前核对捕获句柄中 GPUI Root 的内容实体 ID 确实属于 Prototype，并检查激活与焦点；不是给系统当前活动窗口发送 SendInput。窗口动作只允许 `action=focus` 和 `action=close`。`key=` 使用 GPUI 原生动态解析入口 `Keystroke::parse_with_os`（内部与静态 `parse` 同源），最多 64 字节；`text=` 逐字符派发，最多 4096 字节，拒绝所有 `char::is_control`，换行必须单独发 Enter。

每个连接 5 秒读写超时，`Read::take(MAX_REQUEST_BYTES + 1)` 最多读取 64 KiB 加一个用于检测超限的哨兵字节，超过 64 KiB 就拒绝。接收线程串行处理，无每连接线程；UI 队列容量 1，队列满立即拒绝，等 UI 回复也有 5 秒上限。普通本地用户无法用无界请求分配或线程创建拖垮进程；持续占用连接仍可能延迟服务，回环接口不声称能抵御无限频率的本地流量。

窗口关闭、正常应用退出、绑定失败和写令牌失败均尽力删除令牌。端到端脚本确认正常关闭后文件已经由原型删除。崩溃、断电、TerminateProcess 无法保证执行回调，脚本 finally 再尽力清理已发现的令牌路径。总超时负例 `python -u scripts/gpui-automation.py --timeout 0.1` 非零退出，输出 `prototype-cleanup: exited (1)`，随后查询对应 PID 已不存在，原始输出见 [timeout.txt](assets/P0-23/timeout.txt)。

## 偏差

原型没有设置页，按评估者明确指示改用程序设置的窗口标题作为可读回状态。前版新增了仅自动化构建存在的 `automation_toggled`，并把它描述为“原型已有状态”，这不实且不符合原指令。本轮删除该字段、方法和 toggle-title 命令。当前脚本通过现有终端输入修改程序自己的标题，查询返回最后实际设置的平台标题，不再返回人工切换的常量。

GPUI 的静态 `Keystroke::parse` 参数要求 `&'static str`；动态请求使用官方建议的 `parse_with_os`，二者调用同一 `parse_internal`，没有白名单或字符串泄漏。额外支持 GPUI 的 `secondary-` 系统修饰键别名。

没有修改 status.md、tterm-terminal-view、tterm-ui、tterm-parity，没有增加/升级任何依赖。本卡 Windows 截图用真实原型窗口的 render_to_image，不能将 W0-04 的 macOS 无头 Metal 结论照搬到 Windows。

## 遗留问题

- macOS/Linux 真实窗口输入、标题链路、截图与脚本仅源码确认，未运行验证；没有在本机条件下冒充通过。
- 正式设置页验收需在设置页实现后补充，本卡没有新增页面。
- 文件/目录对话框、密钥串、权限、外部链接等真实系统对话框必须由后续卡按 `[人工]` 验证，AUTOMATION.md 已列禁止清单。
- 管理员、SYSTEM 和同一用户其他进程可读取令牌；这属于明确的本地用户信任边界，接口未承诺防护当前用户自己的恶意进程。强杀进程可能遗留失效令牌文件，启动时每次随机生成新令牌。
