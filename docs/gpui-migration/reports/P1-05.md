### session_nonce：实际隔离边界

现有三类 prompt payload 和三个 respond command **均不携带 session_nonce**，map 也没有 owner/nonce。当前 UUID 只能确保 host/auth 不会把旧 ID 回给另一个新 UUID；任务 abort 后若 sender 留在 map，旧 command 可能取出 sender 后报 receiver gone。`ChannelContext.session_nonce` / `PtySession.session_nonce` 与 kill_pty 的校验保护 PTY 会话；monitor 自己的缓存也按 nonce 校验，但这不是提示回复隔离。不能声称本卡只需“保留已有的 prompt nonce 校验”。

计划把 `(tab_id, session_nonce, attempt_id)` 仅作为内部 scope：终端由 ChannelContext 注入，重连同 nonce 每次独立 attempt；SFTP、连接测试、tunnel 这种没有完整 nonce 的路径使用唯一 operation owner，不能编造 nonce=0 后全局按 tab 清除。侧连接在有可靠终端归属时可关联 session scope；只有 tab_id 的路径保持 operation 生命周期，不扩大关闭行为。`cancel_session` 精确清掉该会话及其登记的子 owner，`cancel_owner` 只清本操作；future drop 无条件移除自身 waiter。scope 关闭后禁止再登记，避免 Auto 口令取消被吞掉后又弹下一问。

ProxyCommand 的 wire ID 可重复：同命令在旧组过期后新建一组仍是同 hash。内部 generation 防止**旧 future/timeout/drop**删掉新组，却无法区分前端发来的同 hash 旧回复与新回复，因为 IPC 没有 generation。保留现有 wire 契约时这个限制无法消除；如要求完全隔离，需要另卡调整 requestId 并兼容去重/前端，不能在本卡静默换 UUID。此点为需要确认的协议缺口。

    HostKey(bool),

    pub fn begin(&self, request: PromptRequest, options: PromptOptions)

    pub fn reply_auth(&self, id: &str, responses: Option<Vec<String>>)

// 为此内部短临界区使用 std::sync::Mutex；绝不在 guard 内 await/emit/落盘。

ID 生成继续由领域调用方负责：host/auth 使用现有 UUID v4；proxy 用现有 command_hash。`begin` 验证同 namespace 唯一性（ProxyCommand 同 hash 则追加 waiter，不覆盖 prompt），把 ID 写入/核对 payload；不会新增一个 JSON request 字段。不同 reply 方法只接受各自领域，类型不匹配不能消费别人的请求。PromptOutcome 是正常生命周期结果，公开失败仍 `Result<_, String>`，符合 A7；旧 caller 映射到原 SshConnectError/错误文案。

不新增 PromptBroker trait：需要 mock 的是已有 EventSink，broker 本身使用真实 oneshot 即可无 UI 测试。RecordingEventSink 使用 P1-02 的 `test-support`，不把测试记录实现放到生产。`PromptWait` 每个 waiter 只有一个 oneshot；proxy 是组中多个 oneshot，不能压成一个 receiver。

超时起点保持在原 `timeout(..., receiver)` 位置：hostkey 在状态行之后、auth 在 reveal 之后、proxy 在 join/首位 emit 之后；`wait` 记录各 waiter deadline。超时先尝试在短锁内取出匹配 generation；锁外通知/发 expired。第一个移除成功者产生过期事件；已经 reply/claim 的组不能被老定时器移除。proxy claim 后原 receiver 的个人 timeout 仍可能先到，不能悄悄把 DB 写入阶段变成无限期等待。

ProxyCommand command 仍先 claim（使 pending 查询看不到），再 `run_blocking` 保存批准，最后 complete(allow && saved.is_ok()) 并返回原 saved。持久化动作不在 broker 内，也不持 broker 锁。已开始写入后用户关闭会话并不回滚既有批准记录，但关闭的 waiter 不得继续启动子进程。保持模板精确文本的 hash，保留未批准拒绝及超时原文案。

### 为什么退出不放进同一请求表

退出/关闭没有 ID，第二次动作代表强制放行，而不是重复回复错误；确认、取消 command 甚至不要求有 pending 请求。保存握手允许 `ready_to_quit` 先到（Notify permit），与“未知 ID 必须拒绝”相反。强行统一需要新增 wire 字段、改变重入语义或引入不可对应的隐式请求，均超出行为不变的重构。

因此仅共享 typed EventSink；Lifecycle 状态机及窗口/退出适配继续留 background（后续 P1-07d/P1-08 抽取），不为这张卡新设通用 confirmation trait。broker 的 shutdown 放在真正提交退出、准备结束任务的阶段，不能在第一次弹退出确认时调用；取消退出后原连接仍必须可继续交互。自动化测试固定现有 AtomicBool、Notify、1500 ms、emit 失败与重复退出语义。此边界请求评估者确认，避免任务卡“各流程”被解释为必须一律塞入 broker。

8. ProxyCommand 用仅含测试主机的未批准模板，例如 `nc %h %p`（先确认 macOS nc 可用）；必须通过导入隔离 SSH config/备份夹具建立“本机未批准”状态，不能从本机设置保存后直接测试（保存会自动批准）。同时发起两条连接，仅一问；拒绝、120 秒过期、批准后重连免问、修改模板空格重新问、窗口后打开补读 pending。关闭一个 waiter 不影响其他 waiter；组结束后旧 hash 与新组复用的歧义按上文记录，不掩盖。
9. 关闭/退出：ask 的取消、tray、quit、记住选择；有运行 tunnel 和未上传 SFTP 修改时 cancel/confirm；提示期间再次 close/Cmd+Q 强制继续；隐藏窗口收到新提示应恢复窗口；启用保存后退出确认先保存再 ready_to_quit；模拟不回复/发送失败验证 1500 ms 放行。自动化覆盖精确时间，人工只确认界面、窗口、文件与退出效果；所有修改仅容器测试文件和隔离数据。
10. 结束隔离 Tauri、其 Vite/编译 runner 与测试用子进程，关闭测试会话；只删除本卡两个容器（`docker rm -f tterm-P1-05-host tterm-P1-05-hop`）与专用网络（`docker network rm tterm-P1-05-net`）。清理临时 identifier 的 Application Support/Caches、临时钥匙串项、`target/p1-05` 中夹具与配置；保留审查所需的合成事件记录和人工截图在本卡证据目录，绝不包含密码、OTP secret 或真实连接。报告附容器/端口和目录清理结果，不能仅写“已清理”。

### broker 的本轮接口调整

为避免依赖尚未合并的领域类型，`PromptRequest` 当前接受已有 `AppEvent`，携带独立 `PromptId`、`PromptKind` 和可选 expired_event；不会先造提示 payload 副本，也不加入对方的占位事件变体。begin 先注册再通过既有 EventSink 发事件；domain payload 与 ID 一致性仍是后续领域构造器的责任。当前只校验非空 ID、命名空间、重复非共享 ID、owner 归属/关闭状态。测试用已有 Tunnel 事件作为不透明的合成事件，**未声称 broker 能在生产发出 tunnel 或提示事件**。C2/C3 接线后将测试夹具换成实际提示变体，并用领域构造器保证 kind/id/event 匹配。

owner 从原计划的“调用方提供字符串”细化为 `register_owner(Option<SessionKey>)` 由 broker 铸造，绑定 broker 的 Weak 身份；拒绝跨 broker owner。每个 owner/请求代次/共享 waiter 使用不回绕的内部序号，序号耗尽返回 String 错误。`cancel_owner(&PromptOwner)` 替代裸 OwnerId；相同 tab 的不同 nonce 或 attempt 各自独立。`shutdown` 阻止新 owner/request 并取消 pending 和 resolving 等待者，但尚未接应用退出阶段。

每个 PromptWait 持有一个 oneshot 接收端与同步 Drop guard；即使未 poll、task abort 或原 caller 已丢 owner handle，pending waiter 保留 owner 身份以支持之后按 session 取消。短 mutex 临界区内不 emit、不 await、不落盘、不发送 reply。timeout 从第一次 poll wait 起算，保留调用方在状态行/reveal 后开始等待的能力；取消不伪造 expired。

ProxyCommand 共享组只保留第一份事件，给每个 waiter 独立通道/时间。claim 先从 UI pending 索引移除，但 resolving 组仍可按 owner 取消；complete 在调用方完成批准落盘后才释放 true，未 complete 的 guard Drop 全部 false。旧 claim/Drop/timeout 仅接触自己代次，不删除同 ID 后来的组。数据库、hash、子进程仍未接线，本轮不能声称已测试 DB 写入失败或批准后实际启动顺序。

### 取消与时序核对

PromptScope Drop 在外层 timeout、取消 future、task abort 时同步关闭其 owner，PromptWait Drop 再清自身 waiter。cancel_session 关闭 nonce 并取消该 nonce 的所有注册 owner；open_session 只由 spawn 持会话写锁时开启。broker 留存 tab 的最后 SessionKey，使终端从 PtyMap 删除后，晚到的侧连接不能退化成无 owner 的匿名操作。副作用是保存少量已关闭会话标识，不存提示/密码；新 session_nonce 可独立注册，显式重开同 nonce 只由新建终端入口执行。

同一 tab 的所有 scope 登记先取 PtyMap 读锁，再登记 broker owner；spawn/关闭取会话写锁，再改 broker 状态，锁顺序一致。broker 临界区不回调 UI/DB，也不获取会话锁。monitor 的 registry 锁只用于其 owner 登记/释放，broker 不回调 registry。scope 关闭后认证的后续方法检查 ensure_open，不能继续弹下一问；用户取消单个 passphrase 仍保留原“跳过该 key”策略，scope 已关闭时下一问注册失败。

Proxy claim 保留 resolving waiter 供取消；DB 写失败返回原错误并全部 false；DB 任务被 abort 时 claim Drop false；收到批准时 owner 已关闭不能启动命令。批准已落盘后关闭不回滚 trusted_proxy_commands。原同 hash 前端迟到回复歧义继续保留。
