# P2-06 续批执行与验收方案

起点 `03ab675d`。沿用 P0-12 的生产滚动条和 P4-15 已验的容量热更新，不重做设置页，不调整门槛。按可以独立复验的改动分两批：

1. **滚动和内存。** 在真实终端模型写满有限容量后，以正式视图的滚轮和拖拽事件浏览历史，检查可见文本、顶部与底部边界、追加与淘汰时的锚点。走现有清历史路径，验证可见屏、历史大小、显示偏移、缓存和之后继续输出；不要把清空当前屏或备用屏当成清除主屏历史。使用可重复的分配或存活内存证据区分「行数归零」和「内存释放」，不要把进程 RSS 必须立即下降作为契约。
2. **概览标记。** 对照原版，接入真实命令标记和搜索匹配行到生产标尺，验证重定位、淘汰、清除、空结果和高密度情形。不构造虚假的生产数据，不提前实现 P2-07 搜索框或全量搜索。详细登记哪些已有生产者、哪些连接点需要 P2-07。

本次先派第 1 批给 Pi + DeepSeek V4.1 Flash。使用独立 worktree，只使用合成输出与隔离会话。检查上游 Alacritty 行存储和既有缓存，先证明缺口再决定是否修生产代码，不修改全局缓存或上游依赖源码。产出可独立复跑的回归和简短报告 `reports/P2-06-scroll-memory.md`，列明桌面手测与自动事件的边界。不合并、不推送、不修改总状态表，由协调者复核。

验收：复跑针对性回归，检查报告与测量口径；前端六项、Rust fmt/严格 Clippy/workspace 测试、release 帧与吞吐门均通过后，本地合并该批。第 2 批和未取得的原生视觉证据保留待办，不以一次局部合并宣告 P2-06 或 G2 通过。
