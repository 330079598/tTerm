# P1-08 平台能力 trait：设计与第 2 轮实施（macOS）

## 设计

### 1. 本轮结论与依据

第 1 轮设计提交 `21936206` 经评估后，先以 `9252a4c6` 合并 GPUI（上游 `34e1600e`，包含 P1-02 EventSink 与 P1-11e，无冲突），再以 `19b75757` 单独提交设计修订，随后实施。实现已完成，等待评估；跨平台与实际用户交互的缺口见“拆分计划 / 本轮实施记录”。没有修改持久化格式、前端 invoke、现有事件发送方式或 exit_guard。

- 环境：Mac mini M4 / macOS Apple Silicon；Windows 原生平台 crate 交叉检查通过，完整 Windows 工作区被本机 C SDK 缺失阻断；Linux 按决策 016 推迟桌面验证。
- 已按要求阅读 AGENTS、README §1/2/4/6、P1 现状与 P1-08、决策 003/016、tech-selection §2.1、environments、dispatch §6，并补读决策 011、dispatch §3.2/5、P1-01 报告及 P5-01/02/03。
- 遵守 A7/A9：公开能力失败为 `Result<T, String>`；trait 与原生实现放 `crates/tterm-platform`，Tauri 的插件、窗口 API 薄适配放 `src-tauri/src/platform/`。platform 不依赖 Tauri/core，不导出插件、IPC Channel 或序列化 DTO。
- `AppPaths` 沿用 P1-01；`AppIdentity` 与更新路由/缓存规则在 core。能力各自 `Arc<dyn X>` 注入，不建服务容器。P1-07 负责后续 AppServices 组装。

### 3. 第 2 轮定稿：依赖、注入和线程

#### 3.6 实施偏差与交接

- 真机验证发现并修复原有 macOS 托盘销毁线程缺陷：remove 改在主线程 drop status item。这是本轮为保证 Tauri 可用而增加的修复，单独提交；无界面测试无法替代真实 Cocoa runloop。
- 因原生代码相互引用，共同 trait/原生去宿主化合并为 `f481a5c8`，随后按能力分提交迁移调用；C6/C7 的定义/接线分散在共同契约和启动提交。纯移动已独立，不夹修改。中间移动/定义提交不能独立编译，最终组合已通过全部检查；这与原计划“每 trait 定义+迁移一提交”不同。
- 更新 install 使用 `self: Arc<Self>` 而非草案 Box，以保持缓存安装失败可再次尝试的既有行为。take_bytes 移出字节、不在句柄中保留第二份安装包；安装消费的 bytes 仍必须来自该下载/缓存。platform 无 ticket 表，command 的 channel pending 映射按评估保留给 P1-07。

- 没有迁移 `.emit`、没有新增 EventSink 事件类型。通知 activation/托盘回调保留原调用点，后续 P1-03/04 可改。提示四调用交 P1-05；路径和 identity 已可供 P1-07/09 组装。
