# P1-08 平台能力 trait：第 1 轮设计（macOS）

## 设计

### 1. 本轮结论与依据

**需要确认（设计待评估）。** 本轮只提出接口与提交计划，不实施、不加依赖、不修改 `status.md`。以下方法签名是评审草案，不是已经存在或已经编译通过的代码。按 dispatch §3.2，评估通过后再开始下一轮。

- 基准：`migrate/P1-08-platform-traits`，`3c824e557ad1786ac6cf07f54ec210e7a6729fe9`；开始时工作区干净。
- 环境：Mac mini M4 / macOS Apple Silicon；环境能力与缺口以 `environments.md` 为准。本轮没有启动应用、访问应用数据目录或系统剪贴板。
- 已按要求阅读 AGENTS、README §1/2/4/6、P1 现状与 P1-08、决策 003/016、tech-selection §2.1、environments、dispatch §6，并补读 dispatch §3.2/5、P1-01 报告及 P5-01/02/03。
- 遵守 A7/A9：公开能力接口使用 `Result<T, String>`，定义放 `crates/tterm-platform`；Tauri 实现放 `src-tauri/src/platform/`。接口不暴露 Tauri、GPUI、IPC Channel、原生裸指针或插件错误。
- 本卡最终验收仍为“core 不依赖任何 `tauri-plugin-*`；Tauri 版功能不变”。本轮只完成设计证据，不能据此判定这两项实施验收通过。

### 3. 第 2 轮定稿：依赖、注入和线程

本节替代第 1 轮接口草案。已先合并 GPUI（含 P1-02 EventSink、P1-11e）；合并未产生冲突。第 2 节历史清单的基准仍为 3c824e55；合并后 lib.rs 在模块声明增加 event_sink，原 :91 注册变为 :92，原 setup :360 变为 :361；tray.rs 的 TunnelState 导入改为 tterm_core::events::tunnel，调用位置未变。其他所列文件未被此次合并修改，行号仍适用。后续实施的最终行号按实际清单补记。

实现位置按评估决定及 tech-selection §2.1、决策 011：原生代码进 tterm-platform，Tauri 包只保留真正调用插件、窗口 API 和 command DTO 的薄适配。native 不依赖 Tauri 或 core；依赖方向 core → platform。主窗口句柄和 UI 调度由客户端绑定，原生对象在拥有它的线程内创建、销毁；用投递 + oneshot 等待结果，主线程不 block_on，自身线程 inline 调用，不能把裸指针作为 Send 数据任意跨线程传递。需要原生句柄时只在主线程任务内解析。

platform 类型不 derive serde，PNG 用 Vec<u8>；camelCase、data URL 与 IPC Channel 在 command 层映射。异步接口的对象安全别名如下；公开失败均 Result<T, String>。
