## 1. 结论

任务卡列出的 32 个源文件可以全部移植，但**不能一次派**：其中 7 个依赖 P1-09b2 移入的 `profiles`、`proxy`、`serial`、`ssh` 类型（`quickConnect`、`profileConnections`、`profileSearch`、`proxy`、`serial`、`vaultLock`、`userVerification`），2 个依赖 P1-09b3 移入的 `profiles/groups.rs` 与 `sftp/internal/api/archive.rs`（`profileGroups`、`sftpArchive`），1 个依赖 P1-11c 的 `shellCommands`（`composerRun` 的 `runLines`），`serialSendStore` 因 `serial/` 目录冲突随 g2 派。建议分成三批（g1 无依赖、g2 等 b2、g3 等 b3），每批以“需要确认”停下。

## 5. 语义风险

每条都附上证据命令的输出（`P1-11g-evidence/semantics.txt`、`ts-oracle.txt`）。

### 5.1 Unicode 与 JS 字符串

| 位置 | JS 行为（实测） | Rust 要求 |
| --- | --- | --- |
| `quickConnect.matchesQuery("İSTANBUL", ["istanbul"])` | `false`（`"İ".toLowerCase()` = `i` + U+0307，两个码位） | `to_lowercase()` 相同，保持 `false`；加用例固定 |
| `commandVariables` 的密钥遮罩 | `"•".repeat(Math.min(value.length, 8))`，`length` 是 **UTF-16 码元**；4 个 emoji 的密钥遮罩 8 个点 | 用 `encode_utf16().count()`，不能用 `chars().count()` |
| `recentCommands.suggestCommandName` | `firstLine.slice(0, 45)` 可以切开代理对，产出孤立代理项 | 按 UTF-16 截断，落单的一半写成 U+FFFD（P1-11a1 已有先例） |
| `serial.ts` 的 `visibleText` | `Array.from` 按码位迭代，emoji 原样通过（实测 `"a😀b"`） | `chars()` 等价，无需替换 |
| `serial.localEchoText` | `split("")` 按码元切再 `join("")`，emoji 复原（实测 `"😀\r"` → `"😀\r\n"`） | `chars()` 等价 |
| `settingsSearch.normalize` | `NFKC` + `toLocaleLowerCase()` + `trim`；`"ｆｏｎｔ"` 能搜到 Font Size（实测） | 需要 `unicode-normalization`（新依赖，见 11.1）或接受差异 |
| `sftpView` 的 `extensionOf` / `sftpArchive` 的 `toLowerCase` | 都是 Unicode 折叠，`İ` 会变成两个码位 | `to_lowercase()`；文件名含 `İ` 时扩展名比较的差异写进测试注释 |

### 5.2 数字

- **`toFixed` 与 Rust 格式化不同。** `(1.25).toFixed(1)` = `"1.3"`（ECMAScript 对恰好一半的值向绝对值大的方向取整），Rust `format!("{:.1}", 1.25)` = `"1.2"`（half-to-even，已用 `rustc` 实测）。`formatBytes(1280)` 因此是 `"1.3 KB"`，不是 `"1.2 KB"`。计划：在 `js::number` 写 `to_fixed`，按 ECMAScript 规则实现，并用 oracle 的 1280、2560 等值固定；`formatBytes` 只用 0 或 1 位小数。
- **`Number(value)` 比 `f64::from_str` 宽。** `Number("0x10")` = 16，`Number("1e3")` = 1000，`Number(" 22 ")` = 22，`Number("Infinity")` = `Infinity`（`isFinite` 为 false），`Number("2_2")` = NaN。Rust：`"0x10"` 解析失败、`"Infinity"` 解析成 `inf`（已用 `rustc` 实测）。`validateVariableValues` 用 `Number.isFinite(Number(value))`，所以 `"0x10"` 在 TS 里是合法的 16。计划：`js::number::parse_number` 覆盖十进制、十六进制、指数、`Infinity`/`NaN` 与非数字前缀（`"12abc"` → NaN），`validate_variable_values` 用它。
- **`serial.normalizeSerialSettings` 用 `Number(raw.baudRate)`。** `{baudRate: "9600"}` → 9600，`{baudRate: 115200.5}` → 回退 115200（`Number.isInteger` 失败），实测。Rust 必须接受数字字符串，并把整数浮点当整数。
- **`terminalLogReplay` 的 `atMs`** = `Number(getBigUint64(...))/1000`（f64）。9007199254740993 µs 实测得 `9007199254740.992`；真实日志不会到 2^53 µs，但端口要用 f64 存 `at_ms`，不要用整数除法。
- **`badgeOverlaySize`** 用 `Math.round`；`Math.round` 对正数与 Rust `f64::round` 相同，负 DPR 不会出现，写一条注释即可。
- **`monitorMetrics`** 用 `value.indexOf(item) === index` 去重（字符串严格相等）；Rust 用「首次出现」集合，顺序保留。

### 5.3 时间

- `serial.timestampPrefix` 与 `sftpDrawerUtils.formatTimestamp` 都读**本地时间**（`getHours()` 等）。实测机器 `Asia/Shanghai`，`2026-01-01T09:05:07Z` → `2026-01-01 17:05:07`。Rust 用 `chrono::Local`（core 已开 `clock`，`session_log/screen/tests.rs` 已在用），测试不要用 UTC 构造，否则 CI 的时区会让断言漂移；建议测试传入 `DateTime<Local>`，与 TS 测试里的 `new Date(2026, 0, 1, 9, 5, 7, 42)` 对齐。
- `formatTimestamp(0)` 是 `"--"`（TS 的 `!value` 把 0 当缺省），`formatTimestamp(-1)` 会格式化 1969 年。Rust 要显式区分 `None` 与 `Some(0)`：`Some(0)` 也返回 `"--"`。
- `quickConnect`/`profileRecents` 的 `lastUsedAt` 是 `Date.now()` 毫秒整数（始终是整数且远小于 2^53）。建议用 `i64`：与后端其它时间戳一致，也避免 `serde_json` 把整数值写成 `1.0`。这两个列表的存储仍在 WebView，端口不负责序列化。
- `updater` 的 6 秒启动延迟与 `daily`/`every-3-days`/`weekly` 间隔是纯常量；定时器留在适配层，core 只给 `next_check_delay(now_ms, last_checked_ms, frequency)`。

### 5.4 正则

- **用户正则要用 `regress`。** `sftpSearch` 把用户输入当 JS `RegExp`（`i` 标志）用；`sftp/internal/api/search/matcher.rs` 用的是 `regex` crate，两者方言不同：`regex` 不支持环视与反向引用，`\d` 默认匹配 Unicode 数字，`(?i)k` 会匹配开尔文符号 `K`（JS 非 `u` 的 `i` 不匹配，实测 `false`），错误文案也不同（`Invalid regular expression: /a(/i: Unterminated group` vs `Invalid pattern: …`）。`regress` 已在 pins（`=0.12.0`，`utf16`），支持 `icase`、`dot_all`、`unicode` 标志。
- **固定模式不要用正则。** `quotePosix` 的字符集含 `[`、`]`、`\`、`^`、`` ` ``，写成 Rust 正则容易错；建议按 `char` 判定，字符集照抄 TS：`\s ! " # $ & ' ( ) * ; < > ? [ \ ] ^ ` { | } ~ =`（注意**不含** `-`，与 macOS 终端一致）。`hasOnlyKnownProxyTokens`（`%` + `%hnpr`）、`parseHexBytes`（`[0-9a-f]`、`0x` 前缀）同样用显式扫描。
- **JS 的 `\s` 包含 U+FEFF，Rust 的不含。** 影响 `parseQuickConnectInput` 的 `\s+`、`profileSearch` 的 `[\s\-_.]+`、`settingsSearch` 的 `\s+`、`parseHexBytes` 的 `[\s,;:-]+`。计划：写一个 `js_whitespace` 判定（`char::is_whitespace() || c == '\u{FEFF}'`），由 `split` 使用；加 BOM 用例。
- `toUnixPath` 的正则带 `s` 标志（`.` 匹配换行）；用 `char` 扫描即可绕开。
- `dropQuotingFor`、`archiveFormatOf` 等只做大小写与前缀，不需要正则。

### 5.5 排序

- **`sftpView` 用 `Intl.Collator(undefined, {numeric: true, sensitivity: "base"})`**：数字按自然序（`file9` < `file10`），大小写与重音不敏感（`Ärger` 与 `Arger` 相等，实测 0）。实测排序 `[".env","app","apple","Ärger","File2.log","file9.log","file10.log","logs","zebra","Zebra","档案"]`；字节序是 `[".env","File2.log","Zebra","app","apple","file10.log","file9.log","logs","zebra","Ärger","档案"]`。**现有 TS 测试的数据恰好两种情况相同**（只有 `File2`/`file10`），加一个 `file9` 就能看出差别（`ts-oracle.txt` 的 `sortSftpEntries` 段）。
- **`profileGroups.byName` 用 `localeCompare`**：实测 `["Web","Zebra","api","prod"]` 排成 `["api","prod","Web","Zebra"]`；字节序是 `["Web","Zebra","api","prod"]`。后端 SQL 已经是 `ORDER BY lower(name), name, id`（`src-tauri/src/profiles/groups.rs:44`），也就是 ASCII 小写序，与 ICU 对纯 ASCII 名字一致，对非 ASCII 不同。
- 计划：写一个共享的 `ascii_case_insensitive_cmp`（ASCII 折叠 + 字节序兜底），`numeric` 部分为 `sftpView` 写一个「数字段按数值、其余按 ASCII 折叠」的比较器，使纯 ASCII 名字（含 `file9`/`file10`）与 `Intl.Collator` 一致；非 ASCII 的次序按字节序，写进测试注释。这样既不改后端 SQL，也不用引入 ICU（`stone` 已在 P1-11d1 接受同类差异）。**需要确认**（11.3）。
- 稳定排序：JS 的 `Array.prototype.sort` 稳定；Rust 用 `sort_by`（稳定），不要 `sort_unstable_by`。`rankProfiles`、`sortSftpEntries`、`buildGroupTree` 的兄弟排序都依赖这一点。
- `profileGroups` 的环：TS 取「未挂上的组里 id 最小者」作根（`localeCompare`）；组 id 是 UUID/ASCII，字节序与 locale 一致，无需特殊处理，但要加注释。

### 5.6 持久化与数据

- 本卡不新增存储。所有 `localStorage` 读写留在 WebView，Rust 只收纯状态；P1-10 负责把它们搬进后端。涉及的键：快速连接最近、连接最近、最近命令、SFTP 视图、SFTP 列宽（不在本卡）、串口发送回显、命令编写器两个标志、日志回放视图。报告只列用途，不复述键值，键名以源码为准。
- `serialSendStore` 的 50 条上限是「最少最近隐藏者先忘」，`saveSerialSendEcho` 里是 `[...others, key].slice(-50)`；Rust 端口保持同样顺序，测试用 51 条（TS 用例）。
- `quickConnect` 的最近项去重键是 `user@host:port|jumpuser@jumphost:jumpPort,…`；`profileRecents` 按 `profileId`。两者都不要改成按 `title` 去重。

1. **NFKC 归一化要不要引入新依赖。** `settingsSearch.normalize` 用 `String.prototype.normalize("NFKC")`；Rust 标准库没有，需要 `unicode-normalization`（crates.io，需登记 pins）或接受全角输入搜不到的差异（`"ｆｏｎｔ"` 用例会失败）。建议引入并按 pins 固定版本；若不同意，删掉该用例并在报告里记为已知差异。
