# P1-11b 关键词高亮纯逻辑移植（macOS）

## 结果

配置与编辑逻辑移植到 `tterm-core::keyword_highlight`；匹配与单元格定位移植到 `tterm-terminal::keyword_highlight`。终端 crate 自己定义中性规则/集合/调色板类型，避免依赖 core；core 只负责持久化配置和编辑，调用边界转换为 terminal 类型。Tauri 现有 `src-tauri/src/config/keyword_highlight.rs` 的 JSON 字段保持不变；新增 core 类型使用同样的 `serde(default)` 形状，并用往返测试确认兼容。

## 导出对应

`config.ts` 的常量、类型、内置集合、名称解析、默认值、集合解析、归一化均对应 `tterm_core::keyword_highlight`；`edit.ts` 的 9 个导出对应同模块编辑函数。`match.ts` 的类型、常量、颜色解析、编译、错误检查、匹配对应 `tterm_terminal::keyword_highlight`。`cells.ts` 的 `CellText`、`HighlightSegment`、`readCellText`、`highlightSegments` 同样对应终端模块。`newHighlightId` 使用 workspace 已有 `uuid` crate 的 v4 UUID，避免每次启动从 1 重新计数。`HighlightPaletteColor` 与 `kind` 联合类型在 Rust 公共配置结构中用 `String` 表示，以保持后端旧配置的宽松兼容；匹配模块对 `kind == "keyword"` 采用字面量，其余按正则处理。

## 语义核对与偏差

- 匹配区间和单元格映射使用 UTF-16 code-unit 计数；Rust 的 `regress` 字节偏移先转换为 UTF-16。中文、宽字符、组合扩展和 emoji 的映射接口不依赖 xterm。
- `tterm-terminal` 不依赖 `tterm-core`；规则类型在 terminal 中定义，core 的配置类型由调用边界转换。
- `regress` 按 ECMAScript 2018 处理用户和内置正则，支持环视与反向引用；flags 与 TS 一一对应为 `g`/`gi`，不添加 `u`。只有 JS 也拒绝的模式返回 `invalid`。
- 配置归一化沿用前端的宽松规则：未知颜色变为 `null`，缺字段取默认，集合和规则按 50/100 上限截断，模式和输入按 UTF-16 code-unit 截断；空格后组合字符和制表符的单元格映射也与 xterm 对齐。
- `newHighlightId` 使用 UUID v4，持久化 id 不会在重启后从 1 重新开始。
