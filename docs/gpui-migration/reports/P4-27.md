## 关键发现

### 设置页只有两页可操作

`SettingsTab` 当前有 `Appearance`、`Terminal` 和 `LocalShells` 三个局部可操作值。其余 11 页没有可用页面，也没有实现：

- 连接分组、连接、代理
- 关键词高亮、通知、快捷键
- 日志、数据迁移、安全、通用、更新

因此设置外壳和搜索虽已工作，不能把“14 页清单”或“搜索索引”算作页面迁移完成。

### Shell 页的清单文字已过时

[设置页逐页清单](../settings-inventory.md)的 `shells` 一节仍把“自动发现、设为默认、隐藏、复制、排序、删除、路径预检”列为待补，但当前代码已经包含这些行操作：

- `crates/tterm-gpui/src/local_shells_setting/list_actions.rs`
- `crates/tterm-gpui/src/local_shells_setting/path_status.rs`

这批能力已在 `82b8ee12` 接入，并由[来源选择验收](P3-11-P4-03-picker-acceptance.md)覆盖。矩阵按代码和该报告判定为“进行中”，剩余的是整页视觉、双端隔离配置桌面读写和另一平台复验，而不是这些动作本身。建议 P4-17 收尾时同步修正清单文字。

### P4-03 的系统选择器已经实现

[P4-03 报告](P4-03-ssh-config-import.md)已记录“选择 SSH 配置文件”和“选择 SSH 配置目录”入口；当前缺口是系统选择窗口本身的桌面复验和跨平台桌面证据，不是重新实现选择器。矩阵因此记为“进行中”，不记为“未开始”。

### P4-01 的连接库已支持基本分组操作

连接库已接入顶层分组创建、重命名、确认删除，以及多选连接后的移动和确认删除；见[实现范围与定向回归](P4-01-ssh-library-macos.md)。这些操作在连接库中，不是独立的「连接分组」设置页。新建时选择父分组、拖放和桌面对照仍待补。

### 大量功能只有 core 服务

以下模块在 `tterm-core` 中已有服务，但 GPUI 没有可操作界面，因此全部记为“未开始”：

- `sftp`、`services/sftp`：SFTP 浏览器与传输管理器
- `session_log`：日志页与回放
- `serial`：串口控制栏、发送栏和历史
- `monitor`：服务器监控栏与面板
- `command_library`、`composer`：命令库、编写器和变量
- `backup`、`sync`：备份、WebDAV 和迁移页
- `theme`、`themes`：主题库、编辑器和导入
- `agent_integration`：agent 安装/卸载与配置目录
- `tunnel`：隧道新建、启停、自动启动和后台运行

core 服务能减少后续实现量，但不能算作用户可用。

## 下一步顺序

P4-27 自身不产生功能，只是把剩余工作排清楚。按依赖和用户收益，建议：

1. **收口 P4-01 与 P4-03**：补父分组选择和拖放，并验证重新打开后分组及连接顺序正确；P4-03 按桌面复验步骤核对系统选择窗口。
2. **补 P4-02 高级连接编辑**：认证方式、跳板机、代理、编码、主题、图标、串口字段和连接测试。它是 P4-04、P4-05、P4-08、P4-10 的前置。
3. **做 P4-05 与 P4-06**：SFTP 抽屉和传输管理器。现有 Tauri 侧约 8500 行，是最大的单块工作，应先拆子卡。
4. **补设置页**：先做连接、代理、安全与外观，再做高亮、通知、快捷键、日志、数据迁移和更新。
5. **补工具与平台**：命令库、编写器、广播、主题库、监控、串口、日志回放、关于/更新、系统集成、无障碍和打包。

只有第 1～5 步全部完成，矩阵才可能没有“未开始”。G2/G3 的长稳、输入法、无 GPU 和 3 个工作日验收仍按原计划独立进行，不用 P4 的功能开发替代。
