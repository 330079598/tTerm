#### `tail_expr_drop_order` 逐处审查

`cargo fix` 没有自动改写 `tail_expr_drop_order`：日志里 lib 生成 81 条、lib test 生成 92 条（其中 81 条与 lib 重复），按 `文件:行:列` 去重后为下表 81 个位置。`if_let_rescope` 本身为 0 条；下表中少数 `if let`/`while let` 的 scrutinee 重排仍由 `tail_expr_drop_order` 报出。下表的行号来自 `cargo fix` 运行时的 2021 源码，发生在 `cargo clippy --fix` 和 `cargo fmt` 之前，因此与当前文件行号有偏移；路径相对于 `src-tauri/src`。

所有 81 个位置都保留原代码，没有添加显式 `drop`，也没有把 `if let` 改成 `match`。理由逐行写在“处理”列；共同点是：临时值要么是已完成的 future、要么是被模式移空的 `Option`/`Result`，没有出现 `RefCell` 借用；涉及锁的位置（`pool_guard`、`_dialing`、`_guard`、`SYNC_LOCK`、`armed_send_state` 等）在 2021 与 2024 下都只在同一同步段或同一 await 区间内持有，重排只改变函数返回时的临时值顺序，不新增 await，也不会让 guard 跨到新的临界区。同一位置被宏展开多次时只列一行，例如 `sftp/internal/api.rs:34` 被多个 `with_sftp!` 调用重复报告了 11 次；其余重复位置同理。
