### 设计选择

- **加载时转换。** 构建时用 `include_str!` 保持现有 JSON 为唯一来源，启动时
  解析、展平和校验一次，并用 `OnceLock` 缓存成功结果或错误。这样发行包不需要
  额外携带 JSON 资源，也不会每次翻译都重新解析。目录错误在启动时由 GPUI 输出
  可操作的错误信息而不打开窗口，不 panic。
- **语义相等而非字面键相等。** 现有文件 `en.json` 为 2838 个扁平键，
  `zh.json` 为 2807 个。两者语义基键均为 2758 个，英文多出的 31 个键全部是
  `_one` 复数形式；中文使用 `_other` 即可表达同一复数组。校验要求英文复数基键
  具备 `_one`/`_other`，中文具备 `_other`，允许额外的合法复数形式，不要求两个
  文件的字面键数相同。
- **占位符校验。** 每个模板在加载时解析 `{{name}}`，不把单个花括号当作插值；
  非 `count` 占位符的并集必须在两种语言间一致。`count` 可以省略，因为译文可以
  不打印数字。参数缺失、重复、非有限数字在运行时返回 `Result` 错误。
- **类型安全边界。** `TranslationKey::new` 是 crate 内可见；GPUI 生产代码只能
  使用 `keys` 注册表中的常量，宏同时生成 `ALL` 供测试核对。构造函数仍可被
  core 内部或测试使用，因此这不是对所有 core 调用方的编译期封闭。参数类型
  （`Text`/`Number`）是编译期枚举，但某个键需要哪些参数、参数是否遗漏，仍由
  加载校验和运行时 `Result` 发现，不是逐键的编译期 schema。
- **复数。** 使用有限 `f64` 计数；英文 `1` 与 `-1` 取单数，`0`、`2`、`1.5`
  取 `_other`；中文取 `_other`。仅当对应语言存在 `_zero` 键时，`count == 0`
  才优先使用 `_zero`。非有限计数返回错误。
- **运行时切换。** `Locale::set_language` 更新实体并通知观察者；GPUI 生产视图
  的默认窗口标题读取 `app.title` + `app.subtitle`，因此英文/中文标题可见变化。
  程序通过 OSC 设置的标题保持原样，`TitleReset` 回到当前语言的最新默认标题。
  当前切换只存在于会话内，不保存配置；持久化留给 P3-02。开发入口只有既有
  debug automation 的 `action=language=en|zh`，没有热键或新界面。

## 偏差

1. 任务卡写“两个语言文件的键集合相同”。实际文件有意不同：英文 2838、中文
   2807，相差 31 个 `_one`。实现按语义基键、各语言必需复数形式和占位符模式
   校验，不修改 JSON 强行补齐字面键，也不要求中文必须带 `_one`。
2. 运行时语言切换目前只有 debug automation 的会话内入口；没有新增设置界面或
   持久化。任务卡要求的运行时切换 API 已由 `Locale::set_language` 提供，配置
   保存与设置界面留给 P3-02。
3. 默认窗口标题使用现有 `app.title` 与 `app.subtitle` 组合；没有新增
   GPUI 专用翻译键或界面。程序 OSC 标题不受语言切换影响。
