## 偏差

### 必须先确认跨卡定义的处理方式

计划 2.7 要求服务方法不接收 Tauri 类型；本轮并行约束只允许在其他卡模块中修改“因为你改了签名而必须跟着改的调用行”。但当前定义如下：

| 本卡调用链                                                                               | 当前跨卡定义（核对基点的行号）                                                                                                                                                                                                                                        | 所属卡与影响                                                                                                    |
| ---------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `profiles/commands.rs::store_profile`、`profiles/storage.rs::delete_profile_secrets`     | `ssh/secret_store/mod.rs:701` 的 `save_password(&self, _app: &AppHandle, ...)`；`:743` 的 `delete_password(&self, _app: &AppHandle, ...)`                                                                                                                             | P1-07a。即使 `_app` 未使用，删除它仍需要修改 a 的定义与其他调用点，超出本轮跨卡权限。                           |
| `profiles/commands.rs::test_connection` → `connection_check.rs::test_connection_handler` | `ssh/types.rs:173` 的 `SshClientHandler.app: tauri::AppHandle`；`ssh/jump/connect.rs:23` 的 `ConnectContext.app: &AppHandle`；`ssh/auth/prompter.rs:14` 的 `AuthPrompter::tab(&AppHandle, ...)`；`core/session/mod.rs:484` 的 `resolve_ssh_password(&AppHandle, ...)` | P1-07a。将连接测试移入无 Tauri 服务仍无法构造这些上下文。需要等待 a 的接口完成，并由签名修改方修复本卡调用行。  |
| `config/mod.rs::save_config`                                                             | `session_log/manager.rs:137` 的 `apply_config(&self, app: &AppHandle, ...)`；`background/mod.rs:79`、`system_integration/mod.rs:97` 的 `apply_config(app: &AppHandle, ...)`                                                                                           | P1-07d。当前保存配置必须调用这三处，不能将编排抽成无 Tauri 服务，也不能在本卡重写其业务逻辑。d 本轮未并行实施。 |

可复核命令：

```sh
rg -n 'pub fn (save_password|delete_password)|pub struct SshClientHandler|pub app:|pub fn apply_config' src-tauri/src/ssh/{secret_store/mod.rs,types.rs,jump/connect.rs} src-tauri/src/{background/mod.rs,session_log/manager.rs,system_integration/mod.rs}
rg -n 'pub fn (tab|resolve_ssh_password)' src-tauri/src/ssh/auth/prompter.rs src-tauri/src/core/session/mod.rs
```

这是跨卡 API 尚未准备好的问题，未发现需要修改 `services/` 字段或计划 2.8 依赖方向的证据。c → app 的 `tunnels`、`session_log` 方向本身符合计划。

建议协调者确认：先由 a、d 各自完成上述定义的去 Tauri 化并更新本卡调用行，再让 c 基于这些接口继续；若仍要求 c 立即实施，则须明确授权哪些跨卡定义由 c 修改，并协调 a 的并行冲突。本轮不自行扩大范围，也不以传入闭包包装 `AppHandle` 的方式隐藏耦合。
