### 从 Alacritty 配置改成参数的地方

| 参数 | 来源 | 默认值 | 说明 |
| ---- | ---- | ------ | ---- |
| `EncoderConfig::alt_sends_escape` | `window.option_as_alt` 与平台 | 非 macOS 为 `true`，macOS 为 `false` | 与 Alacritty 的 `option_as_alt = None` 默认及非 macOS 的 `alt_send_esc = true` 一致。为 `true` 时发 `ESC` 前缀，为 `false` 时发组合字符 |
| `KeyPress::location` | winit `KeyLocation` | `Standard` | 决定小键盘序列与左右修饰键码。GPUI 的 `Keystroke` 不带位置，调用方从平台事件补 |
| `KeyPress::state` | winit `ElementState` | `Pressed` | GPUI 的 `KeyUpEvent` 传 `Released`；只有 kitty 的 `REPORT_EVENT_TYPES` 会写出 |
| `KeyPress::repeat` | winit `KeyEvent.repeat` | `false` | GPUI 的 `KeyDownEvent.is_held`；用于 kitty 事件类型 2 |
| `KeyPress::base_key` | winit `key_without_modifiers` | `None` | kitty 的 alternate-key 与基础键；GPUI 不提供，可选 |
| `KeyPress::shift` | winit `ModifiersState::SHIFT` | `None` | GPUI 会把 Shift 折进标点并从修饰键里清掉；可选覆盖 |
| `KeyPress.keystroke.key_char` | winit `text_with_all_modifiers` | `None` | GPUI 的 `key_char`；命名键另外规范成 `\r`/`\t`/`\x1b`/`\x08`/空格 |
| `MouseModifiers` | winit `ModifiersState` | 全 `false` | 只保留协议有位的 shift/alt/control；`platform`/`function` 忽略 |
| `Wheel` | winit 的像素滚动累计 | `0/0` | 视图做像素累计、倍率与行数取整后传入 |

`search_active`、`hint_state`、输入法预编辑、Vi 模式与应用快捷键不进入编码函数：Alacritty 在调用 `build_sequence` 之前处理它们，视图也必须先处理；`Modes::VI` 时编码器按 Alacritty 的行为直接返回 `None`。

### 与 `ssh_query_handler.rs` 的重叠点

**本卡没有新增任何查询应答者。** 移植的代码只编码用户输入与焦点/鼠标报告，不拦截程序输出里的查询；下面的表把现有的应答方逐条列出，选择由 P2-12 决定，本卡不代选。

| 查询 / 报告 | `src-tauri/src/terminal/ssh_query_handler.rs` | Alacritty 0.26 的模型（P0-09 使用） | 本卡 |
| ----------- | --------------------------------------------- | ----------------------------------- | ---- |
| 主 DA1 `CSI c` / `CSI ? c` | `ESC[?64;1;2;4;6;9;15;21;22c` | `ESC[?6c` | 不参与 |
| 次 DA2 `CSI > c` | `ESC[>0;276;0c` | `ESC[>0;1700;1c`（v0.17.0 的 `version_number`） | 不参与 |
| CPR `CSI 6 n` | 固定 `ESC[1;1R` | 真实光标 `ESC[{line};{col}R` | 不参与 |
| DEC CPR `CSI ? 6 n` | 固定 `ESC[?1;1R` | `device_status(6)` 路径没有单独的 `?` 分支 | 不参与 |
| OSR `CSI 5 n` | `ESC[0n` | `ESC[0n` | 不参与 |
| XTGETTCAP（DCS `+q`） | `Co` 答 256 色，`Ms` 答 OSC 52 字符串，未知答失败 | 不答 | 不参与 |
| 模式查询 `CSI ? Ps $ p`、`CSI Ps $ p` | 不答 | `ESC[?{mode};{state}$y`、`ESC[{mode};{state}$y` | 不参与 |
| Kitty 键盘模式查询 `CSI ? u` | 不答 | 配置 `kitty_keyboard = true` 时答 `ESC[?{flags}u`；P0-09 默认 `false` | 只按模式字节编码，不答 |
| 文本区像素 `CSI 4 t`、字符 `CSI 8 t` | 不答 | `Event::TextAreaSizeRequest` → `ESC[4;{h};{w}t`、`ESC[8;{rows};{cols}t` | 不参与 |
| OSC 10/11 颜色 | 放行，由 xterm.js 前端回答 | `Event::ColorRequest` 由应用回 `OSC 10/11` | 不参与 |
| OSC 52 剪贴板 | 不参与 | `ClipboardPolicy` + `Intent` | 不参与 |
| 焦点上报 `CSI I` / `CSI O` | 不参与 | 输入侧 | **本卡实现**（`focus.rs`） |
| 鼠标上报 | 不参与 | 输入侧 | **本卡实现**（`mouse.rs`） |
| 括号粘贴 `CSI 200~` | 不参与 | 输入侧 | P0-13，本卡不做 |

重复应答的风险集中在 DA1/DA2、CPR、OSR、XTGETTCAP、模式查询与 Kitty 查询：如果 SSH 层继续用旧 handler，同时 P0-09 的模型也把 `Intent::WriteToPty` 写回会话，程序会收到两份回答。P0-13 接入输入通道时必须只保留一条写回路径；本卡没有在视图或编码器里添加第二条。

### 从 Alacritty 有而本卡未移植的内容（给 P2-03、P2-04、P2-11）

- **Vi 模式输入**：`ViAction`、Vi 光标、复制/滚动绑定；`Modes::VI` 时本卡返回 `None`，不消费事件。
- **搜索与 inline search**：搜索输入、延迟、搜索模式下的按键让路；属于 P2-07。
- **提示（hint）键盘选择**：`HintState` 的标签输入、`HintAction`、OSC 8 高亮；本卡只做 URL/路径识别，交互留给链接卡。
- **应用动作与可配置绑定**：复制/粘贴、滚动、字体大小、新窗口/标签、清屏、日志、spawn 等；Alacritty 的 `key_bindings` 与 `BindingMode` 不移植。
- **触摸**：`TouchPurpose`、双指缩放、触摸选择滚动。
- **输入法**：`ImeInhibitor`、预编辑、提交与候选框；P0-13。
- **鼠标选择滚动计时器、像素累计、选择阈值与命中测试**：视图的职责，本卡只做纯编码与选词规则。
- **`OptionAsAlt::OnlyLeft/OnlyRight` 的左右区分**：GPUI 只给一个 Alt 标志，本卡用单个 `alt_sends_escape`；要支持左右需平台层补数据。
- **Kitty 的 `key_without_modifiers`**：标点被 Shift 折进 `key` 时，GPUI 不提供基础键；调用方可以用 `KeyPress::with_platform_key` 补，否则 kitty 编码使用打印字符。
- **X10 鼠标模式（9）**：Alacritty 0.17 不解析，本卡没有对应模式位。
- **应用小键盘的 Alacritty 版本**：Alacritty 0.17 只解析 DECPAM，不编码键；本卡按 xterm 的 SS3 序列补上（见“偏差”）。

### tTerm 的 xterm.js 版有、Alacritty 不支持或不同的行为

核对来源：本仓 `src/lib/keymap/` 与 `src/components/TerminalTab/` 的按键/鼠标处理，以及 `node_modules/@xterm/xterm` 6.0 的 typings 与打包文件（`applicationKeypadMode` 存在，未找到 Kitty 键盘协议的字符串/类型）。

| Shift+滚轮在鼠标上报模式 | 未在本次核对中验证 | 仍上报 | 仍上报 |

## 偏差

1. **没有使用 `migrate/spike`。** 计划允许“原样复制、暂时无法拆分”的代码先放 spike；本卡的四个来源文件都被改写并拆分，键盘 521 行、序列 401 行、字形最大的 406 行，全部低于 800 行，所以直接放在本分支。没有待 P1-13 拆分的文件。
2. **GPUI 的 `Keystroke` 缺少 Alacritty 依赖的几个字段。** 位置、`key_without_modifiers`、被 Shift 折进标点的 Shift 状态、以及按下/重复/释放只由事件类型提供。为此 `KeyPress` 增加了 `location`、`state`、`repeat`、`base_key`、`shift` 五个字段，`EncoderConfig` 承担 Option 策略；默认值与 Alacritty 一致。代价是：**应用小键盘与 kitty 的标点 alternate key 只有在调用方补平台数据时才完全正确**，P0-13 需要把 GPUI 平台事件里的位置等信息接进来；本卡没有在真实窗口里验证这些字段。
3. **应用小键盘是扩展，不是 Alacritty 的行为。** Alacritty 0.17 的 `input/keyboard.rs` 只解析 `APP_KEYPAD`，没有数字键的绑定；本卡按 xterm 的 DECPAM SS3 序列补上，并在 APP_KEYPAD 打开时让小键盘 Enter 发 `ESC OM`。未开 DECPAM 时仍按 Alacritty 的绑定发 `\n`（不是 `\r`），这与 xterm.js 可能不同，P0-15 应逐项对照。
4. **Ctrl+Space 合成为 NUL。** Alacritty 依赖平台 `text_with_all_modifiers` 产出控制字符；GPUI 对 Ctrl 组合不给 `key_char`，所以编码器按 xterm 约定合成 `\x00`。Ctrl+字母与 `[ \ ] ^ _ ?` 同样合成；其他无 C0 对应的键回落到文本路径。
5. **Shift+滚轮在鼠标上报模式下仍上报。** Alacritty 的 `scroll_terminal` 先走上报分支，只有备用屏幕方向键分支检查 Shift。设计说明 8.3 把 Shift 写成通用逃逸键，容易读成滚轮也应本地滚动；本卡按 Alacritty 修正并加测试。建议 P0-12/P2-04 明确滚轮的 Shift 语义。
6. **P0-09 的鼠标模式注释互换。** `MOUSE_MOTION` 位实际对应 1003（全量移动），`MOUSE_DRAG` 对应 1002（按键拖动）；注释原先把两个协议号写反。已修正并用写入 `CSI ? 1002 h` / `CSI ? 1003 h` 的测试固定映射；同时新增 `Modes::union` 供视图组合标志组。
7. **字形从位图改成矢量，三处外观调整。**
   - 圆角 `╭╮╯╰` 的半径取短边的 1/4，而 Alacritty 的光栅圆弧约为短边的一半；后者在髙单元格里会把直臂挤没，矢量版需要保留直臂。截图里圆角比 Alacritty 略紧。
   - 阴影 `░▒▓█` 用 Alacritty 的固定灰度 64/128/192/255（`GlyphFill::Gray`），不跟随前景色；xterm.js 用的是字体自带的点阵字形，因此与 Tauri 版对比时这一组会有可见差别，这是“移植 Alacritty 内置字形”的预期结果。
   - Powerline 的行循环按实测单元格宽度横向拉伸，并用 Alacritty 的竖向人字形条带画箭头；方形单元格下也能到边，而 Alacritty 的原始几何假设字形约为半宽。
8. **URL 正则去掉了 `{-}`。** Alacritty 的 `URL_REGEX` 在字符类里有一段 `{ - }` 集合写法；`regex` crate 不接受它，而且按集合语义它是空操作。本卡保留其余排除字符与 scheme，删掉这一段。URL 的结尾截断规则按 `HintPostProcessor` 重写为字符串偏移版。
9. **裸路径规则是 tTerm 自己的。** Alacritty 只有 URL 与 OSC 8 链接，没有裸路径识别；xterm.js 的 WebLinksAddon 也只有 URL。本卡按执行说明补了一个保守规则（绝对/家目录/显式相对/Windows 盘符/带扩展名的相对路径），`hint/path.rs` 不登记第三方来源，并在报告里明确它不是移植行为。
10. **“在 macOS 截图”用的是无头 Metal 渲染。** 会话没有屏幕录制权限，`screencapture` 无法读取显示器；`glyph_grid --screenshot` 用 GPUI 的 `HeadlessAppContext` + `current_headless_renderer()` 渲染同一视图并写 PNG。它不是窗口截图，但内容与窗口渲染同源；Tauri 对照仍按任务卡留 `[人工]`。
11. **`Snapshot::grid_line` 与 `Modes::union` 是补的模型接口。** 前者是 `screen_row` 的逆，供提示模块把可见行映射回绝对行；后者让视图把 kitty 模式位组合成一个组。两者都有测试（`grid_line_inverts_screen_row`、`mode_sets_combine_for_groups`）。
12. **新增依赖。** `tterm-terminal` 直接依赖 `regex = "1"`，锁文件里已有 1.13.1（`src-tauri` 早已使用），没有新版本与新包；`tterm-gpui` 的 `[dev-dependencies]` 增加本地 `tterm-terminal-view`，只给 example 用，不进入正常二进制依赖图。
