# P3-07 Windows 标签拖动对照（2026-11-21）

基点：`5e77d8b1`。修正曲线并接入首版分屏后，用户反馈实际验证未发现问题。下表记录的是修正前的代码与测试对照，不是桌面帧测量；未留存双端录屏。

| 对照项 | Tauri | GPUI | 结论 |
| --- | --- | --- | --- |
| 相邻标签让位 | `TabItem.css`：200 ms，`cubic-bezier(0.2, 0, 0, 1)` | `window/motion.rs`：200 ms，`1 - (1 - t)³` | 时长相同，曲线不相同。单次完整过渡的 50 ms 处，理论位移分别约为 60.7% 和 57.8%；这不是帧测量。 |
| 靠边持续滚动 | `useTabDrag.ts`：边缘 40 CSS px，最多 14 px/帧 | `window/drag.rs`：边缘取 40 逻辑 px 与半视口宽度中的较小值，最多 14 px/帧 | 常规宽度下参数一致，不能推出两端实际帧率一致。 |
| 停止与落位 | 松手提交；有位置捕获和回落过渡 | 无界面窗口测试验证停靠连续多帧滚动、移出和松手停止；纯状态测试验证快速反向和宽标签能到两端 | 停止逻辑有测试；最后一帧是否出现可见跳动仍待双端录像。 |

已有 `workspace.titlebar.default` 的 Windows React 基线只覆盖静态外观；夹具的 `moveTab` 是空回调，不能用它证明真实重排。本次没有打开正式 Tauri 用户配置，也没有用旧的 GPUI release 二进制代替当前源码。

本批已修正表中基点的曲线差异：GPUI 按同一条 `cubic-bezier(0.2, 0, 0, 1)` 求值，回归测试覆盖端点、中间采样与中途反向。该修正不是桌面手感验收结论。

## 人工复核方法

1. 按 `scripts/perf/README.md` 的 Windows 隔离步骤构建并启动独立标识的 Tauri；GPUI 从同一提交构建并启用独立 `TTERM_GPUI_CHECK_INSTANCE`。确认两边都只有测试本地会话。
2. 在同一显示器使用相同缩放率和相同客户区宽度，记录各自标签滚动区实际宽度。打开一组相同标题的长短标签，直到两边都发生溢出。分别记录活动标签。
3. 用同一只鼠标慢速越过邻项中点、快速反向，再把后台标签拖到栏边缘并保持指针不动一秒。左右各做一次；分别尝试松手、移出和 Esc。确认取消不改顺序、移动后台标签不改变活动会话。
4. 记录两段带指针的同帧率视频、窗口尺寸与缩放；复看开始让位、反向、边缘停靠、释放后的第一帧。仅在有双端观测之后更新本报告的验收结论。
