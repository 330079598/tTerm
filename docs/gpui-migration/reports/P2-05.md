## 行为与实现

- 键盘、平台文本粘贴、Linux PRIMARY、右键和本地文件拖放统一经过 view 的 paste gate。确认条件复用 core `paste_guard`：启用确认、包含 CR/LF、未启用括号粘贴。共享 UI `Dialog` 负责焦点、确认与取消，文本来自现有 en/zh JSON，并随 Locale 更新。
- pending 请求保留文本和 session nonce；确认时再次检查当前连接。对话框打开时拒绝后续请求。立即粘贴直接由 view 继续执行，避免重入同一个 GPUI entity；确认后的延迟回调重新进入 view。
- 请求与确认后发送均读取模型当前模式，而非上一帧的缓存。读取模式不复制网格、不消费 damage。CRLF/LF 在普通和括号粘贴中都转为 CR，依据当前 xterm.js `src/browser/Clipboard.ts`；过滤原有 C0/C1 控制字符以防嵌入括号结束串。
- copy_on_select 仅在本地左键选择完成时复制非空文本，包括恢复丢失 release 的路径。右键粘贴尊重程序鼠标上报和 Shift。
- 文件拖放复用 core 的 shell 检测与 `dropped_paths`，按 PowerShell/cmd/WSL/Git Bash/POSIX 的既有规则转义，不添加 Enter。与当前 Tauri 一样，仅本地终端接收本地路径；SSH/serial 不写入本机路径。
- OSC 52 的所有支持目标（空、c/p/q/s/0–7 及组合）统一产生普通剪贴板 store。查询仍由既有模型读取策略控制；GPUI 产品路径禁止读取，不增加 responder。空文本、非法 base64、非法目标不清空剪贴板。
- 共享有界 control-string framing 从 prompt scanner 抽出。prompt scanner 默认不缓存 OSC52 payload；模型自己的 scanner 在 ClipboardPolicy 允许复制时解码。主 parser 推进到 store 的偏移后才入队对应 Intent，保留标题、查询、store 的流顺序。Alacritty 的 store 分支关闭，读取 formatter 保持原路径。
- parser 到 UI 用单槽与 watch 合并写入；隐藏标签也处理。UI 线程再次检查连接有效性；控制器销毁后先检查 entity 存活再取槽，避免遗留任务消费后续写入。

## 边界

新增 scanner 的原始 payload 上限为 `ceil(1 MiB / 3) * 4 + 16` 字节，超限整串丢弃，不能接受截断前缀。该上限包含目标和 base64 空白，极长目标或空白也可能被拒绝。UI 槽最多接受 1 MiB UTF-8 文本。它们是新增路径的界限，不能称为整个解析器内存上界；原有 Alacritty/VTE parser 仍使用其既有缓冲。

设置在启动时读取；P3-02 将负责运行时配置实体与传播，本卡没有声称已有设置界面的实时修改。对话框预览目前使用共享 description 文本；完整预览外观随 P3 主题与组件继续对齐。
