### 模块去向

`tterm-terminal` 不依赖 `tterm-core`。共享的 JavaScript 字符串/编码工具和命令标记类型放在被依赖的 `tterm-terminal`，`tterm-core` 单向依赖它们，没有在两边各定义一套。

| TS 模块 | 去向 | 理由 |
| --- | --- | --- |
| `agentStatus.ts` | `tterm-core::agent_status` | 代理会话状态、跨 tab 所有权与通知时序属于业务状态，不属于终端模型；仅复用终端的 URI/UTF-16 解码。 |
| `osc52.ts` | `tterm-terminal::osc52` | OSC 52 是终端输出里的剪贴板请求，解析结果由终端视图消费。 |
| `oscLinkDedupe.ts` | 不移植 | 只替换 xterm 6 的 `registerLink`、`_removeMarkerFromLink`、`_dataByLinkId` 和 `_bufferService` 私有成员，依赖 xterm 的 buffer/scrollback/alternate screen；原生终端没有该泄漏。 |
| `terminalCwd.ts` | `tterm-terminal::terminal_cwd` | OSC 7/OSC 9;9 是终端输出协议，输出可直接供原生终端模型使用。 |
| `remoteCwd.ts` | `tterm-core::remote_cwd` | 每 tab 的远程目录、away host 和订阅属于工作区/会话状态；React hooks 留给原生视图状态。 |
| `terminalCommandCapture.ts` | `tterm-terminal::terminal_command_capture` | 从 PTY 输入流维护命令编辑状态，属于终端输入处理。 |
| `terminalOutputScanner.ts` | `tterm-terminal::terminal_output_scanner` | 扫描字节输出里的连接状态标记并处理分块 UTF-8，属于终端输出。 |
| `sudoPrompt.ts` | `tterm-terminal::sudo_prompt` | 从终端光标行识别密码提示，直接依赖终端 `Snapshot`。 |
| `passwordFeedback.ts` | `tterm-core::password_feedback` | 无终端类型的密码编辑计数，只与认证交互状态有关。 |
| `loginScript.ts` | `tterm-core::login_script` | 登录脚本的会话编排与计时，不依赖终端渲染模型。 |
| `pasteGuard.ts` | `tterm-core::paste_guard` | 粘贴确认策略与文本摘要，是独立业务规则。 |
| `terminalNotifications.ts` | `tterm-core::terminal_notifications` | OSC 通知解析、通知设置和 tab attention 规则属于业务事件；命令标记类型由终端 crate 共享。 |
| `distro.ts` | `tterm-core::distro` | 发行版识别和服务器监控元数据，复用 `events::ssh::LinuxDistributionInfo`。 |

### 主要文件

- `crates/tterm-terminal/src/js_text.rs`：按 UTF-16 code unit 计算长度、切片、截断、插入和删除，并提供 ECMAScript `trim` 空白字符集。
- `crates/tterm-terminal/src/js_encoding.rs`：复现 `atob`/`TextDecoder` 与 `decodeURIComponent` 的相关行为，包括 BOM 丢弃和宽松 UTF-8 替换。
- `crates/tterm-terminal/src/terminal_command_capture.rs`、`terminal_output_scanner.rs`、`terminal_cwd.rs`、`osc52.rs`、`sudo_prompt.rs`：终端输入/输出与提示识别。
- `crates/tterm-terminal/src/command_mark.rs`：`tterm-core` 的通知规则与下一组命令标记解析共用的标记类型；本轮没有移植 `components/TerminalTab/commandMarks` 的解析器。
- `crates/tterm-core/src/agent_status.rs`、`terminal_notifications.rs`、`distro.rs`、`paste_guard.rs`、`password_feedback.rs`、`login_script.rs`、`remote_cwd.rs`：业务状态、通知与工作区纯逻辑。
- `scripts/migration/p1-11a1-oracle.mjs`：用 `typescript.transpileModule` 直接加载真实 TS 模块，生成 Rust 补充测试的期望值。

## 偏差

1. **`oscLinkDedupe` 不移植。** 该模块只在 `term._core._oscLinkService` 上包装 xterm 6 私有成员，5 个测试全部通过 xterm 的 buffer、scrollback 和 alternate-screen 状态观察内部链接表。原生终端使用自己的超链接模型，不需要也不能复用这个绕过；若后续原生终端出现同类链接累积，应在原生链接缓存层新建测试与修复。
2. **`AgentTracker` 和 `LoginScriptRunner` 使用显式时钟。** TS 使用 `Date.now()` 与 `setTimeout`；Rust 分别接收 `now` 参数并由调用方调度 `poll`/`fire_due`。测试中的时间点、延迟和断言值没有改变。
3. **`readCursorLine` 使用终端 `Snapshot` 代替 xterm `IBuffer`。** 可见行列与 wrap 语义来自原生终端模型；现有两个折行/光标测试的期望字符串不变。
4. **`remoteCwd` 的两个 React hooks 不定义。** store、getter、setter、订阅和取消订阅已移植；`useTabRemoteCwd`、`useTabRemoteAwayHost` 由 P3 工作区视图状态替代。
5. **Rust 不能保存孤立代理项。** 当 JS 按 UTF-16 下标切在代理对中间时，Rust 结果用 U+FFFD 表示丢失的一半；这是类型能力差异，已用 emoji 切块与截断测试固定。组合字符仍按 code unit 保留，不做 NFC 归一化。
6. **`isDistroId(undefined)` 没有同值 Rust 参数。** Rust API 接收 `&str`；测试用空串和未知字符串覆盖非法输入，`undefined` 的真假判断由调用方在转换成 `Option<&str>` 时处理。
7. **`NSEnumerator` 修复不属于原任务范围。** 基线 macOS 在 `tterm-platform` 的 `native/open/apps.rs` 使用 `urls.iter()` 编译失败，缺少 `objc2-foundation::NSEnumerator` feature。单独提交该一行 feature，未改行为或依赖版本。
8. **BOM 是最终审计中修正的偏差。** `String::from_utf8_lossy` 不丢弃 BOM，而 `TextDecoder` 会丢弃一个前导 BOM；`decode_utf8_text` 现在先移除一个 `EF BB BF`，并由 node oracle 覆盖。

### 正则表达式与匹配条件

所有需要 ECMAScript 语义的正则都用 workspace 已固定的 `regress = 0.12.0`；没有改用 Rust `regex` 的近似版本。TS 与 node 的正反例在 oracle 中逐条运行。

| 位置 | 模式或条件 | 对照结论 |
| --- | --- | --- |
| `terminal_cwd.rs` | `^file://([^/]*)(/.*)$` | regress 与 JS 的 `$`、非贪婪组和 `/` 排除一致；`file:///tmp\n` 两边都为 null。 |
| `terminal_cwd.rs` | `^/[A-Za-z]:([/\\]|$)` | 纯 ASCII 字符类与 JS 一致，正例 `C:/Users`、反例 `/c/Users`。 |
| `terminal_command_capture.rs` | `\s*\S+\s*$` | regress 的 `\s`/`\S` 走 ECMAScript UTF-16 语义；正例中文/emoji 尾词删除，反例无尾词不改变。 |
| `sudo_prompt.rs` | `^\[sudo\] password for '?(\S+?)'?:$` | 正例普通与带引号用户名，反例缺少用户名或结尾冒号。 |
| `sudo_prompt.rs` | `^\[sudo\] (\S+) 的密[码碼][:：]$` | 正例简繁中文，反例英语/未知 locale。 |
| `sudo_prompt.rs` | `^doas \((\S+?)@[^)]*\) password:$` | 正例 doas，反例 ssh 登录提示。 |
| `sudo_prompt.rs` | `^\[sudo\] .+[:：]$` | 已知用户 token 的 locale 前置条件；正例德语/法语，反例不含登录用户。 |
| `sudo_prompt.rs` | `^\[sudo: authenticate\] (.+)[:：]$` | sudo-rs 前缀；正例 Password/密码，反例 PIN/验证码。 |
| `sudo_prompt.rs` | PAM 密码词汇表，`i` | 正例大小写 Password/Passwort/ПАРОЛЬ/中文，反例 PIN/Verification code；固定词表与 TS 相同。 |
| `sudo_prompt.rs` | `(^|[\s(])<escaped known user>($|[\s):：'’])` | 用户名按 JS `escapeRegExp` 集合转义；正例 `a.b`，反例 `stoneage`。 |
| `terminal_notifications.rs` | `^\d+(;|$)` | ASCII 数字与 JS 一致；正例 `9;`/`4`/`9` 被排除，`9\r\n` 作为普通消息保留。 |

以下条件没有使用正则，而是用显式字符集合替换，以避免 Rust 与 ECMAScript 的 Unicode 属性差异：

- `agent_status.rs` 的 agent/session 校验是显式 ASCII 范围，与 TS 的 `^[a-z0-9][a-z0-9-]{0,31}$`、`^[A-Za-z0-9-]{1,64}$` 等价。
- `agent_status.rs` 与 `terminal_notifications.rs` 的 `\p{Cc}` 校验使用 U+0000–U+001F、U+007F–U+009F 并合并连续控制字符，与 TS 的 Unicode Cc 类别相同。
- `osc52.rs` 的 selection target 是显式 `c`、`p`、`q`、`s`、`0`–`7` ASCII 集合。
- `login_script.rs` 的 `SHELL_PROMPT_END` 使用同一结尾字符集配合 `js_trim_end`。
- `paste_guard.rs` 的 `/[\r\n]/` 使用 `contains('\r') || contains('\n')`。
- `agent_status.rs` 的 Windows 路径识别使用显式前缀/盘符判断，保留 TS 的“SSH POSIX 路径大小写敏感、Windows 路径大小写不敏感”规则。

`regress 0.12.0` 的 `i` 大小写折叠有 P1-11b 已记录并接受的上游差异：它会把 U+017F（ſ）折叠到 `s`。本卡没有新增规避实现；PAM 词汇表使用同一引擎，普通正反例已由 node 对照，但该上游差异仍属于已知遗留风险。

## UTF-16 与编码边界

- 所有长度、游标、切片和截断都经过 `js_text` 的 UTF-16 code unit API。测试覆盖中文、emoji（代理对）和 `e` + U+0301 组合字符。
- `utf16_tail(text, 0)` 按 JS `slice(-0)` 返回整个字符串；该边界由 node 输出 `abc` 固定。
- 任何切在代理对中间的 Rust 结果只能把孤立的一半表示为 U+FFFD；TS 可以保留孤立代理项。该差异在 `js_text` 和 `scanTerminalOutput` 的 emoji 切块测试中明确写出。
- `atob` 的宽松 base64、忽略 ASCII 空白、仅在长度为 4 的倍数时去掉 padding、拒绝残缺 padding，均由 node oracle 覆盖；空解码结果按 TS 的 `text ? text : null` 返回 `None`。
- `TextDecoder` 每次独立解码且丢弃一个前导 BOM；`decode_utf8_text` 相同。node 输出：`[EF BB BF 61] -> "a"`、`[EF BB BF] -> ""`、`[EF BB BF EF BB BF] -> "\u{FEFF}"`、`[61 EF BB BF] -> "a\u{FEFF}"`。
- 分块边界没有新增跨块缓冲以“修复” TS 行为：被切开的转义序列、base64 或 UTF-8 序列按 TS 的独立块处理；只有 `terminalOutputScanner` 的 10 个 UTF-16 单元 carry 保留。测试覆盖 `ESC`/`[A`、`ESC[200`/`~` 和 `[Conn`/`ecting`。

## 遗留问题

- `regress 0.12.0` 的 `i` 大小写折叠对 U+017F（ſ）与 JS 不同，见 P1-11b 已记录并接受的上游差异；本卡依赖同一固定版本，未擅自 patch 第三方源码。
- `oscLinkDedupe` 的 5 个测试不迁移；原生终端若以后出现无 id OSC 8 链接重绘累积，应由 P2/P3 的链接缓存测试发现并另开修复。
- Windows 运行验证待补（决策 016）；Linux 运行验证推迟（决策 016）。本轮只在本机 macOS 完成编译和测试，三平台 CI 以工作流实际结果为准。
- 未启动 GPUI/Tauri，未做界面验收；按决策 017，`GPUI` 分支不单独验证 Tauri 运行时。未读写 `com.stone.tTerm` 或 `com.stone.tTerm.dev` 数据目录。
