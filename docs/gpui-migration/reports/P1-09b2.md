### 过滤输出说明

`git show -M -U0 dfc3507d -- '*.rs'` 再用计划 4.1 的过滤命令，输出 5543 行。按文件分：

## 偏差

1. **b2 的 114 个文件不能单独编译，必须带上 4 个直接子模块。** 这些子模块的父文件不是 `mod.rs`，父文件移走后 Tauri 没有地方声明它们：
   - `ssh/auth/prompter.rs`（工具第 17 批）：`impl AuthPrompter` 是 inherent impl，类型在 `ssh/auth.rs`；
   - `ssh/client/reader.rs`（第 28 批）：`ssh/client.rs` 声明 `mod reader;`，且 Tauri 没有 `ssh/client` 模块可留；
   - `terminal/ssh_query_handler.rs`（第 18 批）：移动后的 `ssh/client/reader.rs` 调用它；
   - `session_log/maintenance.rs`（第 23 批）：`impl SessionLogState`，类型在 `session_log/mod.rs`。

   我按“同一模块树”处理，把它们放进 `dfc3507d`，在报告这一节写明。建议评估者把工具补上“`mod` 声明即父文件拥有子文件”与“inherent impl 必须与类型同 crate”两条边；否则 b3 会再次遇到。

2. **`io_batcher` 的两个 Tauri 专用测试文件在移动前换了父模块。** `contracts.rs` 断言 `tauri::ipc::Channel` 的 Raw 负载，`benchmark.rs` 用 Channel 跑 50 MB 吞吐；它们不能进 core。`cc7bc7f3` 把它们移到 `session_sink`，把只测 flow 内部状态的断言留在 `io_batcher/tests.rs`，断言逐字不变。`test_sink` 因此改为 `#[cfg(any(test, feature = "test-support"))] pub`。

3. **12 个 `mod.rs` 是合并而不是整文件重命名。** 计划 4.1 第 2 步本来就说“父模块里加/删 `mod` 声明”；对 `config`、`session_log`、`serial`、`proxy`、`system_integration`、`terminal`、`zmodem`、`core/session`、`ssh/key_vault` 是“内容移走、Tauri 留桩”，对 `profiles/parser`、`ssh/openssh_known_hosts`、`ssh/secret_store` 是“并入 core、Tauri 删除”。`git diff -M` 因此不能把它们显示成重命名。

4. **b1 的 Windows 缺口先修了。** 本 worktree 的基线在 Windows 上编译不过：core 缺 `windows` 依赖，`lib.rs`/`core/commands/mod.rs` 还指向旧的 `terminal::console_reset`，`zmodem/container_tests` 在 Windows 上引用 unix-only 的 `test_sshd`。`a1969fcd` 只改依赖、路径和测试 `cfg`，不改行为。

5. **Windows-only clippy 缺口。** `tterm-platform` 的安装器分支和 `terminal/types.rs` 的控制台重置分支只在 Windows 编译，b1 的 macOS 检查看不到。`57a66bf6` 与 `20901c6a` 是等价的 let chain/`Default`，不属于 b2 的功能改动。

6. **签名基线的两处类型路径。** `create_pty` 的 `connection` 与 `get_sudo_password_source` 的返回类型从 `super::session::…` 变成 `tterm_core::core::session::…`；名称、参数名、参数个数、序列化形状都没变。`03cb3041` 重新生成基线，`d747c710` 修了签名脚本在 Windows 上的路径与入口守卫。

7. **`scripts/migration/core-move-graph.py` 的盲区。** 它把 `mod x;` 只当成“裸路径可用的名字”，不认为那是父文件拥有子文件；也不看 inherent impl。本轮的 4 个额外文件就是这两类盲区。建议修工具后再排 b3。

8. **`use` 语句被展开重排。** 为了把混合了 core/Tauri 项的 `use` 拆开，109 个 Tauri 文件的 `use` 被重写成逐项形式；语义相同，`cargo fmt` 之后是合法的。这让移动提交的 diff 比“只改路径”大，但每一行都仍是 `use`/路径。

1. **b3 未开始。** 现在 `batches` 是 34 批 / 128 个可移动文件，`adapters` 以 0 退出。剩余的大块：`sftp` 37、`agent_integration` 9、`serial` 8、`profiles` 6、`core` 6、`services` 3、`monitor` 3、`tunnel` 3、`backup`/`sync` 的 13 文件环、`db/legacy_import`，最后是 `adapters`/收尾。

3. **`ssh/test_sshd` 现在是 `#[cfg(all(any(test, feature = "test-support"), unix))] pub`。** b3 里还在 Tauri 的 `sftp`/`agent_integration` 真实 sshd 测试通过 `tterm_core::ssh::test_sshd` 使用它；Windows 上这些测试本来就是 unix-gated。
4. **未验证：** macOS 与 Linux 的本机编译（本机只有 Windows，交给 CI）；28 个 ignored 的真实 sshd/代理/性能测试没有运行；Tauri 版的人工界面验证按[决策 017](../../decisions/017-gpui-branch-tauri-untested.md)不做。
5. **工具建议：** 给 `core-move-graph.py` 加两条边（`mod` 父子、inherent impl 与类型同 crate），再把 `use` 展开列入“移动提交允许的变化”，评估者的过滤命令可以少一些噪声。
