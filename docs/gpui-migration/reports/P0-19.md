# P0-19 文件拖出方案

## 结论

部分完成。提交了独立 Windows GPUI 原生拖出示例与决策 011 草稿；原生 Shell 数据对象和延迟生成 200 MB 的本地内容管线通过测试，但真实资源管理器拖放未验证 `[人工]`。macOS 仅按源码判断现有文件承诺方案可接入，未运行验证；Linux 现有方案缺少延迟文件导出能力，明确列为当前不可用，未运行验证。不把编译、本地文件复制或 Shell 格式查询等同于拖放成功。

## 偏差

1. 路径与任务卡一致，没有发现需要改卡的源码位置偏差。按本轮补充只实现 Windows 独立示例；macOS/Linux 以源码可行性评估代替运行，不声称完成三平台演示。
2. 演示复制了现有 Windows 原生实现的最小部分，没有复制全局 Shell watcher，改为只检查启动时指定的 TEMP 目录。这是受控落点演示，不能证明任意目录识别；P1 后共享提取方案已写入决策 011。
3. GPUI 的原始句柄 trait 需要 `raw-window-handle`，pins.md 没有登记这一直接依赖。演示使用已有 windows API 查询前台 HWND，检查 PID、标题与 GPUI active，未新增依赖。未尝试以布局转换等方式访问私有字段。
4. 未驱动原型窗口。`AUTOMATION.md` 接口校验主程序 `Prototype` 实体，不适用此独立示例；本轮又明确禁止修改主程序，所以没有扩展接口或用其他自动化绕过它。真实鼠标拖放允许，但无法在此接口下完成，按用户许可标 `[人工]`。无截图、无录屏。

## 遗留问题

- `[人工]` Windows 真实拖到指定 TEMP 资源管理器空目录：按示例 README 保存 stdout、截图/录屏，验证最终大小/内容、占位清理与刷新、Escape 取消、落回本窗口、无效落点和重复拖动。测试数据允许目录外无写入；选错目标可能遗留空占位文件。
- 未验证 Windows OLE 嵌套事件循环与 GPUI 输入回调重入、鼠标捕获、UI 响应、峰值 RSS、磁盘不足/锁定文件/进程中断。本地文件测试不覆盖这些风险。取消不打断已启动生成，最多等待其完成才清理。复制不是原子发布，崩溃可能留部分目标。
- macOS 未实现/编译本例，缺少本轮可操作的 Mac/Finder。后续提取 promise 适配时应等下载结束才调用 completion，不能继承当前生产实现的“立即兑现、后续另行下载”行为作为成功证据。
- Linux Wayland/X11 未运行验证，缺少真实桌面/文件管理器；现有路线不满足延迟文件导出，需要后续单独评估是否实现 Linux 原生适配或按 P0-06 退路补丁。此处的“不可用”针对当前代码，不是断言平台永久无法支持。
- 决策 011 保持“提议”，是否接受 Linux 缺口、何时补平台验证由评估者/决策人决定。本轮未合并到 GPUI，未开始下一卡。

## 评估

结论：通过（Windows）。决策 011 保持“提议”，Linux 的缺口由决策人决定。

评估者在 2026-11-08 用真实鼠标完成了执行者标为 `[人工]` 的 Windows 拖放。驱动脚本 `assets/P0-19/manual/drag-real-mouse.ps1`：新建 `%TEMP%` 下的空目录并用资源管理器打开，把这个窗口临时置顶（前台锁会拒绝普通的提到最前，第一次尝试时落点被评估者自己的终端窗口挡住，脚本在发出任何输入之前停下）；按下前确认前台是演示窗口，松开前确认光标下是这个资源管理器窗口；测完关闭窗口并删除目录。

| 场景 | 结果 | 证据 |
| --- | --- | --- |
| 拖到资源管理器 | 通过：`native_drag_started ... placeholder_bytes=0` 之后才生成内容，`native_drag_ended accepted=true`，`Published and verified bytes=200000000`；目标目录最终只有 `generated-200MB.bin`，200,000,000 字节，占位文件已删除 | `manual/drop-stdout.txt`、`drop-1-before.png`、`drop-2-probe-after.png`、`drop-3-explorer-after.png` |
| 拖动中按 Escape 取消 | 通过：`accepted=false`，目标目录为空，`generated staging content discarded` | `manual/escape-stdout.txt`、`escape-*.png` |

发现的问题：发布完成三秒后，资源管理器的视图仍显示 0 字节的占位文件 `tTerm-P0-19-drag-<pid>-0.bin`，没有刷新为 `generated-200MB.bin`（`drop-3-explorer-after.png`）。生产实现在发布后需要通知 Shell 刷新（例如 `SHChangeNotify`），或改用不经过占位文件改名的发布方式；列为决策 011 的后续事项。

未验证：落回本窗口、无效落点与重复拖动；拖放期间的峰值内存与窗口响应；macOS 与 Linux。
