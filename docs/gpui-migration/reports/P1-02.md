## 接口设计

### 领域分组

`AppEvent` 是业务事件的总入口，但每个领域拥有自己的事件枚举：

```rust
pub enum AppEvent {
    Tunnel(TunnelEvent),
    // 后续按领域增加：Ssh(SshEvent)、Sftp(SftpEvent)、Terminal(TerminalEvent)……
}
```

本卡只实现 `TunnelEvent::Status(TunnelStatus)`。这样 GPUI 可以订阅 `AppEvent::Tunnel(...)` 后在 tunnel 领域内匹配，而不会依赖客户端字符串；P1-03/P1-04 分别增加 SSH、SFTP 等领域时，只扩展一个领域文件和一个总枚举变体，不把所有 payload 塞进一个平面枚举。

payload 继续使用现有 serde 类型。tunnel 的 `TunnelState`、`TunnelStatus`、`TunnelTraffic` 和 `TunnelFailure` 已移动到 `tterm-core::events::tunnel`，序列化属性逐字保留：状态使用 lowercase（`needsCredentials` 仍为原显式名称），结构使用 camelCase。

### EventSink 方法

```rust
pub trait EventSink: Send + Sync {
    fn emit(&self, event: AppEvent) -> Result<(), String>;
}
```

core 只看 typed event 和可行动的 `String` 错误，不依赖 Tauri 或 GPUI。同步方法适合当前 emit 语义：Tauri `emit` 本身只把事件交给前端队列，不等待前端处理；GPUI 适配器以后可把同一事件放入 UI 通道。tunnel reporter 保存 `Arc<dyn EventSink>`，因此测试可以注入 recording sink，客户端可以注入不同适配器。

### 事件名和目标

`EventName` 有两个形态：

- `Static("tunnel-status")` 表达稳定事件名。
- `TabScoped { prefix, tab_id }` 表达 `format!("{prefix}-{tab_id}")`，覆盖 `sftp-upload-batch-complete-{tab_id}`、`pty-output-{tab_id}`、`zmodem-{kind}-{tab_id}` 等现有动态命名。动态部分留在 typed event，适配器最后生成字符串，避免业务代码自行拼接。

`EventTarget::Default` 对应旧的 `app.emit(...)`；`EventTarget::Any` 对应旧的 `app.emit_to(tauri::EventTarget::any(), ...)`。两者不能合并：前者保留 Tauri 默认 app 目标，后者明确广播到所有 webview。tunnel status 的目标是 `Default`，与改动前一致。

GPUI 端以后按领域订阅：先从通道取 `AppEvent`，对 `AppEvent::Tunnel(TunnelEvent::Status(status))` 更新 tunnel store；其他领域各自消费自己的变体。GPUI 不需要知道 Tauri 事件名，只有 Tauri 适配器负责 wire name、目标和 JSON。

### 适配器和录制器

`TauriEventSink::wire` 是纯映射函数，返回 `(EventName, EventTarget, serde_json::Value)`，然后由适配器调用 `emit` 或 `emit_to(any)`。保留 `wire` 纯函数让兼容性测试无需创建窗口。`RecordingEventSink` 在 `#[cfg(any(test, feature = "test-support"))]` 下编译，记录完整 typed event，测试可比较领域、变体和 payload。

## tunnel 迁移证据

`tunnel/runtime/reporter.rs` 现在持有 `Arc<dyn EventSink>`；`TunnelManager::reporter_for` 注入 `TauriEventSink`。reporter 的状态更新、traffic 保存、tick 节流和 tray 刷新顺序未变，只替换最终发送调用。tunnel 模块中已无直接 `AppHandle.emit`/`emit_to` 调用；`AppHandle` 仍用于读取 profile、secret 和 tray 刷新，这些用途不属于本卡事件范围。

兼容性测试 `event_sink::tests::tunnel_status_wire_contract_matches_existing_tauri_event` 构造完整 status payload，并断言：

- 事件名为 `tunnel-status`；
- 目标为 `EventTarget::Default`；
- JSON 使用旧的 `camelCase` 字段和 `running` 状态；
- `lastFailure`、`lifetime`、时间戳和计数值逐项相等。

`RecordingEventSink` 测试记录 `TunnelEvent::Status`，证明 typed payload 在 sink 中不被改写。

### [人工] 隧道面板步骤

1. 使用临时 Tauri 标识和空 `XDG_CONFIG_HOME`，按 `dispatch.md` 第 5 节写入 `target/` 下的 `--config` JSON；禁止使用 `com.stone.tTerm` 或 `com.stone.tTerm.dev`。
2. 启动隔离 Tauri 版后先只读调用 `list_profiles`，确认返回空数组；再在隔离目录中创建仅用于测试的 `localhost` SSH profile 和 tunnel rule。
3. 在本机开启 sshd，并用隔离密钥配置 `ssh localhost`（仅监听 loopback）。确认 tunnels 面板收到 `tunnel-status`：`starting` → `running`，`boundPort` 与规则一致。
4. 对本地转发端口发一次无害连接，确认 `activeConnections`、`totalConnections`、`bytesUp/bytesDown` 更新；断开后确认 active 回落为 0。
5. 点击停止，确认收到 `stopped`，`boundPort` 清空且 lifetime traffic 保留。
6. 退出 Tauri，检查并删除临时标识在 `~/Library/Application Support/` 与 `~/Library/Caches/` 下的目录和 `target/` 配置 JSON；报告中附清理路径、事件面板截图或录屏。

## 偏差

1. 任务卡把 tunnel payload 描述为“使用现有 serde 类型”，而这些类型原来位于 `src-tauri`。为让 core 的 `AppEvent` 真正可被 GPUI 使用，本轮增加了一个纯移动提交把 tunnel payload 放进 `tterm-core::events::tunnel`；serde 属性和持久化 JSON 未变。这是必要的接口落点，未扩大到其他领域类型。
2. 现状统计写 tunnel 5 次 `.emit`，代码实际是 reporter 的一个发送点被 5 个状态路径调用；本报告按任务卡统计口径记录为 5，并在迁移证据中说明调用关系。
3. 隧道面板真实验收依赖本机 sshd；当前端口 22 不可用，按要求标为 `[人工]`，没有启动真实 Tauri 或读取真实连接数据。
