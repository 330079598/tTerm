## 结论

**完成（Windows）。** GPUI 终端的会话改由应用级 `SessionManager` 持有，视图只通过 `SessionAttachment` 订阅模型与输出；视图销毁不再关闭会话，重新创建的视图附着到同一模型并保留视图消失期间解析的全部内容。关闭标签会同时释放 core 会话、提示代次、保存的已输入密码和注意力状态；新会话会重置主机密钥提示、连接状态与进度、本地 shell 启动失败原因。macOS 未在本机运行，按[决策 016](../decisions/016-mac-windows-either.md)记为待补；Linux 桌面验证推迟到 Linux 发布前。

### 行为变化

- 视图销毁只丢弃 `SessionAttachment`；`TabBinding` 和 `Arc<Session>` 仍由 `SessionManager` 持有，模型、解析器与 core PTY 继续运行。重新附着使用同一模型，因此视图不可见期间的内容完整保留。
- 输出在解析前检查所属 `session_nonce` 与关闭标志。旧代次的队列批次、冷路径状态行和迟到唤醒都不会写入新模型或触发新视图重绘。
- 关闭标签走 `SessionManager::close_tab` → `AppServices::close_tab`：移除会话、取消该标签所有提示、忘记 `ssh::typed_passwords` 中该标签保存的密码。
- 新代次开始时 `SessionScopedState::begin` 清空主机密钥提示、连接状态/进度与启动失败；旧 nonce 的 setter 返回未更新。
- 进入标签清除 `TabAttentionStore` 中该标签的标记与未读通知；`TerminalView::activate` 聚焦并重新上报网格，`deactivate` 隐藏视图并停止闪烁、输入法预编辑等视图活动。

## 偏差

1. **冷路径输出事件增加 `session_nonce`。** 原 `TerminalEvent::Output` 只有 `tab_id` 与 `text`，无法在重连后拒绝旧状态行。新增内部字段后，GPUI 用事件中的 nonce 过闸；Tauri adapter 仍只序列化 `text`，冻结的 JSON 契约测试保持通过。
2. **关闭标签的清理下沉到 core。** 新增 `AppServices::close_tab` 与 `PromptBroker::cancel_tab`，而不是只在 GPUI 侧调用 `kill_pty` 与 `forget_typed_passwords`。这样两个客户端可以共用同一释放路径，并处理旧 nonce 的提示 owner。
3. **视图激活/离开放入 `terminal-view`。** `activate` 重新上报当前网格，`deactivate` 复用 `set_visible(false)` 的停止闪烁与输入法清理，避免在窗口层重复视图状态逻辑。
4. **原型仍是单标签窗口。** `SessionManager` 已按 `tab_id` 管理多个绑定，但当前窗口固定使用 `gpui-main`；多标签、分屏与标签移动属于 P3，不在本卡实现。
5. **未阅读 Zed 终端源码。** 本卡没有可列出的 Zed 提交或文件；实现依据 `terminal-design.md`、P0-14/P1-12 代码与 core API，没有复制 Zed 的代码、注释、测试或私有标识符。
6. **macOS 未运行。** 本机只有 Windows；按决策 016，同一流程在 macOS 发布前补跑。Linux 桌面项推迟。

## 遗留问题

- macOS 需要重跑 `cargo test -p tterm-gpui --lib` 与真实窗口的本地 shell 流程；本次未运行。
- 连接进度与主机密钥事件本身仍不带 nonce。新会话的 `SessionScopedState` setter 会拒绝旧 nonce，标签路由也按 `tab_id` 过滤；但若旧 SSH 任务在新会话开始后仍发出同标签进度事件，窗口无法仅凭事件区分代次。建议 P2-21 给连接进度事件补代次或由 core 按当前提示 owner 过滤。
- 本卡没有实现 P2-02 背压、P2-03 键盘编码、P2-04 鼠标/选区或 P3 外观；窗口仍是原型形态。
- 没有修改 `docs/gpui-migration/status.md`，没有合并或推送分支；`.pi-sessions/`、`P1-11g-g1.pi.jsonl` 与 `pi-task.prompt.md` 保持未跟踪。
