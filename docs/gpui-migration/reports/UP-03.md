生成器在写入前还会校验 JSON 的结构：某个主题缺一条变量、多出一条不属于任何分组的颜色、两个主题重名、`:root` 不是恰好一个，都会退出码 1 并说出是哪个主题的哪几条变量。临时删掉浅色主题的 `titlebar` 时：

```text
$ node scripts/tokens/generate.mjs --check
tokens: light is missing titlebar
[exit 1]
```

## 偏差

1. **“阴影”没有对应的令牌。** 卡上写“把 `themes.css` 中的颜色、圆角、阴影与 `uiPlatform.ts` 中的字号行高抽成一份 `tokens.json`”，但两个文件里都没有阴影令牌：`themes.css` 只有 HSL 三元组与 `--radius`，`uiPlatform.ts` 只有字号与行高。现有阴影来自 Tailwind 内建的 `shadow-*` 工具类与组件 CSS 里散落的 `box-shadow`（例如 `TerminalOverlays.css`、`islands.css`），它们不是可复用的令牌。2026-11-05 询问后确认：本卡只抽颜色、圆角、字号行高，不发明数值（“不做：改任何颜色或尺寸”）。建议把“阴影”从本卡删去；若确实要令牌化，等 P0-25 核实 GPUI 的 `BoxShadow` 能力后另开卡。

2. **`tterm-ui` 当时不存在，GPUI 的版本也还没固定。** 卡上要求生成“`tterm-ui` 的 Rust 常量”，`ui-parity.md` 第 2 节写的是“生成 `Hsla` 常量”。但 `crates/tterm-ui` 在本卡之前不存在，GPUI 的固定 rev 由 P0-06 的 `pins.md` 决定，README 执行规则 5 禁止在此之前引入 GPUI 来源。经确认，本卡新建 `crates/tterm-ui`，只放与框架无关的常量（`Hsl` 的三个分量、`FontSize` 的 rem 与行高），不依赖 gpui；`Hsl` 到 `Hsla`、rem 到 `Pixels` 的映射留给 P0-24。建议在 P0-24 的卡上注明这一点，或在 `ui-parity.md` 第 2 节把“up-03 生成 Hsla”改成“UP-03 生成 HSL 分量，P0-24 映射为 Hsla”。

3. **卡外新增了防漂移检查。** 只让脚本能写文件不够：有人手改 `themes.css` 之后单一来源就断了。经确认新增 `pnpm check:tokens`（重新生成到内存并与已提交的文件比较），并在 `.github/workflows/check.yml` 的 frontend job 里执行。这条不在卡上，改动是一行 CI 步骤与一个 npm script。

4. **`tokens.json` 的位置。** 卡上没有指定，经确认放在 `src/styles/tokens.json`：前端直接 `import`，Rust 侧用 `include_str!("../../../../src/styles/tokens.json")` 读取，两边的路径都稳定。

5. **`uiPlatform.ts` 改为读取 `tokens.json`。** 卡上说把它的字号行高“抽成 `tokens.json`”，抽走之后函数必须从 JSON 取值，否则同一组数值会有两份。写进 `--text-*` 的字符串与改动前逐字相同（`0.75 * factor` 得到 `0.75rem`，行高仍是 `"1.15"`），新增的测试锁定这一点。这也让 `src/lib/uiPlatform.ts` 不再需要 `--text-*` 的 14 行样板。

## 遗留问题

1. **W0-05 的参考截图尚未生成。** 验收条件里的“W0-05 的参考截图不变”要等 W0-05 首次生成截图后才能核对。本卡的 CSS 与改动前逐字节相同，理论上不会带来差异；W0-05 首次出图时请顺手确认一下。
2. **`Cargo.lock` 有新增。** 新 crate `tterm-ui` 与它的 dev-dependency `serde_json`（解析到锁文件里已有的 1.0.151）写进锁文件；没有升级任何已有依赖。
3. **阴影令牌仍未解决。** 见偏差第 1 条。若 P0-25 证明 GPUI 的多层 `BoxShadow` 能对上 Tailwind 的 `shadow-*`，届时再决定是否令牌化；现有 92 处工具类与组件 CSS 里的 `box-shadow` 不在本卡范围。
4. **`tterm-ui` 还没有 GPUI 依赖。** P0-24 需要把 `Hsl` 映射成 `gpui::Hsla`（透明度由使用处传入，令牌只存不透明分量），并在那时决定 `tterm-ui` 如何依赖 GPUI 的固定 rev。
5. **`themes.css` 是生成文件，但文件里不能写提示。** 为了保持与改动前逐字节相同，生成的文件没有“请勿手改”的头注释；提示只在 `scripts/tokens/generate.mjs` 的文件头、`pnpm check:tokens` 的失败信息与本报告里。手改 `themes.css` 的提交会被 CI 的 `check:tokens` 拒绝。
6. **PTY 测试在这个沙箱里失败。** 见“检查”一节；有真实终端的机器上应当通过。
