## 偏差

1. **不提交探针 crate。** 任务卡的「产出」只列了 `pins.md`、决策 002、重复依赖清单与打补丁步骤，没有列 crate；`tterm-gpui` 是 P0-08 的产出。所以探针程序与合并解析用的 `crates/pins-probe` 都只用临时副本，源码与重建步骤写进文末的[探针程序](#探针程序)，仓库里没有残留。代价是合并后的锁文件没有进仓库：`Cargo.lock` 在本分支一行未变（722 个包），`[workspace.dependencies]` 目前没有使用者。
2. **三平台只验证了 macOS。** 不推送就没有 CI（决策 006 的豁免仍然有效）；本机 `~/.rustup` 在沙箱里只读，无法 `rustup target add` 做交叉检查，所以 Windows 与 Linux 记为未验证。同一豁免下 W0-01 的先例也是这样处理的。
3. **第一次把 GPUI 接进 workspace 会动到现有依赖。** 临时副本的合并解析显示：包数 722 → 1128，新增 421 个，替换掉 15 个现有包（`icu_*` 2.3.0→2.4.0、`toml` 0.8.2→0.8.23、`yoke`/`zerovec`/`tinystr` 的补丁版本等）。这些是 GPUI 的约束逼出来的兼容升级，不是本卡的选择；本卡因此不把 GPUI 接进 workspace，把这次锁文件变化留给 P0-08，并已在决策 002 里要求那一次提交单独复核。
4. **技术选型的三处更正**（`12add5e`）：gpui-kit 0.9.0 在 crates.io 上**有** `license = "Apache-2.0"` 字段；`gpui-pre` 不声明 `rust-version`，工具链下限只能从依赖树推；resolver 的问题本来写着「在 P0-06 决定」，现在填上结论。这三处属于本卡工作项本身（第 1、4 步），不是范围外的改写。
5. **两个 HTTP 客户端。** 技术选型预期「reqwest 可能两个版本共存」，实际是 GPUI 用了一个改名发布的包 `gpui-pre-reqwest 0.12.15`（reqwest 0.12 的快照），与 tTerm 的 `reqwest 0.13.5` 不是同一个包，Cargo 不会报冲突，但二进制里会有两套实现。它们各自服务不同的调用方（tTerm 的同步与更新、GPUI 的资源缓存），本卡不合并，记入遗留问题。
6. **构建需要可写的 `CARGO_HOME`。** 本会话的沙箱不允许写 `~/.cargo`，所以所有 cargo 命令都带 `CARGO_HOME=/tmp/p006/cargo-home`，首次会重新下载约 1,100 个 crate。仓库与 CI 不受影响，这条只影响本机复现命令的写法。
7. **没有更新 `status.md`。** 按 README 第 8 节 U-02，状态表由评估者维护。

## 遗留问题

1. **Windows 与 Linux 的编译未验证。** GPUI 第一次推送时，`check.yml` 的三平台任务必须先跑通；Linux 还要在 CI 与 `tterm-gpui/README.md` 里装上 GPUI 的系统依赖（wayland、x11、fontconfig/freetype、Vulkan 驱动），本卡没有做这一步，属于 P0-08 的工作。
2. **P0-08 要处理的锁文件变化。** 第一次把 GPUI 加入 workspace 会重解析整个树（见「偏差」第 3 条）：需要在同一个提交里复核 15 个被替换的包，确认 Tauri 版仍能构建与运行，并把这次变化写进报告。
3. **两个 HTTP 客户端与体积。** 空程序 release 已有 2.1 MiB；两套 reqwest 与两套平台绑定（`accesskit` 自带的 objc2 0.5、windows 0.58）会继续抬高发行体积。P0-26 做打包时按实际体积复测，G1 的重新估算（P0-22）以本卡的 2.1 MiB 为起点。
4. **MSRV 只在 macOS 上核对过。** 树里最高声明是 `oo7` 的 1.92，它只经 Linux 的 ashpd 门户到达；Linux 上首次完整构建时若发现更高要求，需要同时改 `rust-toolchain.toml` 与 `pins.md`。
5. **同一个 `openpty` 测试在其他卡上还会失败。** 这是本会话沙箱的限制，不是仓库的问题；在能打开 PTY 的环境里应当能通过，但没有人在这台机器以外的环境中复跑过，留给评估者或验证人确认。
6. **pnpm 11 的构建脚本审批。** 干净检出上 `pnpm install` 会因 `esbuild` 的构建脚本未获批准而失败，进而让所有 `pnpm <script>` 失败。这与迁移无关，但会挡住每一位执行者；建议另开一张卡，在仓库里补 `onlyBuiltDependencies`（PNPM 10 起写在 `pnpm-workspace.yaml`）。

## 打补丁退路的实测步骤

```text
1. 取固定版本源码，放在仓库外：
   $ cp -R $CARGO_HOME/registry/src/*/gpui-pre-0.3.11 /tmp/p006/patch/gpui-pre
   $ chmod -R u+w /tmp/p006/patch/gpui-pre

2. 改一行无害代码。这个包的库根是 src/gpui.rs（crate 名 gpui），不是 src/lib.rs：
   $ tail -3 /tmp/p006/patch/gpui-pre/src/gpui.rs
   + /// P0-06 probe marker; the only local change in the patch test.
   + pub const P0_06_PATCH_MARKER: &str = "patched gpui-pre 0.3.11";

3. 在要编译的工程里加一条 patch，版本必须与依赖要求一致（=0.3.11）：
   [patch.crates-io]
   gpui-pre = { path = "/tmp/p006/patch/gpui-pre" }

4. 重新编译并运行：
   $ cargo run
     Compiling gpui-pre-macos v0.3.11
     Compiling gpui-pre-platform v0.3.11
     Compiling gpui-kit v0.9.0
     Compiling pins-probe v0.1.0
      Finished `dev` profile [unoptimized + debuginfo] target(s) in 1m 25s
      Running `target/debug/pins-probe`
   alacritty_terminal: 4 lines x 20 columns, cursor at Point { line: Line(1), column: Column(10) }
   patch marker: patched gpui-pre 0.3.11
   gpui through the facade: gpui::app::Application / gpui::color::Hsla
```

要点：

- `[patch.crates-io]` 替换的是「名字 + 版本」，所有依赖方都会换成这份源码（上面 `gpui-pre-macos` 也从它编译），不需要改 `Cargo.toml` 里的版本号。
- 只 patch 了一个 crate。真要改 `gpui-pre-macos`、`gpui-pre-platform` 这类兄弟 crate，得逐个加进 `[patch.crates-io]`，包装的还是同一份快照源码目录。
- 仓库里没有留下补丁：`git status` 干净，`Cargo.lock` 未变。以后真的要用时，按决策 002 与 `pins.md` 的「打补丁记录」一条补记原因与对应的 P0-07 条目。

## 探针程序

没有提交，需要时按下面的内容重建（`/tmp/p006/probe`，`CARGO_HOME` 指向可写目录）：

`Cargo.toml`：

```toml
[package]
name = "pins-probe"
version = "0.1.0"
edition = "2024"

[dependencies]
gpui-kit = "=0.9.0"
alacritty_terminal = "=0.26.0"
```

`src/main.rs`：

```rust
//! Throwaway probe for P0-06: proves that the pinned `gpui-kit` facade and
//! `alacritty_terminal` resolve together, and that the interfaces the later
//! cards need are reachable through `gpui_kit` alone.

use gpui_kit::*;

use alacritty_terminal::event::{Event, EventListener};
use alacritty_terminal::grid::Dimensions as _;
use alacritty_terminal::term::{Config as TermConfig, Term};
use alacritty_terminal::vte::ansi::{Processor, StdSyncHandler};

struct GridSize {
    lines: usize,
    columns: usize,
}

impl alacritty_terminal::grid::Dimensions for GridSize {
    fn columns(&self) -> usize {
        self.columns
    }

    fn screen_lines(&self) -> usize {
        self.lines
    }

    fn total_lines(&self) -> usize {
        self.lines
    }
}

struct Listener;

impl EventListener for Listener {
    fn send_event(&self, _event: Event) {}
}

struct Probe;

impl Render for Probe {
    fn render(&mut self, _window: &mut Window, _cx: &mut Context<Self>) -> impl IntoElement {
        div().px(px(8.0)).child(SharedString::from("P0-06"))
    }
}

actions!(pins_probe, [Quit]);

// Never called: opening a window needs a display, and P0-08 owns the first
// real program.
#[allow(dead_code)]
fn open_probe_window() {
    gpui_kit::application().run(|cx: &mut App| {
        gpui_kit::init(cx);
        let opened: Result<(AnyWindowHandle, Entity<Probe>)> =
            gpui_kit::open_window(WindowOptions::default(), cx, |_, cx| cx.new(|_| Probe));
        opened.expect("window");
    });
    let _ = std::any::type_name::<WindowTextSystem>();
    let _ = std::any::type_name::<ClipboardItem>();
    let _ = KeyBinding::new("cmd-q", Quit, None);
}

fn platform_entry_points() {
    let _: fn() -> Application = gpui_kit::platform::application;
    let _: fn() -> BackgroundExecutor = gpui_kit::platform::background_executor;
    let _ = gpui_kit::platform::current_platform(false);
    let _: fn() -> gpui_kit::Result<()> = || Ok(());
    let _ = std::any::type_name::<std::rc::Rc<dyn Platform>>();
}

fn main() {
    platform_entry_points();

    let size = GridSize {
        lines: 4,
        columns: 20,
    };
    let mut term: Term<Listener> = Term::new(TermConfig::default(), &size, Listener);
    let mut processor = Processor::<StdSyncHandler>::new();
    processor.advance(&mut term, b"hello\r\nP0-06 pins");
    let grid = term.grid();
    println!(
        "alacritty_terminal: {} lines x {} columns, cursor at {:?}",
        grid.screen_lines(),
        grid.columns(),
        grid.cursor.point,
    );
    println!(
        "gpui through the facade: {} / {}",
        std::any::type_name::<Application>(),
        std::any::type_name::<Hsla>(),
    );
}
```

合并解析用的临时成员只是把它放进仓库副本的 `crates/pins-probe`，并在 `Cargo.toml` 里写 `gpui-kit.workspace = true`、`alacritty_terminal.workspace = true`。
