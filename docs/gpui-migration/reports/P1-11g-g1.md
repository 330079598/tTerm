## 偏差

1. **提交拆分从计划的 9 个收敛为 4 个代码提交 + 报告。** 每个提交单独 `cargo check -p tterm-core --all-targets` 通过；收拢的原因是 g1 各模块共享 `lib.rs` 与 `config/mod.rs` 的模块声明，逐模块提交会把同一声明反复改。
2. **`settingsSearch` 的 NFKC 没有实现。** 计划 11.1 需要 `unicode-normalization`，它不在 `pins.md`，派工没有确认新依赖，所以本分支只做 `toLowerCase + trim`。后果：全角输入（`ｆｏｎｔ`）搜不到 `Font Size`；现有 7 个搜索用例不覆盖全角，全部通过。这是待确认项。
3. **`settingsSearchIndex.ts` 没有搬。** 计划 11.2 建议留给 GPUI 设置页（P4）；本次 7 个搜索用例用 `en.json`/`zh.json` 中的英文字符串构造条目，索引数据与 2 个索引校验用例留在设置页。`buildSettingsSearchItems` 未移植（它依赖索引与 `SETTINGS_TABS`），`searchSettings` 接收已翻译条目。
4. **`sftpView` 的排序不是 `Intl.Collator`。** 用「ASCII 大小写折叠 + 数字段按数值」等价纯 ASCII 名字（`file9` < `file10`，`File2`/`file2` 相等）；`localeCompare` 用在扩展名、权限、owner/group 上，用「ASCII 折叠 + 原串兜底」。非 ASCII 名字（`Ärger`、`档案`）按码位而非 ICU 次序，可能与 Tauri 版不同；计划 11.3 是同一取舍，需要确认。
5. **`sftpView` 的存储用例改了输入方式。** `loadSftpViewPreferences`/`save*` 的 `Storage` 留在 WebView；Rust 的 `normalize_sftp_view_preferences(Option<&str>)` 只做 JSON 校验与默认值，测试直接传存储文本（`not json`、bogus 列等），与 TS 用例逐条对应。
6. **`serialSendStore` 与 `profileRecents`/`recentCommands` 只搬纯部分。** `localStorage` 的读、写、异常吞掉留在 WebView；Rust 提供 `serial_send_key`、`parse_serial_send_echo`、`save_serial_send_echo`（50 条上限）与 `parse_recent_*`。`lastUsedAt`/`lastUsed` 用 `i64`（计划 5.3 的建议），因此 `1.5` 这类非整数时间戳会被 `parse_*` 丢掉；TS 的 `typeof number` 会保留，实际写入的都是 `Date.now()` 整数。
7. **`composerRuns` 没有单独模块。** 它的纯转换就是 `composer::run` 的状态迁移：`start/finish/promptReached/retry/continue/stop/isRunActive`。每 tab 的 `Map`、`onPrompt` 订阅、`useSyncExternalStore` 与两个 localStorage 标志按计划 2.4 留 WebView，4 个 TS 用例也留在前端。`composerRun.runLines` 仍依赖 P1-11c 的 `splitShellCommands`，未移植（1 个用例）。
8. **`updater` 使用 `trait UpdateBackend` 整块搬状态机。** `invoke`、`Channel`、`getVersion`、`relaunch`、`setTimeout` 由客户端实现；`startBackgroundUpdateChecks` 的定时器留在适配层，纯调度函数 `next_check_delay` 进 core，并加了 1 个测试（计划没有对应 TS 用例）。12 个 TS 用例全部覆盖；`it.each` 的两个 case 放在一个测试的循环里。`update_state.rs` 超过 800 行，按 AGENTS 的模块规则拆成 `mod.rs`（类型、状态、check）与 `transfer.rs`（download/install/retry），测试在 `tests.rs`。
9. **`terminalCd` 的 `CdRefusal` 类型没有搬。** 它是「为什么没发 cd」的 UI 原因（busy/elsewhere），没有测试也没有纯逻辑；只搬了 `cd_command`（计划里也放在 `dropped_paths`）。
10. **`profileLastUsed` 搬了但没有 TS 用例。** 它是 `profileRecents.ts` 的导出函数，一行 Map 构造；没有单独测试，按“对应 TS 用例”的要求不影响计数。
11. **`sftpHistory` 的 index 用 `i32`。** TS 用 `-1` 表示“还没列目录”，`usize` 表达不了；`EMPTY_SFTP_HISTORY` 保留 -1，其余函数的行为与 TS 一致。
