# P1-10 WebView 本地存储迁入后端

## 结论

完成。WebView 里属于用户数据的 9 个 localStorage 键已经改由 `app_meta` 保存，启动时一次性迁移，原值保留；备份和同步前恢复备份里的前端状态改由后端读取同一个存储。备份格式没有变化，旧备份可以导入。

这项改动必须随一个正式的 Tauri 版本发给用户，并在用户机器上至少成功运行一次；GPUI 版读不到 WebView 的 localStorage。按 P5-03 的两级升级，建议用 0.9.0 作为过渡版、保留原值到 0.10.0，并在切到 GPUI 版之前留出足够的升级时间，不能假设用户会立即升级。若用户跳过过渡版，GPUI 版只能按 P5-03 的约定提示恢复默认或先安装过渡版。

## 偏差

1. 任务卡把“串口发送历史与回显设置”都列为用户数据。实际串口发送历史已经在 `serial_sends` 表里（由现有 `record_serial_send` 写入），localStorage 只保存“哪些连接隐藏回显”的 per-device 设置；本次只迁移了这个设置，历史表未改。
2. 任务卡要求备份格式保持不变。因此新增到后端的 `serialSendEcho`、`commandComposerOpen`、`commandComposerLineByLine`、`replayView` 没有加入 `BackupFrontendState`；备份仍只有原来的 5 个字段。这 4 项在备份/恢复后不会跨设备恢复，报告在“遗留问题”中列出。
3. WebDAV 同步实际不把前端状态作为同步集合传输；`run_sync` 只用它创建同步前的恢复备份。本次把恢复备份的读取改到后端，没有改同步文档格式或同步集合。
4. 为遵守“现有 command 名与参数不改，只新增”，`export_backup` 的 `options.frontendState`、`run_due_automatic_backup` / `run_webdav_backup` / `run_sync` 的 `frontendState` 参数仍保留，但后端不再读取，前端也不再发送。这样旧调用方仍能调用新后端。
5. 过渡版版本号按 0.9.0、删除 localStorage 原值按 0.10.0 记录，这是建议计划，不是任务卡给定的版本号；发布前需要按 P5-03 的更新器安排确认。
6. `custom-themes` 是已有迁移：它在导入数据库后删除 localStorage 原值，与本卡“保留一个版本”的规则不同；本卡没有改它，以免改变既有行为。

## 遗留问题

1. 前端写入是异步的：缓存先更新，数据库写入在后台串行执行。如果用户写完立刻强制退出，最后一次写入可能来不及落盘；目前没有在退出流程里等待写队列。需要时可另开卡增加“退出前 flush”。
2. 4 个新迁移的用户数据（串口回显、命令编写器两项、日志回放）没有备份字段，无法随备份或同步跨设备恢复。出于“备份格式不变”的硬性要求，本卡没有扩展格式；建议后续单独开卡设计兼容的扩展。
3. `[人工]` 升级/回退验证未执行，因此没有真实设备上的录屏和数据对照。
4. 过渡版必须让用户运行一次，且要留出升级时间；这部分发布与更新器工作属于 P5-03，不在本卡范围。
