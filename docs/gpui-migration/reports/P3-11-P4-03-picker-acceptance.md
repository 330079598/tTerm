# 本地 Shell 与 SSH 导入：执行计划与验收（2026-11-26）

基点 `GPUI@4597ff94`。本批只补从系统选择路径的操作和新标签菜单的本地 Shell 回归，不重写 Shell 发现、WSL 枚举或 SSH 配置解析。`82b8ee12` 已接入检测列表、默认项、隐藏、复制、移动、删除与路径检查；[本地 Shell 首批](P3-11-P4-17-local-shells.md)是此前的快照，不是当前缺口清单。

## 执行顺序

1. 并行对照 React 的 Shell 程序选择器、SSH 导入来源选择器、启动器菜单。分别修改相应视图与测试，不改变共享数据格式、启动策略或解析服务。
2. 协调者复核：用测试窗口驱动入口并控制系统选择器的返回值；用隔离配置、真实服务验证保存/导入。审查取消、失效回调和写入时机。不把模拟选择文件记作操作过系统窗口。
3. 在集成后的工作树运行 AGENTS.md 的前端六项、格式、工作区严格 Clippy 和默认并发测试。它们结束后才单独测 release 前台帧与后台吞吐。记录实际结果；不调整预算。
4. 桌面复测使用全新编号的调试实例。SSH 默认预览会查找用户主目录下的 `.ssh/config`：必须另用隔离的系统账户或确认进程使用合成的测试主目录，仅隔离应用数据库不够。不在个人连接库上验收。

## 桌面验收步骤

| 操作 | 通过条件 |
| --- | --- |
| 本地 Shell → 新增或编辑 → 选择本机已知的测试 Shell 程序 | 路径回到当前草稿；选择并不保存或启动。取消整个编辑后原配置不变。再次选择并显式保存，从 `+` 启动时保留名称和参数，原标签仍可输入。 |
| 在 Shell 或导入来源已有路径时打开系统窗口并取消 | 输入不清空、原选择不改变，不创建标签或连接。关闭再打开编辑器/导入框后，旧窗口返回不能修改新对话框。 |
| 在 SSH 导入中分别选择合成 `config` 文件和包含它的目录 | 预览对应来源；Include 警告有源文件和行号。仅勾选一台主机导入指定分组；重开列表只增加所选主机，不尝试连接。 |
| 再次导入同一配置，分别关闭/打开覆盖和转发 | 计数、库中主机和转发字段符合[原验收表](P4-03-ssh-config-import.md)，取消不写库。用两套独立测试库比对，不比较生成的 ID。 |

## 本轮结果（Windows x64，未提交工作树）

- **自动验收通过。** Shell 选择只改草稿，保存前不写盘；取消和旧编辑器回调不覆盖新草稿。SSH 原生入口区分单文件与单目录，选中后预览，取消保留选择，关窗后迟到的结果不覆盖新对话框。窗口测试控制系统对话框的返回，不把它算作鼠标操作了系统窗口。导入与落盘沿用两端隔离库的同一份合成配置。
- **启动器对照。** `+` 菜单首项标记当前默认 Shell；配置项不在检测列表时仍使用配置的默认程序，而不是 Auto。合成 WSL 条目覆盖排序、隐藏和取消，不启动或登录实际发行版。另外修复连接面板操作区在按钮较多时越过对话框边缘的问题，原先失败的连接面板用例保留，10 项定向复验通过。
- **桌面部分通过。** 在独立编号的 Windows 实例中看到程序的“浏览”按钮，输入合成路径后显示程序名提示及路径缺失提醒；取消编辑未写配置，显式保存仅写入该测试条目。未打开系统选择窗口：进程级 HOME 不能隔离 Windows 快速访问和最近文件。三种系统窗口的点选/取消、macOS 对照和整页视觉仍待专用测试账户复核。GPUI 的程序选择器不像 React 的 Windows 版那样按 exe/bat/cmd 筛选，此差异未豁免。
- **仓库检查。** 六项 pnpm 检查通过（Vitest 188 个文件、1368 个测试）；`cargo fmt --all --check`、工作区全目标严格 Clippy、默认并发 `cargo test --workspace` 通过（3399 个通过，41 个按仓库定义忽略）。独立运行 `node scripts/perf/gpui-release-frame-budget.mjs`：前台加载 p95 **0.2429 ms**，采样期间 30/30 个会话推进；独立的 30 MiB 全部应用并确认用时 **138.959 ms（215.89 MiB/s）**。日志在本机 `target/migration-picker-final.log`、`target/migration-picker-final-frontend.log`、`target/migration-picker-release.log`。不是 macOS CI、桌面验收或 G2 通过的证据。
