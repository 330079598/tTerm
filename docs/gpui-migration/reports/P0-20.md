### 工作项逐项结论

以下均来自上述命令；测试名可在同目录 `tests.rs` 找到。满足仅指所列验证范围，没有把无界面协议或布局当成真实输入法/GPU 结果。

| --- | --- | --- |
| 撤销与重做 | 满足 | `undo_redo_and_search_replace`：派发组件 Undo/Redo 动作，断言 `alpha 中文 alpha` → `beta 中文 beta` → 原文 → 修改文；真实窗口快捷键焦点另需人工复核。 |

| Markdown 语法高亮 | 不满足 | 同测试：`language=markdown highlight_spans=0`。候选 tree-sitter-markdown；内嵌代码另验。 |

| 编码与换行格式的保留 | 部分满足 | `local_encoding_newlines_and_conflicts`：UTF-8、UTF-8 BOM、UTF-16 LE/BE BOM × LF/CRLF/CR 共 12 组合，真实本地临时文件读写、逐字节往返及修改后格式断言；`editor_normalized_text_preserves_file_format` 验证编辑器文本与 UTF-8 BOM/CRLF 的桥接。拒绝未知编码、非法 UTF-16、混合换行，替代为外部编辑器；未实现生产编码探测。 |

## 偏差

1. 任务卡与当前编辑器代码路径一致，未出现需要改卡或扩展生产实现的冲突。README A1 所述根 workspace 规则已遵守。
2. 卡未要求新增编辑器依赖，补充要求只用 gpui-kit 0.9.0 自带组件。本轮把当前默认组合的高亮缺失作为“不满足”结论，提出后续审批内置语言特性；没有为了满足高亮而增加依赖，故无需中途依赖决策。
3. P0-08 报告中的 `app.rs` 已由后续卡替换成终端原型，本卡遵守补充要求使用独立 example，没有改动主程序。P0-23 的控制接口绑定并校验终端 `Prototype`，不能直接控制本独立 example。本轮没有驱动原型窗口，也没有发送系统级输入。真实窗口截图、GPU 滚动和 IME 因此明确未验证；测试上下文证据不能替代它们。
4. 50 MiB 初次打开折行测试时，按每行高度换算的偏移落到文件第 5120 行而非第 25600 行，因为长行被折成多显示行。最终示例明确关闭折行，再断言实际文件行可见；未把初次结果称为组件缺陷，也未声称已完成折行性能验证。

## 遗留问题

1. `[人工]` Windows 微软拼音、微信输入法真实输入与候选框定位；缺真人操作，协议模拟不替代。步骤见示例 README。
2. 未验证 Windows 真实窗口 GPU 滚动、峰值内存、快捷键焦点与截图，以及极长单行/大量短行/折行的大文件负载。当前 P0-23 入口仅支持终端；若要求 agent 自动化此示例，需另行评估接口复用方式，避免扩展本卡到主程序。
3. macOS、Linux 原生窗口、IME、布局和编译均未在本轮运行；缺本会话可用的对应平台运行环境。Linux 桌面/输入法矩阵在 environments.md 标缺失。
4. 七语言高亮默认全部不满足；决策 010 仍为“提议”。后续应审批固定的内置语言特性传递依赖并验证七语言及现有扩展名别名/嵌入语言。未得到该批准前保持纯文本或外部编辑器建议，不默认引入新 crate。
5. 保存实验不是生产 SFTP：未知编码/混合换行、原子替换、权限保留、远程 compare-and-write 竞态尚未解决。保留错误并转外部编辑器；后续卡评估生产集成。
6. ui-parity 第 3 节允许编辑器交互差异，主题色、字号、行号栏仍需后续正式界面对齐。本轮没有视觉一致性截图或新增例外；P0-25 的绘制限制未被当成已解决。
