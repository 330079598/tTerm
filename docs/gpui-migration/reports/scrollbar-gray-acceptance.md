# 滚动条低存在感验收方案

- 日期：2026-11-27
- 范围：GPUI 终端及其滚动区域的滚动条视觉，不修改 Tauri 行为
- 关联：P2-06、P4-16；串口/日志回放后置决定见 [021](../decisions/021-defer-nonblocking-terminal-features.md)

## 目标

滚动条应像 Tauri 版一样保持低存在感：轨道透明或接近透明，滑块为固定的中性灰并带透明度；不因主题强调色、成功/失败状态、命令标记或 hover/active 状态变成抢眼颜色。滚动条仍必须可见、可拖动，并且不改变终端文本区域的布局。

## 实现约束

1. 只调整 GPUI 滚动条的绘制/颜色来源；不删除滚动能力，不修改滚动位置、回滚模型或命令标记数据。
2. 终端存在回滚内容时显示滚动条；没有可滚动内容时不新增可见滚动条。
3. 轨道使用透明背景，滑块使用固定灰色和低 alpha；hover、按下和非活动标签不切换到主题 accent、success 或 error 色。
4. 颜色常量或主题映射必须有单元测试/快照覆盖，避免以后主题改动重新引入高饱和颜色。

## 验收步骤

### 自动验收

- 运行滚动条相关的定向测试，确认有回滚内容时滚动条节点/绘制存在、无回滚时隐藏、拖动仍更新滚动偏移。
- 检查颜色断言：轨道 alpha 为 0 或接近透明；滑块为中性灰、alpha 小于 1；hover/active 与普通状态颜色相同或只提高可读性，不使用主题强调色。
- 运行 `cargo fmt --all --check` 和受影响 crate 的严格 Clippy/测试。

### 人工/截图验收

在深色和浅色主题各打开大量回滚内容，与 Tauri 参照并排观察：

1. 滚动条始终可发现但不吸引注意力；终端文字、选区和命令标记仍是视觉主体。
2. 鼠标悬停、按住拖动、切换活动/后台标签时颜色不跳成高亮色。
3. 向上滚动、拖到顶部/底部、回到实时输出后位置和会话内容正确。
4. 没有回滚内容的全新会话不出现多余滚动条。

记录平台、主题、窗口缩放、截图路径和实际颜色/alpha；截图只作为视觉证据，行为仍以自动测试为准。

## 本轮结果（2026-11-27，Pi agent 实现，协调者复验）

- `crates/tterm-terminal-view/src/view/frame.rs` 不再从终端 ANSI palette 的 cursor/bright-black 取色，改用滚动条模块提供的固定中性灰轨道和滑块；概览标记仍绘制在滑块下方，未改变成功/失败标记颜色。
- `SCROLLBAR_TRACK` 为 `#808080` alpha 46，`SCROLLBAR_THUMB` 为 `#808080` alpha 150；两者均透明，滑块不随主题强调色、光标色或 hover 状态变化。
- 自动测试：`view::scrollbar::tests` **5/5 通过**；`overview_layout_is_painted_in_the_track_under_the_thumb` **1/1 通过**。
- 质量检查：`cargo fmt --all --check` 通过；`cargo clippy -p tterm-terminal-view --all-targets -- -D warnings` 通过。
- 本轮未做物理桌面截图；因此深/浅主题的像素级视觉对照仍标记为待补，不把自动绘制测试当作整卡视觉签收。

**协调者结论：实现与定向行为验收通过；滚动条颜色小卡可通过，完整桌面视觉验收待后续专用窗口复核。**
