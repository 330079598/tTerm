## 偏差

1. **任务卡没有固定 Zed 提交。** 设计说明以官方仓库 `4ba7d82f6872cb5ee8adc122529e49ba28057c3a`（2026-11-05）为阅读快照。它比 `gpui-pre 0.3.11` 的 2026-11-02 快照晚三天；说明只依赖长期稳定的公开接口，没有依赖这三天内新增的 Zed/GPUI 能力。若评估要求与 `gpui-pre` 完全同提交，需要重新核对一遍，但不预期改变结论。
2. **`pnpm format:check` 不覆盖 `docs/`。** 与 W0-02 相同，命令本身通过，但不能证明新文档符合 Prettier；本卡补跑了直接检查。建议后续新增 docs 格式脚本，或在任务卡中明确“新文档用 `pnpm exec prettier --check <文件>` 验证”。
3. **说明包含 tTerm 特有的决定。** 除了描述 Zed 的架构，设计说明还写了 core/会话边界、现有 Tauri 版的输入法光标守卫、鼠标上报保护、回滚锚定候选方案等。这是为了让 P0-09、P0-10、P0-12、P0-13 能直接执行，并满足“为什么这样设计”的验收；没有复制 Zed 代码或私有标识符。
4. **代码检查在基线而非 worktree 运行。** 原因见“检查”一节；改动范围证明分支没有代码差异。这个证据方式要在评估时说明，不能把基线的通过当作分支上独立复跑的结果。

## 遗留问题

1. **回滚写满后的锚定仍是开放问题。** 说明只列出视口内容比对、行身份、上游补丁三类方向；P0-12 必须选定方案并写决策记录，不能用“与 Zed 一致”代替目标行为。
2. **Windows 输入法候选框时序未验证。** 需要 P0-18 与 P2-11 在真实 Windows 机器上测组合开始前的候选框位置；必要时按决策 007 第 4 条给 `gpui-pre` 打补丁，不 fork 整个 Zed。
3. **搜索大回滚区的锁竞争未测量。** P2-07 要用 10 万行数据给出耗时与锁等待；如果后台搜索让解析饥饿，需要改成更细粒度的增量扫描。
4. **多视图共享同一会话未定。** 当前按“一模型一可见视图”设计；P3 分屏若要同时显示同一会话，需要决定滚动位置与选区如何共享。
5. **动态回滚容量语义未定。** Alacritty 的 `set_options` 可以调整历史容量，缩容会丢弃最旧历史；P2-06 要定义修改设置后的内存释放与用户提示。
6. **空闲光标闪烁的验收口径。** 建议 P0-10 与 P2-25 把“空闲无闪烁”和“空闲有闪烁”分开记录，后者按动画帧计，避免“空闲不重绘”被误读为禁止光标动画。
7. **净室审查仍需评估者逐节复核。** 执行者已做标识符与代码围栏自检，但不能替代评估者对“是否只描述事实、是否含逐行翻译”的判断；如发现任何 Zed 私有标识符或过细实现描述，需在同一分支修正。
8. **设计说明没有性能数据。** 模型快照、行级缓存、搜索与输入法的收益要由 P0-10、P0-21、P2-07、P2-25 的测量证明；本卡只给设计约束，不宣称已达到帧率或内存目标。
