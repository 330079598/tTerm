以上 payload 保留现有 serde 属性、字段类型、tag 与 skip 规则；新事件及组成类型补齐 `Debug/Clone/PartialEq` 以满足现有 AppEvent。派生不是纯移动的一部分，必须放修改提交。LogErrorPayload 以显式字段替代 json!，针对 L1–L4 分别保留 null/缺省语义。移动 TerminalLogStatus 等私有字段时仅按构造点需要开放字段，禁止整片模块 pub，也不加 pub use。

每个领域事件实现 `pub fn name(&self) -> EventName` 与 `pub fn target(&self) -> EventTarget`，总枚举只委派。这是 P1-02 现有方式：core 的 `name()` 是唯一 wire 名声明，业务发送者和 GPUI 不拼接、不订阅这些字符串；Tauri 适配层消费名字、选择实际 Tauri 目标并生成 JSON。这里不另起一套与 P1-02 冲突的命名 API。动态名字仍用 `TabScoped`，三个 transfer 变体分别固定 prefix 为 `zmodem-transfer-start`、`zmodem-transfer-progress`、`zmodem-transfer-complete`，SerialEvent 也保留这些 prefix。

```rust
// src-tauri/src/event_sink.rs，既有签名保持。
impl TauriEventSink {
    pub(crate) fn new(app: AppHandle) -> Self;
    pub(crate) fn wire(
        event: &AppEvent,
    ) -> Result<(EventName, EventTarget, serde_json::Value), String>;
}
// wire 的每一分支都返回 event.name()、event.target() 和旧 payload 的 JSON；
// 空 payload 用 to_value(())，不 serialize AppEvent 自身（不能出现枚举外壳）。
```

适配器按领域拆为 `src-tauri/src/event_sink/{ssh,background,zmodem,session_log,terminal,notification,serial,launch_dir}.rs` 中的纯 payload 映射函数，`wire` 汇合 `(event.name(), event.target(), payload)`；测试放同目录 `tests.rs` 与领域测试文件。目标只能来自 `event.target()`，不能在 wire 内重复决定 Default/Any。`src-tauri/src/event_sink.rs` 保持传输入口，避免随着四卡扩张成巨文件。

发送者内部需要保存依赖时注入 `Arc<dyn EventSink>`，可用临时领域 helper 缩小改动范围：例如 `emit_connection_progress(events: &dyn EventSink, ...)`、`spawn_cwd_watcher(events: Arc<dyn EventSink>, ...)`、`ZmodemReceiveDriver` 与发送线程捕获 sink；仅有平台入口的 notification/launch_dir/tray 可在边界创建 `TauriEventSink`，调用不含 Tauri 的发送 helper。不为每条输出热路径重新构造 sink；也不在本卡给 `ChannelContext` 加字段，避免与 P1-06 抢结构体。需要 app 作日志、窗口、State 用途的函数保留 app，sink 只替换末端发送。新增参数若超过 7 则用领域 context，不加 allow。

### 退出、关闭与保存的现有顺序及防护

现有接线：`lib.rs:139–142` 接 CloseRequested 并 prevent_close；`434–439` 仅对 `ExitRequested {code:None}` 执行拦截，有退出码的 `app.exit(0)` 不重复询问；`441–449` RunEvent::Exit 依次 save window → forget startup marker → save tunnel traffic → session_log::shutdown → external SFTP shutdown。

1. 关闭按钮：Tray 直接 hide/minimize；Ask 首次把 `prompt_open` swap(true) 再发 `close-requested`，成功即等待 `resolve_close_request`；失败清标记并走 quit_unless_held。再次关闭绕过 Ask。resolve 先清标记；cancel 无动作、tray 后台、quit 进 request_quit。
2. request_quit 在有 blockers 时先 show 主窗口，随后 `hold_exit_for_confirmation`。它取得 tunnel 数和未上传文件，检查 confirmed，首次置 prompt_open 再发 `quit-requested` 并返回 true（即使 emit 失败）；再次退出表示用户坚持，绕过等待。取消清 prompt_open，确认先置 confirmed 再调用 quit。
3. Cmd+Q 等无 code 退出先执行 hold；`hold || quit_after_save` 短路，hold 时不会发 `app-will-quit`。无 hold 才进入保存；close/tray 菜单路径经 quit 也用同一个 quit_after_save。
4. quit_after_save 先读 save_before_quit；为真才 `quitting.swap(true, SeqCst)`。不需保存或已在等时返回 false；需要保存则同步发 `app-will-quit`，发送失败返回 false 并由调用者立即退出/放行。发成功**之后**才 spawn 等待任务；`ready_to_quit` 用 `Notify::notify_one` 储存提前到达的 permit；收到保存回复或 1500 ms 到期后 app.exit(0)。第二次退出不会再等。
5. 前端 `savedTerminalContent.ts` 的 answerQuit 先串行 saveTerminalContent，finally 调 ready_to_quit；现有恢复/快照格式和 generation 防迟到逻辑全部保留。

本卡只替换第 4 步的同步 emit，不引入中间通道、不 await、不提前置状态或创建等待、不吞掉 sink 的 Err。P1-05 只拥有 B1/B2 及 broker/确认状态，必须保留上面流程；建议 P1-03 background 提交先合，P1-05 基于它修改，若反序则逐 hunk 复核并联合复跑。

T4 的时间断言以等待任务进入 timeout 后的虚拟时钟为起点，不能以 GUI 调用墙钟计时；已确认 `src-tauri/Cargo.toml:115` 的 dev-dependency 启用了 `tokio/test-util`，不必加依赖。T4 在旧实现先建立 trace（confirm/emit/spawn/save/exit hook 为最小可测试 seam），测试“无保存/无 blockers”“hold 不发 will_quit”“确认后发”“取消后不退出且可再询问”“二次 close/quit”“发送失败”“回复早于 notified”“回复后退出”“到 1499 ms 不退出/1500 ms 退出”，并保留现有 should_hold/should_wait/should_ask 测试。测试 hook 只替代窗口/退出副作用，不另写一份状态机当被测对象。静态 review 确认 SeqCst、Notify::notify_one、短路、spawn 与 lib.rs shutdown 顺序没有变化；用隔离 UI 做一次完整保存再启动读取验证。不得因通知乱序测试难写而把故障语义改成“更合理”的行为。

### 其他风险与防法

- **锁与重入**：log manager/status、launch dirs、zmodem map/armed map/tap 的 guard 作用域逐行对照，不把 sink 调用移入原先已释放的锁；记录 sink 可在 emit 时重入只读查询，以捕获死锁。保持已有在锁内发送的路径，不借本卡顺手重排锁；发现必须变更则另列问题。
- **取消与 nonce**：事件线上现在未含 nonce 的不得新增；map 更新、迟到线程清理仍检查 session_nonce。传输 ID、armed/running 取消、abort sequence、PortClaim Drop 与 stop_rx 取消不改；测试旧 tab 同 ID 新 nonce 时旧任务不能清新登记。本卡不改变 PromptBroker 超时或 SessionSink 的取消。
- **二进制分流/节流**：只换回调参数和接线，保留 ZMODEM 检测先于终端送出、send pipe 与 passthrough 的顺序；120 ms 进度间隔、最后完成进度、日志记录和约 1 MiB ack 逻辑不动。跨卡共同文件 `zmodem/session.rs`、`ssh/client.rs`、`terminal/reader.rs` 由 P1-06 等本卡接线合并后再改，不能覆盖闭包或 ChannelContext 构造。
- **错误与缺字段**：fire-and-forget 仍忽略 Err；S10/N1/A1 仍 eprintln；B3 的 Err 必须传回退出分支。LogError.phase 缺省与 tabId:null、start.sizeUnknown 的缺省、SSH Option 跳过和 tagged shellIntegration 做完整 JSON 对比，不能改成空串或统一 null。
- **跨平台与所有权**：sink Send+Sync，线程使用 Arc，不改 tokio/OS 线程分工；cwd watcher Windows 原本不产生目录就保持；notification 原平台 cfg 不挪到 core；连接进度 f64 不能随意派生 Eq。旧 payload 新增 Clone/Debug/PartialEq 只为枚举/测试，不改变 serde。
- **文件大小**：本次读取 ssh/types.rs 622、shell_integration.rs 357、session_log.rs 451、zmodem/session.rs 603、background/tray.rs 494、lib.rs 461、event_sink.rs 112 行，均未超 800；基线 JSON 为 `{}`。实施前重查，若合并后超限先独立拆分，不能加基线/allow/expect。测试独立文件，适配器按领域拆。
