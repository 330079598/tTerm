# P0-29 nyaterm 模块挑选与质量关卡

## 结论

完成：固定 nyaterm `v2.0.2`（提交 `1453f6cefe5bfccd2dcb119514221b8af682588c`）并完成三个候选模块的质量关卡。关键词高亮不采用；sixel 与 kitty graphics 按任务卡明确范围不采用、不实现、不复制。没有文件复制进本分支，也没有使用 `migrate/spike`。结论是不采用任何 nyaterm 模块，后续关键词高亮由 tTerm 现有纯逻辑继续演进，图片协议是否加入另行决策。

- 固定版本：`v2.0.2`，提交 `1453f6cefe5bfccd2dcb119514221b8af682588c`，克隆路径 `C:\Users\stone\AppData\Local\Temp\tterm-p0-29-nyaterm`。该目录在 worktree 外，不属于本仓库。

- 本卡没有复制代码，因此没有新增 `third-party.md` 登记；固定版本仓库只有 Apache-2.0 `LICENSE`，没有 `NOTICE`。

### 质量关卡逐模块结果

#### 关键词高亮：不采用

- 规模：`keywords.rs` 为 2,687 行，超过仓库 `.rs` 800 行限制 1,887 行；它还把 49 个单元测试以内联测试形式放在同一文件中。
- 依赖：`aho-corasick`、`regex`、`nyaterm-core`、`nyaterm-terminal`、`nyaterm-ui`，以及 GPUI-facing 的 `element`、`semantic`、`types` 模块。它不是可从 nyaterm 独立摘取的纯高亮算法文件。
- 滚动计数：没有发现 `scroll_counter` 或 nyaterm Alacritty 滚动计数 API 的引用；但模块把 `display_offset`、`scrollback_len`、行 revision 和快照行身份纳入缓存键，仍然耦合 nyaterm 的快照模型。按决策 007，不能把这一整套缓存当作独立模块带入。
- 质量：上游文件的生产区没有随机输入抗崩溃测试；命中的 `unwrap`/`expect`/`panic!` 主要在内联测试和测试断言中，但生产模块本身仍需拆分并重写依赖边界后才能符合 tTerm 的错误约定。
- 拆分估算：至少拆成配置/规则编译、文本匹配、跨 wrapped 行范围、快照缓存、语义提示、GPUI 适配和测试七个文件；同时要把 `TerminalSnapshot`/`ThemePalette`/nyaterm semantic API 换成 tTerm 接口。预计为一项独立的 P1-11b 设计与实现工作，不满足“原样复制后暂放 spike”的条件。
- 对照结论：tTerm 已有 `src/lib/keywordHighlight/`，其规则配置、字面量/正则匹配、跨行 cell 分段和测试均在大小限制内。采用 nyaterm 文件会重复实现并扩大依赖面，因此不采用。

#### Sixel：不采用

- 任务卡明确图片协议“只给出结论，不实现，也不复制”；当前 Tauri 版本没有 Sixel 对齐目标。
- 独立审查：`sixel.rs` 为 447 行，使用 4096×4096、8 MiB cursor extent、4 MiB raster 上限；内置 4 个测试通过。
- 抗崩溃证据：将独立 sixel 解码器抽取为临时测试程序，使用 seed `0x0e09202611050001` 生成长度 0–256 的 102,800 组随机字节，输出 `sixel_random_inputs=102800 seed=0x0f0ebb35987eb801`，进程退出码 0，无 panic。
- 依赖/集成：模块输出 NYAR 格式，graphics 状态负责把 DCS 转成图像事件并放入快照；因此即使只复制 `sixel.rs`，也没有 tTerm 当前可用的消费端。
- 结论：质量上可单独测试，但功能在本卡不属于对齐范围；不复制、不实现。

#### Kitty graphics：不采用

- 任务卡明确图片协议“只给出结论，不实现，也不复制”；当前 Tauri 版本没有 Kitty graphics 对齐目标。
- 规模：`graphics/mod.rs` 为 1,754 行，超过 800 行限制 954 行；`graphics/tests.rs` 为 1,312 行（测试豁免大小限制），`kitty_payload.rs` 为 156 行。
- 依赖：Kitty APC、iTerm2 OSC、Sixel 分类、base64/压缩 payload、存储上限、placement、删除模式、查询回复、cursor motion 和 viewport 坐标都集中在 graphics 状态中；它依赖 nyaterm 的 `TerminalSnapshot`、滚动坐标和 NYAR 图像格式，不能作为独立模块复制。
- 滚动计数：未发现 nyaterm 专有 `scroll_counter` API；但 placement 通过 `display_offset` 计算视口行，和本仓库不采用 Alacritty 滚动计数补丁的决定仍存在架构耦合。图片协议不能借此绕过 P0-12 的滚动锚定决定。
- 质量：固定版本的 graphics 测试包含 chunk 边界、超大 payload、存储淘汰、删除、Sixel 与 Kitty RGB24 等 38 个测试函数；不过无法在 nyaterm 原 workspace 直接运行完整 crate 检查，因为其 Cargo.toml 含 `zed-reqwest` 的 crates.io patch 与个人 git fork，当前 Windows 会话无法解析未缓存的依赖。
- 拆分估算：需拆出协议分类、Kitty 参数/payload、图片存储、placement/viewport、回复和渲染适配至少六个生产模块，并重做 tTerm 快照事件接口；这不是原样复制可接受的 spike 文件。
- 结论：即使技术质量可继续研究，也不属于本卡对齐范围；不复制、不实现，等待另行决策。

## 偏差

1. **nyaterm workspace 完整 clippy/test 未验证。** v2.0.2 的 Cargo workspace 使用 `zed-reqwest` crates.io patch、多个个人 git 依赖和 forked Alacritty；Windows 会话没有可用的 Schannel 凭据/缓存，Cargo 在解析 `zed-reqwest` 时失败。这个失败不影响本仓库全量检查，也不改变“不采用”的结论；若评估者需要完整上游运行证据，应在可访问这些依赖的环境中复跑。
2. **没有创建 `migrate/spike`。** 没有模块达到“采用且需要原样暂存”的条件；按规则不切换分支、不复制文件。若决策人将来决定采用某个模块，必须先在本报告列出待复制文件并经确认后，再从 `GPUI` 创建/切换 `migrate/spike`。
3. **图片协议未做窗口或渲染验证。** 任务卡明确要求只给结论；Sixel 的解码单测和随机输入仅用于质量关卡，不代表 tTerm 支持图片协议。
4. **跨平台与真实窗口未验证。** 本机只有 Windows 11；macOS、Linux 桌面、DPI、多显示器和真实输入法按环境清单属于未验证项。本卡没有原型窗口验收条件。

## 遗留问题

1. P1-11b 需要在 tTerm 现有 `src/lib/keywordHighlight/` 上决定是否补充语义提示、跨 wrapped 行缓存和性能限制；不得直接复制 nyaterm 的 `keywords.rs`。
2. 如果产品将来要支持 Sixel 或 Kitty graphics，应另开决策/任务卡，先定义协议范围、渲染格式、内存上限、滚动与快照事件接口，再从官方来源或自写实现开始；本报告的 nyaterm 文件不能直接作为实现输入。
3. nyaterm v2.0.2 的上游完整测试需要具备其 git 依赖的网络/凭据环境；这不是本卡采用结论的前置条件，但可作为后续上游跟踪 U-01 的复核项。

## 评估

结论：通过。

- 三个候选模块都有“不采用”的结论和证据，理由成立：关键词高亮 2,687 行，并依赖 nyaterm 的快照、主题与语义模块，tTerm 已有 `src/lib/keywordHighlight/` 实现；Sixel 与 Kitty graphics 按任务卡只给结论。
- 与任务卡的出入：卡要求“在 tTerm 的 clippy 配置下的告警清单”，执行者因 nyaterm 的 `zed-reqwest` git patch 在本机无法解析而没有产出。三个模块已因依赖与规模被否决，告警清单不会改变结论，评估接受，记为未验证。
- 评估者修正了验收表中被 `rg` 模式里的 `|` 断开的一行，没有改动结论。
- 没有复制任何第三方代码，`migrate/spike` 没有创建，`third-party.md` 无需登记。nyaterm 的临时克隆在仓库外的 `%TEMP%	term-p0-29-nyaterm`。
