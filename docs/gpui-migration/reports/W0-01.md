另外两项与“确认 Tauri 版构建、打包与 `pnpm tauri dev` 不受影响”有关的本地证据：

- `pnpm tauri build --debug` 走完 `beforeBuildCommand`（`gen-licenses` + `tsc` + `vite build`）、编译与打包，产物在根目录：`target/debug/tTerm`、`target/debug/bundle/macos/tTerm.app`、`target/debug/bundle/dmg/tTerm_0.8.1_aarch64.dmg`、`target/debug/bundle/macos/tTerm.app.tar.gz`。最后一步因为本机没有 `TAURI_SIGNING_PRIVATE_KEY` 而失败，这是 updater 签名所需，CI 提供该变量，与本卡改动无关。

## 偏差

1. **分支名。** 任务要求从 `dev` 切出 `gpui/W0-01-workspace`，但仓库已有 `GPUI` 分支，macOS 的文件系统不区分大小写，Git 无法同时存在 `refs/heads/gpui` 与 `refs/heads/gpui/...`（`cannot lock ref ... 'refs/heads/gpui' exists`）。按“在 GPUI 分支上做”的指示，改动提交在 `GPUI` 上；开工前它与 `dev` 是同一个提交（`5a7e90b`，`git diff dev GPUI` 为空）。
2. **`[workspace.dependencies]` 没有建立。** 技术选型 2.1 节的布局里列了它，本卡没有要求，三个空 crate 也没有依赖可共享；P0-06 固定 GPUI 来源时再加入。
3. **显式写了 `resolver = "2"`。** 虚拟 workspace 默认解析器是 1，会让现有依赖的解析与 `src-tauri` 单独构建时不同；写明 2 保持现状。技术选型没有提到这一点，建议补进文档。
4. **额外移动/修改的文件。** `.cargo/config.toml` 必须随 workspace 根移动，否则从仓库根执行 `cargo run` 时 macOS 的 runner 不再生效；`scripts/gen-licenses.mjs`、`CONTRIBUTING.md`、`sudo-mode.yml` 的路径过滤也因布局变化而必须改，否则 `pnpm build` 或触发条件会失效。这些都不在卡的“工作”列表里。
5. **锁文件不再是“完全相同”。** 移动本身的提交是 100% rename；增加 workspace 成员后，锁文件必然多出三个本地包条目。依赖的版本与 checksum 没有变化，报告按这个口径核对。
6. **CI 安装工具链的方式。** 原工作流用 `dtolnay/rust-toolchain@stable`，它会把 `RUSTUP_TOOLCHAIN` 固定为 `stable`，覆盖 `rust-toolchain.toml`。改为 `rustup show` 读取固定版本；macOS 的交叉编译目标改为显式的 `rustup target add`。我在一个临时工程里验证过 `rustup show` 会安装 `rust-toolchain.toml` 指定的工具链及其 `components`。
7. **固定 `1.99.1` 的依据。** 这是本机验证用的 stable。P0-06 会按 GPUI 与 nyaterm 的最低版本再调；`rust-toolchain.toml` 的注释已写明。
8. **`target/` 位置变化的影响。** 旧检出中的 `src-tauri/target` 不再被使用，可以手动删除；`.gitignore` 同时保留旧路径以免它出现在 `git status` 里。

## 遗留问题

1. **三平台 CI 与 beta 发布未跑。** 需要推送 `GPUI`（或改名后的分支）并手动触发 `release-dev-beta.yml`。第一次运行时重点看三处：`rustup show` 在 Windows runner 的 PowerShell 下是否正常、`swatinem/rust-cache` 的 `. -> target` 是否命中、`tauri-action` 在 Windows/Linux 上能否从根目录 `target` 找到安装包。另外 beta 发布矩阵里的 macOS 任务带 `--target` 参数，`tauri-action` 会在 `target/<triple>/release/bundle` 下找产物；这部分本次没有改，如实测有问题另开卡。
2. **`pnpm tauri dev` 的启动环节**未验证（理由见“验收”）。建议人工在 macOS 上跑一次，确认通知与单实例仍正常，并确认 `.app` 生成在 `target/debug/bundle/dev/`。
3. **首次构建代价。** 根目录 `target/` 为空时要全量编译一次；本机空 target 下 `cargo test --workspace` 约 3 分钟、clippy 约 1 分钟。建议在团队说明里写明旧的 `src-tauri/target` 可以删除。
4. **`resolver = "3"` 与 `[workspace.dependencies]`** 留给 P0-06 决定；届时应同时决定新 crate 的 edition 与 workspace 默认值是否统一。
5. **`docs/gpui-migration/reports/README.md`** 属于 W0-02，本卡没有创建，只新增了本报告文件。
