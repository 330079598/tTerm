### Tauri 入口与剩余扫描说明

扫描命令：

```sh
rg -n 'tauri::|AppHandle|TauriEventSink::new' src-tauri/src/{tunnel,notification,background,agent_integration,system_integration,app_state.rs,launch_dir.rs,updater.rs} -g '*.rs'
```

[原始结果](P1-07d-evidence/tauri-grep.txt) 的剩余逐类说明：

- 35 个 `#[tauri::command]` 宏和 State<Arc<AppServices>> 参数：Tauri IPC 注入入口，见清单。
- `notification/mod.rs` 的 Response：read_notification_sound 将服务字节转换成 IPC 响应；notification_permission 的 AppHandle 与 Manager：入口克隆同一通知能力后交给 permission。Tauri 宏不允许带 State 引用的 async command 直接返回枚举，保留 AppHandle 才能维持原 NotificationPermission 返回类型。
- `notification/badge.rs` 只有 command/State；overlay 校验、attention 与 badge 更新在无 Tauri 的 set_unseen 服务中。
- `background/mod.rs::resolve_close_request` 的 AppHandle：入口通过既有 SFTP 接口取得未上传文件名，再交给服务。P1-07b 并行期间未改对方定义。其他 background 只剩 command/State。
- `agent_integration/remote.rs` 的 AppHandle 导入与两个 command 参数：SftpHost 当前仍由 P1-07b 负责去掉 AppHandle；本卡只在两个入口调用既有 handles 接口，remote_status/remote_change/open 不接受 Tauri 类型。
- `updater.rs` 的 Channel 导入与两个 command 参数：仅包装 IPC 进度发送；Progress 本身只保存无框架回调。download_app_update 的 AppHandle 仅用于在入口读取 AppPaths。
- `system_integration`、`launch_dir`、`app_state`、`tunnel` 其余匹配均为 command 宏与注入参数。tunnel runtime/reporter、系统集成服务无匹配。

Tauri 专用图标/菜单构造和回调已放在 `platform/tray_native.rs`，属于平台适配层。菜单回调只读 AppServices、组装 Context、把 action ID 交给服务；鼠标回调转换原生事件并调用显示/刷新服务。lib.rs 的 single-instance、窗口 close、RunEvent 都在入口用 try_state，未初始化时跳过；后台任务不再捕获 AppHandle。

## 偏差

- 第 1 轮骨架缺口由本轮用户明确授权修订，不再是需要确认事项。services 定义只增加这两个字段，未新建平台 trait。现有 trait 新增方法为 Notifications::initialize、Tray::dispatch、MainWindow::send_to_background、MainWindow::save_before_update；Tauri 与现有测试实现均同步，三平台共用的代码不增加平台专属编译分支。
- `platform::initialize` 返回装配闭包：先在原位置构造并 manage 九个既有能力，在系统集成初始化后补入两个新增能力。这样 AppServices 可以按授权后移，既有平台能力的构造位置不变。通知使用已存在窗口/badge Arc，不额外创建平台能力。
- `7c6563b0` 是托盘目录 100% 原样 rename，0 插入/删除；后续才分离原生适配和菜单逻辑。部分模块间签名提交需要最终启动接线提交才能组合编译，未改写历史，完整组合通过全部检查。
- SFTP 的两个 AppHandle 接口属于并行 P1-07b，遵守跨卡限制不改其定义：在本卡 Tauri 入口取得 SftpHandles 和未上传文件名快照，再传给服务。P1-07b 合并后可将这些入口改为对应的无 Tauri 依赖，服务无需再改签名。没有把整个 AppServices 交给服务，也未用元组打包参数。
- `system_integration::apply_config` 改为 async 以调用已有 refresh 能力。setup 使用 runtime.block_on，config 仍在原 run_blocking worker 中等待，刷新完成再进入下一步。初始化失败信息由原格式保存，未为失败建立第二份能力。
- 通知权限入口保留 AppHandle 的编译原因见扫描说明。三个 update command 保持 State 参数在前，匹配既有签名扫描器对 lifetime 的解析结果；没有改基线或扫描器。
- 配套文件：`config/mod.rs` 只跟改两个 apply_config 调用；`lib.rs` 跟改启动/退出/窗口/单实例入口并删除专有 manage；`ssh/auth/tests/broker.rs` 仅补现有 MainWindow trait 新方法的测试实现；其余跨领域变化位于平台适配层。core、ssh、session_log、proxy 的生产定义未改。
