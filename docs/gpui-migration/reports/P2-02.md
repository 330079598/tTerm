# P2-02 输出管线与背压

- 执行者：Codex
- 当前分支：`codex/P2-02-output-pipeline-backpressure`，基于 `5b757b1d`
- 实现提交：`70b73bf6`
- 审查修复提交：`637c4c77`
- 本机：Windows 11，使用仓库固定的 Rust 与 pnpm 工具链

## 结论

**完成（Windows）。** GPUI 端输出现在由后台解析线程分批写入模型；解析队列和
`OutputFlow` 共同限制持续输出时的排队量。视图来不及消费输出时只会保留一个待处理的刷新，
不可见会话继续解析并确认，但不再请求快照或绘制。背压确认发生在对应输出已经写入
模型并处理完解析意图之后；普通输入和 Ctrl+C 直接走会话写入路径，不等待输出队列。

三项验收在最终代码 `637c4c77` 上均通过：持续输出期间队列高水位固定在 `589,824`
字节；真实本地 PTY 输出洪峰期间，普通输入写入为 `7.5µs`，Ctrl+C 写入为 `400ns`，
从写入 Ctrl+C 到进程退出为 `10.2814ms`；30 个后台解析器持续输出时，前台准备的
帧耗时 p95 为 `407.6µs`，远低于 `16.667ms` 的 60 FPS 帧预算。前台基线 p50/p95 为
`239.3µs`/`256.9µs`，加载 30 个后台会话后为 `278.4µs`/`407.6µs`，p50 增加约
`16.3%`；本报告不以 p50 增加为由声称帧率完全不变，验收依据是后台负载下 p95 仍低于
预算。补测共处理并确认 `31,799,600` 字节；120 次前台快照等待模型锁合计 `4.9µs`，
持锁合计 `11.0091ms`，单次最大 `216.5µs`。定向行为测试与最终全量检查均通过。

### 行为变化

- 核心 `OutputFlow` 送来的块先按最大 `64 KiB` 切分，再进入容量为 7 块的同步队列。
  同一会话的发送者串行执行整个发送，因此队列之外最多还有一个等待槽位的发送块和
  一个正在解析的在途批次；三部分合计封顶为 9 × 64 KiB，即 `589,824` 字节。
  解析完成前，已接受和阻塞中的字节持续计入队列占用；解析后立即释放。
- 解析线程每次只取一个队列块并直接应用，不再把相邻小块合并成更大批次。大 IPC
  消息仍会在入队前切分，所以模型锁的单次持有工作量保持在 `64 KiB` 以内，界面快照
  不必等待整个 512 KiB 核心块解析完。修复版保留了这一总量上限，同时避免并发发送者
  各自跨越同一预算。
- 每个 PTY 输出块携带它应确认的流控字节数；ACK 在该块写入模型并处理完所有解析
  意图之后发出。本地生成的 `[Process exited]` 提示也进入同一解析器和刷新路径，但
  不消耗 PTY 的流控额度。关闭代次拒收的迟到 PTY 块仍会 ACK，避免读取线程永久卡在
  不再绘制的数据上。
- `RefreshSignal` 使用一个原子待处理位合并唤醒。视图在开始处理刷新时确认该位；
  持续解析不会堆叠 watch 通知。新订阅会清除无接收者期间留下的待处理位，避免重附着
  后下一条输出被旧位抑制。
- 隐藏会话仍解析和 ACK，模型内容与回滚区保持最新，但不发送输出刷新。重新进入标签
  时主动请求一帧以显示隐藏期间积累的内容；新会话继承标签当前的可见状态。
- `ViewStats` 增加每帧快照数，`Terminal` 增加快照数、等待锁时间、持锁总时间和最大
  持锁时间。计时只覆盖获取公平锁和复制可见行，不包括排版、字体测量或绘制。

## 偏差

1. **帧指标来自 GPUI 测试窗口，不是合成器 FPS。** 基准直接重复准备并渲染 120 个前台帧，
   同时运行 30 个真实解析线程和隐藏模型。它衡量前台帧准备/绘制成本和后台解析器争用，
   没有运行 30 个实际标签、窗口管理器和 GPU 合成器，也不等同外部帧率采集。
2. **输入数据是写入与被中断延迟。** `7.5µs` 和 `400ns` 是调用会话输入到写入 core 的耗时，
   `10.2814ms` 是 Ctrl+C 写入后到真实 PTY 进程退出、退出行进入模型的耗时；不是键盘事件到
   屏幕像素的端到端延迟。
3. **内存证据使用结构性上限和队列高水位。** 测试验证 `OutputFlow`、解析队列、模型批次和
   固定回滚区都不会随持续输出增长，没有用整进程 RSS 作为平台无关的通过条件。窗口线程和
   图形后端自身分配不计入解析队列指标。
4. **64 KiB 切分可能跨越 UTF-8 或转义序列边界。** Alacritty 解析器按流保存跨写入状态；
   本卡的分块只限定每批持锁工作量。P2-01 已有的普通、中文和转义输出测试保持通过。
5. **当前窗口仍是单标签原型。** 可见性接口已经按每个 `TabBinding` 同步，30 会话性能测试
   直接创建 30 个会话解析器；真实多标签 UI 仍属于后续窗口/标签工作。
6. **与 Tauri 的对比是同一核心实现和源码路径对比。** 本次没有同时运行 Tauri 与 GPUI 的
   端到端基准，因此帧与输入数字只描述 GPUI 路径，不宣称原生版在所有场景更快。
7. **性能数字对应初版实现。** 审查修复版保留总字节上限并让每个队列项独立解析，但移除了
   小块合并，增加了发送串行化与合成输出分流；因此延迟和帧耗时数据标记为 `70b73bf6`
   初版测量，修复版只据最终全量行为测试判定通过。
