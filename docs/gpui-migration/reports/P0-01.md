超过 10% 的噪声来源与限制：

- cat 实际持续 3 / 2 秒，40 秒窗口含长空闲尾段；约 3 秒 PDH 采样可能漏采或稀释短峰，CPU 绝对差 0.292 个百分点。文件预先生成，两轮 SHA256 同为 `B20012581B92CDE076A4E6A94DA49540B07C82ABA6922705E9ECEFA2878A6FF5`，恰为 50,000,000 字节。不能以该 CPU 值声称吞吐改善。
- yes 两轮均 30 秒。vim 两轮均 31 秒，20 ms timer 受调度、redraw 和背压影响，并非硬实时节拍；CPU 绝对差 0.163 个百分点，RSS/GPU 接近。
- tmux 四窗格无限速 yes 各运行 30 秒，3 秒后退出。WSL/tmux 调度、四窗格重绘合并、ConPTY 背压、PDH 相位使输出总量不固定；第二轮还有失败重采的缓存/堆状态差异。CPU 差 63.6%、RSS 差 10.3%，不能唯一归因或声称稳定 10%。P0-21 须使用同样流程并报告方差。
- 空闲 CPU 均低于 0.06% 整机，近零分母放大调度/计时器噪声，绝对差很小；RSS 在 3.6% 内。30 会话 GPU dedicated 差 27.2%，可能与隐藏 renderer 回收和 GPU 驻留时机有关，保留逐样本数据，未证明唯一因果。10 会话第一轮 GPU 查询报 invalid sample，留空保存错误，未当作零。
- 峰值与帧尾分位数更受调度和空闲尾段影响；两轮不足以区分系统噪声与应用方差。没有删异常值、升阈值或隐去超限指标。

实际负载起止 UTC 在各 `*.started`、`*.done` 与 `workload-durations.json`；截图 `run*-vim-active.png` 显示实际滚动，`run*-tmux-active.png` 显示四窗格同时输出。1/10/30 会话逐级增加，每项稳定等待 15 秒，只有一个前台标签。
