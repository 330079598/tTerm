- `ssh/secret_store/mod.rs` 去掉无用途的 AppHandle 参数；启动／解锁的迁移路径由 AppPaths 的 data_dir 注入，keyring 标识由 AppIdentity 注入。
- proxy 审批接收现有 PromptBroker 和 MainWindow，未增加平台 trait。monitor 显式接收 PendingMonitorPrompts，修正旧读取方未包 Arc 的状态类型。
- `lib.rs` 仅增入口组装模块声明、同步签名调用，并删除仅 a 使用的五项 manage：Zmodem 三项、MonitorSessionMap、PendingMonitorPrompts。所有跨卡共享 manage 均保留。

### Tauri 入口与扫描

[Tauri 入口清单](P1-07a-evidence/entries.txt) 列出本卡 83 个 command 的文件和函数名。本卡没有新增交给 Tauri 的非 command 回调。原来的服务辅助函数、线程和 Tokio task 均不再接受或捕获 AppHandle。

[完整 grep 结果](P1-07a-evidence/tauri-grep.txt) 包括测试，命令：

```sh
rg -n 'tauri::|AppHandle|TauriEventSink::new' src-tauri/src/{core,session,terminal,ssh,serial,zmodem,monitor,proxy,session_log,prompt_scope.rs} -g '*.rs'
```

结果中的每类剩余用途：

- `#[tauri::command]` 与其参数 `tauri::State<Arc<AppServices>>`：对应入口清单，IPC 注入。
- `core/commands/mod.rs` 的 `use tauri::{AppHandle, State}`、create_pty 的 AppHandle、Webview、JavaScriptChannelId：仅用于在入口建立二进制 Channel 和 TauriSessionSink，然后把无客户端的 sink 交给服务。
- `ssh/secret_commands.rs::unlock_secret_vault` 的 AppHandle：仅在入口读取已经初始化的 AppPaths，服务接收 PathBuf。
- `session_log/mod.rs` 的 `tauri::ipc::Response` 导入：只供两个读取日志的 command 将服务返回的 Vec<u8> 转换为 IPC Response。
- `core/blocking.rs` 的 `#[tauri::command]` 文档文字：解释为何阻塞工作离开主线程，不是类型或调用。
- `terminal/io_batcher.rs` 的 cfg(test) test_sink 和 tests、contracts、benchmark、real_pty_tests、lifecycle_tests、legacy_events/tests.rs：测试二进制 IPC 与原事件适配器的契约。均在 cfg(test) 下，测试断言未放宽。

其中 `TauriEventSink::new` 只在测试中剩余。`prompt_scope.rs`、日志实现子模块、SSH 连接与 proxy 非入口实现均零匹配。

- 为遵守文件拆分规则，先将 core/commands.rs、session_log.rs 原样移动为目录 mod.rs；两次 `git show -M --stat` 均为 100% rename、0 插入／删除。之后拆分创建流程和 IPC 输出适配器。最终复核将 TerminalOutput 改为字节发送回调，并把无框架端点放回 terminal/output.rs；没有新建平台 trait。依赖接线分模块提交，部分中间提交需后续模块提交才能编译，最终组合已通过全部检查；没有把自动检查失败当作完成。
- IPC 输入名称与类型不变。原签名基线记录了 `mut targets`，入口通过 mem::take 转交给服务以保留原模式；未改基线。现有签名脚本把 lifetime 当引号，因此绝大多数 State 参数放在 IPC 参数之后；`terminal_log_ids_for_tab` 保留原 State 在前的位置以匹配原基线（不影响实际 IPC）。
- `SessionLogState::validate_config` 签名不变；apply_config 改为具体 LogContext。config/mod.rs 仅修正 Arc 状态读取和 apply_config 调用。日志默认目录仍经 P1-01 已初始化的 config::paths 读取（其底层来自 AppPaths），保持原目录位置。
- lib.rs 额外同步密钥库 initialize、日志 apply_config 与退出 shutdown 调用，均由本卡去掉 Tauri 参数所必需，启动顺序未调整。
