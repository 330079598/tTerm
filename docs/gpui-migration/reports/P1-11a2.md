# P1-11a2 终端标签页的输出处理移植到 Rust（macOS）

## 结论

完成：`src/components/TerminalTab/` 中范围内的 8 个模块及其依赖的 `src/lib/predictiveEcho.ts` 已移植到 `tterm-terminal` 与 `tterm-core`；`predictiveEchoOverlay.ts` 是 DOM 绘制，不移植。8 个 TS 测试文件共 80 个用例全部逐条转写为 Rust 测试，`commandTracking.ts` 没有 TS 测试，其期望值全部由真实 TS 模块的 node oracle 生成。`src/`、`src-tauri/` 和 `docs/gpui-migration/status.md` 未修改。

### 主要文件

- `crates/tterm-terminal/src/command_marks.rs`：OSC 133/633 命令标记、提示事件、提示状态、命令输出范围；xterm marker 由绝对行号与 `CommandMarkViewport` 替代。
- `crates/tterm-terminal/src/cursor_move_hold.rs`：行重绘前导块的缓冲规则与 `is_line_redraw_lead`；定时器由调用方调度。
- `crates/tterm-terminal/src/predictive_echo.rs`：`EchoPredictor`、预测显示/确认/回滚规则、`PredictiveEchoState` 与遮罩行规则；DOM 叠加层不移植。
- `crates/tterm-core/src/attention_reports.rs`：OSC 9/99/777 报告、agent 会话回调与 bell。
- `crates/tterm-core/src/command_tracking.rs`：输入命令、shell integration 命令、1500ms 去重、命令计时器与 agent 重置；共享 `AgentTracker` 与 `CommandTimer`。
- `crates/tterm-core/src/cwd_reports.rs`：本地/远程 OSC 7、OSC 9;9 与 `pty-cwd-*` 会话代次；复用 `tterm_terminal::terminal_cwd`。
- `crates/tterm-core/src/os_reports.rs`：本地 WSL 的 OSC 777 发行版报告；复用 `tterm_core::distro`。
- `crates/tterm-core/src/saved_password_prompts.rs`：sudo 提示的保存密码报价、拒绝窗口、查找/填入 action、login script 行；复用 `tterm_terminal::sudo_prompt`、`password_feedback` 与 `login_script`。
- `scripts/migration/p1-11a2-oracle.mjs`：用 `typescript.transpileModule` 加载真实 TS 模块，只在 xterm、Tauri、React 边界打桩。

### crate 去向

`tterm-terminal` 不依赖 `tterm-core`；需要连接、配置、历史或工作区回调的模块放在 `tterm-core`。本卡没有新增依赖，沿用 workspace 已有的 `regress = 0.12.0`（`utf16` feature）与 `serde`。

| TS 模块 | Rust 位置 | 理由与 xterm 替代 |
| --- | --- | --- |
| `attentionReports.ts` | `tterm-core::attention_reports` | 通知与 agent 会话属于业务事件；OSC 注册由适配器做，agent 状态复用 `AgentTracker`。 |
| `commandMarks.ts` | `tterm-terminal::command_marks` | 标记与输出范围属于终端模型；marker 由绝对行号与 `CommandMarkViewport` 替代，decoration 由视图绘制。 |
| `commandTracking.ts` | `tterm-core::command_tracking` | 需要 `AgentTracker`、`CommandTimer`、命令历史与 tab 回调；终端状态经 `CommandMarkViewport` 读取。 |
| `cwdReports.ts` | `tterm-core::cwd_reports` | 每 tab 的目录/主机状态与 `pty-cwd-*` 事件；OSC 7 解析复用 `tterm_terminal::terminal_cwd`。 |
| `osReports.ts` | `tterm-core::os_reports` | 发行版身份属于业务状态；OSC 777 注册由适配器做，识别复用 `tterm_core::distro`。 |
| `savedPasswordPrompts.ts` | `tterm-core::saved_password_prompts` | 需要连接配置、保存密码、登录脚本与输入通道；提示识别复用 `tterm_terminal::sudo_prompt`。 |
| `cursorMoveHold.ts` | `tterm-terminal::cursor_move_hold` | 只做输出分块缓冲；parser、定时器和 `onData` 监听由适配器持有。 |
| `predictiveEcho.ts`（`src/lib/`） | `tterm-terminal::predictive_echo` | 预测与确认规则属于终端输入/输出模型；xterm marker、buffer、定时器与叠加层由视图适配。 |
| `predictiveEcho.ts`（`components/TerminalTab/`） | `tterm-terminal::predictive_echo` 的 `PredictiveEcho` | 保留模式、阈值与 `canPredict` 规则；xterm 事件、marker 与 DOM 叠加层不移植。 |
| `predictiveEchoOverlay.ts` | 不移植 | 纯 DOM 绘制，原生端由 P3 的终端视图绘制预测格与光标。 |

## 偏差

1. **超过 `i64` 的退出码。** TS `Number("9223372036854775808")` 得到约 `9.223372036854776e18`（JSON 里显示 `9223372036854776000`）；Rust 的 `i64` 字段放不下，`parse_exit_code` 返回 `None`。测试 `exit_codes_outside_the_shared_i64_field_are_dropped` 固定了这一差异。`-0` 也只能表示为 `0`。
2. **xterm marker 与 scrollback 驱逐（第 2 轮已补齐状态接口）。** 原生适配器在清屏时调用 `CommandMarks::dispose_markers`，顶部裁剪 n 行时调用 `trim_scrollback(n)`。前者 dispose 全部 marker；后者同步 prompt/output/end 与跳转 marker 的行号，负数 prompt 删除整条 entry，负数 output/end 令输出范围无效，与 TS `prompt.onDispose`、`current()`、`liveEntries()` 一致。受影响函数为 `handle_mark`（含 `start_prompt`/`start_output`/`finish_command` 与 `current_exit_code`）、`is_at_prompt`、`handle_enter`、`scroll_to_previous_prompt`、`scroll_to_next_prompt`（含 `jumped_prompt_line`）、`last_output_range`、`last_output_text`、`select_last_output`。清屏/裁剪不重置独立的 `command_running`、`marks_prompts`、`status_since_prompt` 和 `output_since_prompt`，所以 `prompt_state`、`is_running_program` 与后续 PromptEvent 的 `exit_code`/`started_command`/`status` 同样遵守 TS。真实 TS 配最小 marker stub 的 oracle 已覆盖这些语义；P3 只需转发实际 grid 的清屏/裁剪通知，不改终端模型。
3. **buffer 行。** TS 的 `IBufferLine.translateToString(true)` 由 xterm 提供；Rust 用 `BufferLine { is_wrapped, text }` 回调。`Snapshot` 只含可见行，滚动区历史行必须由适配器提供；`last_output_text` 因此接收 `line_at` 而不是直接读 `Snapshot`。
4. **decoration 与滚动条颜色。** TS 在 `finishCommand` 里 `registerDecoration` 并给 `.command-mark-dot` 上色；Rust 只返回命令/退出码/范围，原生视图负责绘制。`CommandMarkViewport` 不含 decoration API。
5. **prompt listener。** TS `onPrompt` 是 `Set`，每个 listener 同步收到事件；Rust 用单一 `prompt_events` 队列，显式 `listen_prompt_events`/`stop_listening_prompt_events` 控制。测试逐项比较事件内容、顺序和 `Ended` 时机；多个 listener 由适配器自行分发。
6. **`CommandTracking` 的所有权。** TS 返回 `agentTracker`、`commandTimer`、`commandMarks` 与若干 disposable，并接 `mouseReportingGuard`、`lineFeedDisposable`；Rust `CommandTracking` 持有共享 `AgentTracker`、`CommandTimer` 与 `CommandMarks`，提供访问器；mouse reporting guard 属于另一个模块，line feed 计数由适配器调用 `SavedPasswordPrompts::note_line_feed`。OSC/PTY 注册不进入 Rust API。
7. **`AttentionReports`、`CwdReports`、`OsReports` 的注册。** TS 的 `watch*` 负责 `registerOscHandler`、`onBell` 和 Tauri `listen`；Rust 提供 `handle_osc`/`handle_bell`/`handle_pty_cwd`，由适配器注册和路由。`now_ms` 取代 `Date.now()`，测试可显式控制时钟。
8. **`SavedPasswordPrompts` 的 I/O 与 React 状态。** TS 直接读 xterm 光标行、调用 `invoke`、拥有 `LoginScriptRunner` 并写 tab store；Rust 接收 `line`，返回 `LookupSource`/`FillThroughCommand`/`FillThroughInput`/`NotifyNotSent` 等 action，`login_script_lines` 只返回要执行的命令。`read_cursor_line` 复用 `tterm_terminal::sudo_prompt`，`LoginScriptRunner` 仍由后端/适配器运行。`SavedPasswordPromptState` 是内部 tagged enum，适配器映射回 TS 的 `status` 字段。
9. **DOM 预测叠加层。** `predictiveEchoOverlay.ts` 的 `RealCursor` 与 `createPredictiveEchoOverlay` 不移植；`PredictiveEcho` 只返回 `PredictionView`。P3 终端视图按同样的 cell、cursor 与 stalled 规则绘制。
10. **`PredictiveEcho` 的 xterm 状态。** TS 直接读 `_core.coreService.isCursorHidden`、`buffer.active.type`、`modes.mouseTrackingMode`、marker 与 `onWriteParsed`/`onResize`/`buffer.onBufferChange`/`onScroll`；Rust 用 `PredictiveEchoState` 的四个布尔输入接收这些状态，view 传入 `PredictionScreen`。timer 与 marker 同步由适配器做。
11. **`CursorMoveHold` 的定时与输入监听。** TS 内部 `setTimeout` 和 `term.onData`；Rust 用 `next_deadline`/`flush_due` 与 `note_input`，调用方负责调度与 dispose listener。字节与顺序不变，仅渲染延迟。
12. **序列化。** `ExecutedCommand` 使用 `camelCase`，`profileId`/`profileName` 为 `None` 时省略，与 TS 对象经 `JSON.stringify` 的形状一致；反序列化忽略未知字段（测试含 `"unknown": true`）。`SudoPasswordSource` 的 serde 值是 `"sudo"`/`"login"`，与后端枚举一致。`tterm-core` 已开 `float_roundtrip`；本卡没有依赖 JSON 对象键顺序的写回逻辑，所以没有改 `Cargo.toml` 的 `preserve_order`。单独 `cargo test -p tterm-core` 与 `cargo test -p tterm-terminal` 均已通过。
13. **`SudoPasswordSource` 不能表示空字符串。** TS 的 `source` 可以是 `""`（truthiness 为假）；Rust enum 只有 `Sudo`/`Login`，`from_wire("") -> None`，效果与手动路径相同。直接调用 `resolve_saved_password_source` 的调用方需要用 `None` 表示空值。
14. **数值时钟类型。** TS 用 `Date.now()`/`performance.now()` 的 `number`；Rust 用 `u64` 或 `f64` 显式传入。`CommandTracking` 的 `now_ms as i64` 只用于正的时间戳；`CommandTimer` 沿用已有实现。
15. **`commandTracking.ts` 没有 TS 测试。** `oracle_*` 测试以 `scripts/migration/p1-11a2-oracle.mjs` 的真实 TS 输出为期望值，没有手算或回填实现输出。第 2 轮又加载真实 `terminalInput.ts`，验证手动回答密码后恢复命令记录；五个原始 TS 测试已去除误加的 `oracle_` 前缀。

## 遗留问题

- **空用户名的自定义提示**：自定义正则的 `user` 分组捕获到 `""`，连接用户名也是 `""` 时，TS 与 Rust 都会提供保存密码；见 oracle 的 `savedOracle.customPromptUsers.emptyUsername`。本卡如实保留 TS 行为；TS 侧可能也值得收紧，由 stone 决定。
- **Windows**：待补（决策 016）；本机无法验证 Windows 的 ConPTY/marker 行为，CI 仍需三平台编译。
- **Linux**：推迟（决策 016）；未在本机运行 Linux。
- **原生 marker 通知/decoration 接线**：P3 终端视图需把清屏与顶部裁剪通知分别传给 `dispose_markers`/`trim_scrollback`，并绘制 decoration；状态与查询规则已在第 2 轮对照真实 TS 测试。
- **`regress` 的 `i` 大小写折叠**：P1-11a1 已记录 `U+017F`（ſ）折叠到 `s` 的上游差异；本卡复用的 PAM 词汇表仍受同一引擎影响，未新增规避实现。
- **`tsx` 不可用**：本 worktree 的 `pnpm exec tsx` 报 `Command "tsx" not found`，oracle 使用任务卡允许的 `typescript.transpileModule` 方式，命令已写入报告。
- **Tauri 版未运行**：按决策 017，本卡不人工验证 Tauri 版；没有读写 `com.stone.tTerm` 或 `com.stone.tTerm.dev` 的数据目录。
- **`cargo test --workspace` 的 64 个 ignored**：均为仓库已有项，本卡没有新增 `#[ignore]`；沙箱内的 macOS 应用列表测试需沙箱外复跑，最终复跑通过。

## 评估

结论（2026-11-12，Claude）：通过（macOS），两轮，执行模型为 DeepSeek v4.1 flash（Codex）。Windows 待补，Linux 推迟（决策 016）。

- **第 1 轮：没有高危问题。** 独立审查用 oracle 逐个分支核对了保存密码的真值表，以及预测回显（包括 f589e57 的遮罩规则），都与 TS 一致；80 个 TS 用例都有对应。需修改的是接口缺失：TS 通过 `session` 共享的几项状态，原生端没法维护。
  - 新命令之后，上次的填入记录清不掉，结果会把再次出现的 sudo 提示当成被拒，整个会话都不再填入。
  - 命令捕获的暂停状态只能读、不能写。
  - `CommandMarks` 没有处理 xterm 在清屏、回滚缓冲区裁剪时让 marker 失效的情况。
- **第 2 轮：全部修正。** 加了 `forget_last_fill`，测试改为让真实的 `CommandTracking` 驱动 `SavedPasswordPrompts`；`capture_input` 照 `terminalInput.ts:90-97` 移植，状态只保存一份；清屏与裁剪的失效处理覆盖了全部查询，期望值由 node 运行真实的 `CommandMarks` 得到。复审确认三处都已修好，没有引入新的密码路径风险。

- **遗留（低，留给 P2 接入终端时处理）：**
  - 终端尺寸变化引起重排时，xterm 会移动 marker，必要时还会让它失效。`CommandMarks` 目前只处理从顶部裁剪，没有处理重排的接口。原生端的标记位置应当由 `tterm-terminal` 的网格提供，到 P2 时按实际模型决定。
  - oracle 用的 xterm 替身在每次 `clear()` 时都会让全部 marker 失效。真实的 xterm 在光标位于第一行、缓冲区没有回滚内容时，不会让 marker 失效。
  - `cwd_reports::tests::oracle_pty_events_require_the_matching_session_nonce` 没有对应的 oracle 数据（规则 15）。
  - 自定义提示的 `user` 分组捕获到空字符串、连接的用户名也是空字符串时，TS 会提供密码；Rust 照搬了这一行为，是否收紧由 stone 决定。
