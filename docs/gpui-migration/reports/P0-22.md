# P0-22 P0 结论与重新估算

## 结论

P0 没有触发任何停止条件。迁移计划第 6 节的四条停止条件中，两条已有结论，两条按[决策 015](../decisions/015-trim-p0.md) 推迟到 P2，没有一条得出“不可接受”。G1 的七条标准中，有六条已满足；剩下的一条“重新估算的工期”就是本报告。建议 G1 通过，进入 P1。

重新估算后，剩余工作约 **445–640 人天（90–130 人周）**，与 README 第 10 节的总量基本相同：P0 省下的部分（P1-13 没有内容、P2 的输入与滚动已有底子、P3-06 已有 8 个组件）被推迟进来的验收（P0-16、17、18、21 与 P0-01 的剩余部分）抵消了。按 P0 的实际节奏换算成日历时间，约为 **3–5 个月**，见第 3 节。

作者：Claude（评估者）。本卡只汇总已合并的报告，没有运行新的测量。

**日历时间。** P0 从 2026-11-05 到 2026-11-09，5 天合并了 24 张卡，平均每天约 5 张，执行者为 Codex 与 Claude，两台机器。这个节奏不能直接外推：

- P0 的卡多是独立的原型与验证，P1 起是对正式代码的重构，要保证 Tauri 版行为不变，回归风险高；
- 界面对齐卡每张要 3–6 轮（P0-24 第二批的经验）；
- 评估与 stone 的人工验收不会随执行者变快，现在的瓶颈就在这两处。

按每天 2–4 张卡估算，剩余约 110 张卡（含子卡）需要 **3–5 个月**。P1 的关键路径是 P1-02 → P1-03 至 P1-06 → P1-07a–d → P1-09 → P1-12，其中 P1-08 要等 P1-01，在 P1-09 前汇合。这条路径上有 4 张 L 卡串行，预计 **2–3 周**；P1-12 完成后才能开始 P2 与 P3。
