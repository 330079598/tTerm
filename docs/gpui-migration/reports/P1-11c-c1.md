设计要点：

- `scrollback` 的数字处理沿用 `tterm_terminal::theme::js::js_round`，以保留 JavaScript `Math.round` 对负数半分的处理；`grown_scrollback_capacity` 在 `u64` 中计算 `lines * 2` 和翻倍，避免 `u32` 溢出。`count_line_feeds` 按字节匹配 `0x0a/0x0b/0x0c`，与 `charCodeAt` 对 ASCII 控制符的判断等价，非 ASCII 字节不会被误计。
- `terminal_font` 的 `first_installed_font` 用 `tterm_terminal::js_text::js_trim` 逐项 trim，再去掉**一个**首引号和**一个**尾引号，与 `replace(/^["']|["']$/g, "")` 一致；返回字体链中写的名字，链中没有安装项时返回整条链。`detected_font_family` 用 `cfg!(target_os)` 替代 `@tauri-apps/plugin-os`。
- `tab_settings` 使用 `workspace` 的三套类型（`TabIconConfig`、`TabAgentIndicatorConfig`、`PaneLayoutTemplate`），不依赖 `config` 类型；`TabWidthMode` 用 `String` 保存两个合法 id。`Serialize` 只用于测试把默认值逐字节比对 oracle，c2 写回 `AppConfig` 时仍需按计划做三处类型转换。
- `shell_commands` 的 `BREAKS`、注释判断、`\s`、`case … in` 与 here-document 五个正则全部照抄 TypeScript，交给 `regress` 编译一次并缓存（无 flags，保留 `\2` 反向引用）；`/\r\n?|\n/` 用手写 `split_lines` 实现，不匹配 U+2028/U+2029。扫描以 Unicode 字符推进，对 ASCII 语法符号和 UTF-16 代码单元扫描等价。
- `remote_shell_integration` 的两个常量与 oracle 的 `remoteShellIntegration.scripts` 逐字节相等；`${"$"}` 在运行期就是 `$`，`\033`、`\e` 保持字面反斜杠。
- `ssh_shell_integration` 复用 `events::ssh::UnavailableReason`，不复制原因枚举。Rust 的 match 覆盖全部现有变体；以后新增变体会在编译期提醒补规则，而不是像 TS 的 `default` 那样静默归为“提示”。

### shellCommands 正则对照

| 位置 | TypeScript 规则 | Rust |
| --- | --- | --- |
| 单词分隔 | 空白、`;`、`&`、竖线、圆括号、尖括号、单双引号、反引号、反斜杠字符类（无 flags） | `BREAKS`，`regress`，无 flags |
| 注释前字符 | 空白、`;`、`&`、竖线、圆括号字符类（无 flags） | `COMMENT_BREAKS`，`regress`，无 flags |
| 空白 | JavaScript 的空白类（无 flags） | `WHITESPACE`，`regress`，无 flags |
| `case … in` | 空白、`in`、空白或行尾（无 flags） | `CASE_IN`，`regress`，无 flags |
| here-document | 行首 `<<`、可选 `-`、可选反斜杠与引号、结束词，保留反向引用（无 flags） | `HEREDOC`，`regress`，无 flags |
| 行切分 | CRLF、CR 或 LF | 手写 `split_lines`，只认 CR/LF |
| 引号黏连 | 单引号、双引号、反引号或反斜杠 | 逐字符 `matches!` 判断（无正则） |

全部正则用 `LazyLock` 只编译一次；没有加 `u` flag，空白集合与 JavaScript 一致，不由 Rust `regex` 近似。完整模式见 `src/lib/shellCommands.ts` 与本模块源码。

## 偏差

1. **报告文件名为 `P1-11c-c1.md`**，与 P1-11c 计划中的通用 `P1-11c.md` 不同，按本轮任务要求执行；计划中的 c2 内容未写入本报告。
2. **`shellCommands` 的 8 个 TS 用例对应 12 个具名 Rust 测试 + 5 个边界/oracle 测试**，没有逐条拆成计划里提到的 18 个独立 `#[test]`。18 个 oracle 检查由 `oracle_matches_every_typescript_shell_commands_case` 逐条断言（包括 for/elif/while/case 与函数/子 shell/PowerShell/fish 的每个子用例），失败时仍会打印用例 id；因此覆盖范围不减少，只是测试函数粒度与计划不同。
3. **`ssh_shell_integration` 的 Rust match 不含 `_ => true`**，而是显式覆盖 `UnavailableReason` 的 7 个变体。TS 的 `default` 会给未来新增的 reason 默认“提示”；Rust 选择在新增变体时编译失败，迫使调用方补规则，避免静默行为差异。
4. **`tab_settings` 新增了 `Serialize` 派生**，用于测试中与 oracle 的 JSON 逐字节比较；没有加 `Deserialize`，c2 仍按计划做 `workspace` 类型到 `config` 类型的显式转换。该派生不改变运行时行为。
5. **`terminal_font` 新增 `detected_font_family()`**，替代 TS 默认参数的 `getDetectedPlatform()`；这是平台能力，不是浏览器 API。`default_font_family()` 保留显式平台参数以便测试和 c2 复用。
6. **`tabSettings` 的默认值比较使用 oracle JSON**，没有从 `src-tauri` 的 `AppConfig` 默认值读取；后者是 c2 的逐字段比对工作，c1 不修改 `config/defaults.rs`，避免提前与 b2 的移动作业冲突。
7. **一次只跑 `cargo test -p tterm-core` 时出现过与本卡无关的偶发失败**：先是 Windows ConPTY 颜色查询测试，后是 `terminal::io_batcher::…an_echo_after_a_quiet_spell…` 的时序断言；同一条命令重跑和两次完整 `cargo test --workspace` 均通过。相关代码不在本卡改动范围，按环境偶发记录，不修改测试、不忽略。

## 遗留问题

- c2 仍需实现 `appConfig` 默认值与限额常量、`appConfigNormalize`、`localShells`、`terminalShells`；`tab_settings` 的三套 `workspace` 类型与 `AppConfig` 的 `config` 类型之间的转换也在 c2 完成。
- `shell_commands` 的 UTF-16 与 Rust 字符边界对代理对（astral 字符）的扫描在理论上不同：TS 逐代码单元扫描，Rust 逐字符扫描。对 ASCII 语法符号、引号、注释和关键字判断，两者结果相同；本卡没有新增代理对专项测试，后续若要处理极端输入可另开卡补。
- `remote_shell_integration` 的两个脚本与 TS 逐字节相等，但脚本内容仍由前端与 Rust 各保存一份；c2 是否让核心成为唯一来源不在本卡范围。
- P1-11c 计划中的 `normalizeSecretStatus`、`monitorVisibleMetrics`、`sftpStartDirectory` 等仍未完成，仍按计划留在 P1-11g/c2。
- Windows/Linux 的真实运行验证待补（决策 016）。本卡在 Windows 上完成 Rust 与前端检查；macOS/Linux 的 Rust 测试由 CI 覆盖，本机没有启动 GPUI/Tauri 窗口。
