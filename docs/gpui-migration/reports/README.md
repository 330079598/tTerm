# 迁移报告

本目录保存每张任务卡完成后的报告，以及迁移期间的持续性工作报告。报告是评估者核对验收条件的主要依据，没有写进报告的完成项视为未完成。

## 命名

| 类型                  | 文件名           | 示例                   |
| --------------------- | ---------------- | ---------------------- |
| 任务卡报告            | `<任务ID>.md`    | `W0-01.md`、`P0-26.md` |
| 上游跟踪（U-01）      | `U-01-<年月>.md` | `U-01-2026-11.md`      |
| 与 `dev` 同步（U-03） | `U-03-<日期>.md` | `U-03-2026-11-05.md`   |

- 任务 ID 与任务卡标题中的 ID 一致，不要用标题或日期做文件名。
- 同一任务卡在同一分支上只保留一份报告。评估后的补充写进原报告对应的小节，不另建文件。
- U-02 是状态维护，不单独出报告，结果直接更新 [status.md](../status.md)。

## 正文

照 [README 第 6 节](../README.md#6-报告模板)的模板写，包含下面六节：

- **结论**：完成、部分完成或未完成，一句话说明。
- **改动**：提交哈希与摘要，以及主要文件及其职责。
- **验收**：表头为“验收条件（照抄任务卡）”“结果”“证据”，逐条照抄任务卡的条件；结果只写“通过”“未通过”“未验证”，证据写命令与输出、测试名或截图路径。
- **检查**：贴出实际运行的检查命令与结果摘要。没有运行的检查不要写成通过。
- **偏差**：与任务卡不一致之处、原因与建议。
- **遗留问题**：未解决的问题、发现的新风险、建议新增的卡。

## 提交与评估

- 报告与代码或文档在同一分支提交，报告是最后一个提交。
- 评估者按报告核对验收条件与证据，给出“通过”“需修改”或“驳回”，并按 [U-02](../README.md#8-持续性工作) 更新 [status.md](../status.md) 的状态、执行者、分支与报告链接。
- 没有条件验证的项写“未验证”并说明缺少什么，不用“通过”代替。
