# P2-07 第一批：全量搜索模型执行方案

起点为本地 `GPUI` `2ba5e4c5`。本批先做模型与性能基线，不实现搜索栏 UI、快捷键或完整高亮。

## 实施范围

- 从生产终端快照生成稳定的保留历史文本视图，行坐标与 P2-06 概览标记一致；历史淘汰、清除、备用屏和 resize 后旧结果必须失效或可重新扫描。
- 支持正则、大小写和全词三个选项，复用仓库已有 regex 语义；非法正则返回可显示错误，不 panic、不把查询当普通文本偷偷改写。
- 返回全部匹配的绝对行/范围、结果计数和当前结果索引所需的数据；相邻行/折行匹配要有明确测试。
- 扫描放到 worker 可用的纯数据接口；模型锁不能在 10 万行扫描期间长时间占用。先提供可取消/generation 校验的 API，UI 在下一批接入。

## 验收

使用隔离终端合成 100,000 行，测量普通文本、正则、大小写和全词查询的耗时与分配，报告硬件、行宽、匹配数和命令；不修改性能门槛。测试覆盖空查询、无结果、非法正则、Unicode/中文、折行、输出持续增加、历史淘汰、清除、备用屏和 resize。

本批不绘制搜索框，也不伪造 P2-06 概览搜索标记；只在结果接口稳定且 generation 正确后，下一批接入高亮、概览标记、上一个/下一个和结果计数。使用独立 worktree，由 Pi + DeepSeek V4.1 Flash 实现；不读取真实连接、密钥或正式数据，不 push/merge。协调者独立复跑全套前端、Rust 和 release 检查后再决定本地合并。
