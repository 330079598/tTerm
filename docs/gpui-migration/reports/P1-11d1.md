## 偏差

1. **窗格负向越界偏移。** TS 的 `getSiblingPaneId(..., offset)` 在
   `index + offset + length` 为负时取到 `undefined`，随后访问 `.id` 抛
   `TypeError`；oracle 记录为 `{"error":"TypeError"}`。Rust 生产代码不得 panic，
   因此返回 `None`。正常快捷键只使用 ±1 至 ±9，不经过该路径。
   标签版 `getSiblingTabId` 不受影响：它直接返回数组元素，负下标得到
   `undefined`；oracle 记录 `{"value":null}`，Rust 的 `None` 与 TS 一致，不是偏差。
2. **`localeCompare`。** TS 在非编号 id 上回退到 `first.localeCompare(second)`；
   Rust 当前用 `str::cmp`（UTF-8 字节序）。差异不限于非 ASCII：纯 ASCII 的
   `compareTabIds("B", "a")` 在 TS 得 `1`、Rust 得 `-1`；重音与非拉丁 id 也会不同。
   既有 TS 用例只比较 `a`/`b`，这两种顺序恰好一致。生产标签 id 由
   `useTabs.ts` 的 `tab-${++counter}` 生成，都匹配 `^tab-(\d+)$`，不会进入该回退。
   本轮按评估要求先不改实现，是否接受 locale 差异由 stone 决定。
3. **`fillShape` 输入不足。** TS 在 `tabIds` 少于 pane 数时产生
   `tabId: undefined`，`JSON.stringify` 省略该字段；Rust 的 `String` 只能是空串。
   这是无效输入；唯一生产调用方 `applyTemplateToGroups` 会先检查数量，不足时原样
   返回，不会调用 `fillShape`。
4. **数字 API 收窄。** `getTabIdAtPosition(position)`、`getSiblingTabId(offset)`
   和 `dragSash(index)` 在 TS 里是 `number`；Rust 用 `i64`，无法表达小数。TS 传入
   小数会得到 `undefined`，Rust 在类型层拒绝。所有合法调用方都用整数。
5. **DOM 与 hooks。** `tabNudge` 不再操作 class/`scrollIntoView`，改为
   `TabNudgeState`；`tabAttention` 的模块全局状态改为 `TabAttentionStore`，hooks
   改为查询方法，`setTimeout` 改为调用方传入的 `now_ms` 与 `advance_to`。P3 工作区
   视图负责订阅状态并绘制动画/滚动。
6. **模块单例。** `appNavigation` 的模块级 handler 改为 `AppNavigation` 实例；
   原生端只有一个实例。取消函数改为返回 id，行为相同。
7. **翻译与日志依赖。** `tabMenuActions` 的 i18next `t` 改为 `Translate` 闭包；
   `getTabLogMenuActions` 的记录状态由 `log_recording: bool` 输入，等待 P1-11g 的
   `terminalLogRecording` 移植。`hasTabIcon(tab)` 只依赖 `isSessionTab`，因此没有
   移植第 2 组的整个 `tabIcons`。
8. **类型子集。** `Tab`/`TabConnection`/`TabContextMenuAction` 只包含本组读取的
   字段；第 2 组会在同一模块补全。`separator` 在 TS 是可缺省字段，Rust 用 `bool`，
   不参与持久化，P3 适配时把 `false` 视为非分隔符。
9. **持久化容器。** `tabGroupsPersistence.ts` 属于第 2 组，本轮不实现其完整逻辑；
   `persistence.rs` 只用测试局部 `SavedTabGroups` 容器验证 `PaneNode` 的序列化字节。
   `PaneNode` 已去掉 `Deserialize`：TS 的 `readPaneNode` 会把非数字尺寸当成 0，
   并由 `flatMap` 只丢弃坏组；直接 derive 会拒绝自身写出的 `sizes:null`，也会让整份
   文档失败。宽松读取留给第 2 组移植 `readPaneNode` 时提供。现有持久化测试只证明
   写出和 `zoomedTabId` 省略，不证明 `PaneNode` 能读回。
10. **实现修正。** `minimum_extent` 的跨轴 `Math.max` 现在传播 `NaN`（与 JS 一致）；
    `set_tab_running_agent` 把空字符串视为 `None`（与 TS 的 `if (agent)` 一致）；
    `drag_sash` 的 index 加法用 `checked_add`，避免 `i64::MAX` 溢出；兄弟偏移计算
    使用 `i128`，避免大数组长度与偏移相加溢出。

### 1. 阅读顺序与 V8 排序

`sortPanesByReadingOrder` 不再调用标准库 `sort_by`，而是按 V8
`array-sort.tq` 的短数组路径实现 `CountAndMakeRun` 和 `BinaryInsertionSort`。
输入先经 `isVisible` 过滤，再在过滤后的数组上执行，因此阈值与 TS 的排序数组长度
一致。比较函数的浮点比较顺序、降序 run 反转和二分插入位置都照 V8；非传递比较不会
触发 Rust 的排序 panic。

oracle 用真实 TS 生成了三列各两格、下格顶边为 209/207/205 的例子及全部 720 种输入
排列。`oracle_breaks_the_reading_order_cycle_like_v8` 断言示例排序与
`getSiblingPaneId(..., "R1", 1)`；`oracle_matches_v8_for_every_permutation...`
逐项断言 720 个排序和 sibling。另有 70 个窗格的非传递输入，在 `catch_unwind` 下
断言不 panic、结果仍含全部 70 个 id。

长度达到 64 时 V8 进入归并路径；本实现为绝对不 panic 继续使用同一短数组算法，
因此 64 个及以上元素的结果可能与 V8 不同；该路径仍不会 panic。这个已知差异在
报告中保留。

### 2. `PaneNode` 读取

本组列出的 TS 函数都不从 JSON 读取 `PaneNode`，因此移除了它的 `Deserialize`，
只保留与 `JSON.stringify` 一致的 `Serialize`。第 2 组移植 `readPaneNode` 时会在同一
`tab_groups.rs` 补宽松读取：非数字尺寸按 TS 记为 0，坏组由组读取器丢弃，而不是让
整份文档失败。`persistence.rs` 现在只声明验证写出；`zoomedTabId: null` 的容器测试
不再被描述成 `Vec<f64>` 接受 `null`。

### 3. 浮点解析

`tterm-core` 的 `serde_json` 同时启用 `float_roundtrip` 与既有 `raw_value`。
`Cargo.lock` 未因这两个 feature 改变。`dragSash([0.5,0.5], 0, 37, 1003, [200,200])`
的 TS 结果 `0.46311066799601197` 现在解析后位模式不变，写回也是同一串。
`oracle_drag_sash_results_roundtrip_byte_for_byte_through_json` 遍历 oracle 的全部
`dragSash` 用例，`oracle_parses_the_seventeen_digit_drag_result_exactly` 单独锁定该值。
feature 在 workspace 统一生效，因此 Tauri 读取恢复数据时也会从原来的 1 ULP 偏差
变为精确解析。

`4136742f` 是在验证时发现 `45607b4e` 误删了原有 `raw_value` feature 后的修正；
两者现在并存。

### 4. `Math.round`

`js_round` 对正值取 `floor`、对负值取 `ceil`，负半 ULP 不越过半数边界：
`0.49999999999999994` 得 0，`-0.49999999999999994` 得 `-0`。绝对值不小于
`2^52` 的有限值原样返回，因为该范围的 f64 已是整数。NaN、Infinity 和 `-0`
原样传播。`oracle_js_round_matches_math_round` 用 node 的 `Math.round` 生成输入、
输出，并逐项比较位模式。

### 5. 空字符串窗格 id

`get_sibling_pane_id` 与 `find_pane_in_direction` 现在用 `Option<&str>` 的存在性
表示“有 active id”，不再把 `Some("")` 当成缺失。oracle 的
`paneNavigation.emptyId` 用 `[{id:""},{id:"x"}]` 生成 sibling 与 direction 期望；
两个 Rust 测试分别覆盖存在空 id 和没有空 id 的输入。
