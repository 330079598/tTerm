# 008 实现终端的执行者可以阅读 Zed 终端源码

- 日期：2026-11-07
- 决策人：stone
- 状态：已决定（替代[决策 007](007-official-sources-and-terminal-route.md) 第 3 条的 Zed 净室规则）

## 背景

决策 007 规定只有 P0-27 的执行者阅读 Zed 的 `terminal` 与 `terminal_view`，并写成纯文字设计说明 `terminal-design.md`；实现终端的执行者不得阅读。P0-09、P0-10 按这条规则完成，报告声明了未阅读。

后续的卡（P0-12 的滚动与锚定、P0-13 的输入与输入法、P2 的终端功能）细节多，只靠设计说明，执行者要自己重新摸索 Zed 已经解决过的边界情况。决策人决定放宽这条规则，用“不复制”代替“不阅读”。

## 决定

1. 从 2026-11-07 起，实现终端的执行者可以阅读 Zed 的 `terminal`、`terminal_view` 源码，同时继续以 [terminal-design.md](../terminal-design.md) 为主要依据。
2. 只能借鉴实现思路，不得复制 Zed 的代码、注释、测试或私有标识符，也不得逐个函数翻译或照搬模块结构。代码按 tTerm 的模块划分与仓库规则重新写。
3. 不引入任何 GPL 依赖，这一点不变。
4. 报告不再声明“未阅读 Zed 终端源码”，改为列出阅读过的 Zed 提交与文件，并声明没有复制代码、注释、测试或私有标识符。
5. 评估者对照报告列出的 Zed 文件抽查实现，发现结构、命名或注释与 Zed 相近时要求重写。
6. 已经通过的 P0-09、P0-10 不受影响，它们的“未阅读”声明保持原样。

## 影响

- 文档：README 执行规则第 6 条、技术选型第 5 节、验收协议的 G1 标准、`third-party.md`、`terminal-design.md` 第 0 节与第 11 节、P0-12、P0-13 与 P2 的前提随之修改。
- 尚未开始的终端卡改为按第 4 条写报告。

## 风险

- **许可风险上升。** Zed 的终端 crate 是 GPL-3.0-or-later，tTerm 是 MIT。读过源码再写出的相近实现，比净室流程更难证明不是衍生作品。第 2、4、5 条用来降低这个风险，但不能消除它。
- **抽查依赖评估者。** 第 5 条的审查只能发现明显的相似之处。执行者越依赖 Zed 的写法，评估越难判断。
