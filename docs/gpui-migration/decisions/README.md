## 命名

- 文件名：`NNN-<短名>.md`，`NNN` 是三位补零的编号，如 `001-formal-migration.md`、`006-w0-01-ci-waiver.md`。

## 正文格式

照 001 与 006 的写法，文首列出元信息，正文分节说明决定与影响：

```markdown
# NNN <标题>

- 日期：YYYY-MM-DD
- 决策人：<姓名>
- 状态：已决定 / 待确认 / 已替代

## 决定

1. ...

## 影响 / 风险

- ...
```

001 使用“对原计划的影响”与“仍然成立的风险”两节，006 使用“背景”“决定”“风险”。两种都可以，但必须包含日期、决策人、状态、决定，以及影响或风险。背景较长时在“决定”前加一节“背景”。

## 何时需要记录

- [README 第 4 节](../README.md#4-架构约定)的架构约定（A1–A10）需要变更时。修改先在记录中说明，经评估通过后再改代码。
- [验收协议第 4 节](../acceptance.md#4-关卡标准)的 G1–G4 结论确定时。关卡结论由评估者建议、决策人确认后写入。
- 其他影响多张卡的决定：放弃某个功能、缩小平台范围、更换依赖来源、改变持久化格式或应用标识。
- 只影响单张卡的实现选择写进该卡的报告，不占编号；需要后续卡共同遵守时才写进本目录。
