# 016 macOS 与 Windows 同等，有哪台用哪台；Linux 推迟到 Linux 发布前

- 日期：2026-11-09
- 决策人：stone
- 状态：已决定。替代[决策 012](012-windows-first.md) 第 1 至 3 条中的平台顺序；012 第 4、5 条（Windows 对比通道的做法、三处替代画法）仍然有效。

## 背景

决策 012 定了 Windows 优先、macOS 与 Linux 的验证推后。之后 P0-24 的 8 个组件都是在 Mac 上做完并达标的，决策人手头 macOS 与 Windows 机器都有，只有 Linux 没有机器。按 012，在 Mac 上做完的工作还得等 Windows 复跑才算数，这会拖慢进度。

## 决定

1. **macOS 与 Windows 同等。** 任务卡的平台验收项在当时手头有的那台机器上做，过了这张卡就算通过。另一个平台的同一项记为“待补（决策 016）”，不阻塞关卡和后续的卡。
2. **待补项在该平台发布之前补齐。** macOS 的待补项在发布 macOS 版之前补齐，Windows 的在发布 Windows 版之前补齐。评估者在 `status.md` 的状态里写明哪个平台待补，方便以后汇总。
3. **Linux 的验证全部推迟到 Linux 发布之前**，记为“推迟（决策 016）”。这包括 P0-16 与 P2-11 中的 Linux 输入法矩阵、P0-17 与 P2-25 中的 Linux 无 GPU 环境、P3-01 的 Wayland 装饰、P5-07 的 Linux 部分，以及其他只能在 Linux 上验的项。Linux 发布前另开补验证的卡。
4. **代码仍按三平台编写，CI 仍在三平台编译和测试。** 推迟的是需要 Linux 桌面的人工或真机验收，不是 Linux 代码。CI 中 Linux 编译或测试失败照样要修。
5. **跨平台的对比要用同一平台的数据。** 例如统一性能对比（决策 015 第 5 条）在哪个平台测，就用 P0-01 在同一平台的基线：Windows 已有基线，macOS 要先补。

## 影响

- P0-24 的 8 个组件已在 macOS 深浅两种主题下达标，满足 G1 的界面对齐条件。Windows 通道对比改为待补，不再是 G1 门槛。
- 按[决策 015](015-trim-p0.md)，G1 之前只剩精简版 P0-22。
- P0-26 已在 Windows 验证从 Tauri 版自动升级到 GPUI 程序，满足 G1 的升级条件；macOS 待补。
- G1 至 G3 中写着“三平台”或“macOS 与 Windows”的条件，按本决策理解：手头一个平台通过即可，另一个待补，Linux 推迟。G4（正式切换）按发布的平台逐个要求，发布哪个平台，那个平台的待补项就必须全部清零。

## 风险

- 只在一个平台上验过的东西，换到另一个平台可能出问题，尤其是输入法、窗口装饰、签名和钥匙串这类平台相关的部分。待补项越积越多，发布前的补验证工作就越集中。评估者每过一个关卡汇总一次待补清单，量大时提醒决策人先补。
- Linux 推迟最久，GPUI 在 Linux 上已知的问题（输入法、无 Vulkan 的机器，见 ui-parity.md 第 4 节）到 Linux 发布前才会正面处理。如果到那时问题绕不过去，可能需要推迟 Linux 版，或继续为 Linux 发 Tauri 版。
