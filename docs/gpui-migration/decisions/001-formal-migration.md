# 001 正式迁移到 GPUI

- 日期：2026-11-05
- 决策人：stone
- 状态：已决定

## 决定

1. tTerm 正式从 Tauri + React 迁移到 GPUI，GPUI 版替换现有正式版本。
2. 界面目标：与现有 Tauri 版一致，不借迁移重新设计。“一致”的定义与门槛见 [ui-parity.md](../ui-parity.md)；做不到的项按该文第 4 节的替代画法处理。
3. 在本仓库中进行，不新建仓库：GPUI 界面从零编写，Rust 业务核心由两个客户端共用。workspace 根移到仓库根目录（修订 README 约定 A1），布局见 [tech-selection.md 第 2 节](../tech-selection.md#2-仓库形态不新建仓库)。
4. 技术选型见 [tech-selection.md](../tech-selection.md)。
5. 验收由 Claude 评估，关卡结论由决策人确认，规则见 [acceptance.md](../acceptance.md)。

## 对原计划的影响

- **G0 不再决定是否迁移。** P0-01 至 P0-05 照常执行，作用变为：给 P0-21 和 G4 提供性能基线；找出 Tauri 版内可以先修的问题（例如 macOS 透明与模糊的开销），在迁移的这几个月里改善现有用户的体验。
- **G1 不再决定是否迁移，改为决定是否进入 P1。** G1 发现阻塞时，结论只能是调整方案或缩小平台范围，例如某平台暂缓切换，而不是放弃迁移。
- README 第 9 节的待决定事项：视觉目标已定为一致；其余三项按 README 的建议执行，除非另有决策记录。
- 新增任务卡 W0-04、W0-05、UP-03、P0-24、P0-25、P0-26，总工作量约 105–145 人周（ui-parity 第 7 节）。

## 仍然成立的风险

迁移计划与[验证报告](../validation-2026-11-05.md)列出的两个平台风险没有因为这个决定而消失：Linux 输入法（nyaterm #1017、#1073）与无 GPU 环境（#938 不修）。P0-16、P0-17 必须在 G1 前完成。
