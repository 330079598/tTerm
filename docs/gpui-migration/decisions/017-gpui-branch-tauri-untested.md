# 017 GPUI 分支只保证 GPUI 版正常，不再人工验证分支上的 Tauri 版

- 日期：2026-11-11
- 决策人：stone
- 状态：已决定。修改 README 第 2 节执行规则第 2 条，以及 P1 各卡中“在 Tauri 版中手工验证”的验收项。

## 背景

P1 的卡是对 Tauri 后端的重构。原来的规则要求 Tauri 版的行为不变，并且每张卡都要在隔离标识下手工点一遍 Tauri 版的界面。但 `GPUI` 分支上的 Tauri 版不会发布：发布线是 dev，`GPUI` 分支最后会删除全部 Tauri 代码。在这个版本上做人工验证、隔离运行和性能对比，花了大量时间，得到的只是对一个即将删除的客户端的保证。

## 决定

1. **`GPUI` 分支只需要保证 GPUI 版的 tTerm 正常。**以后的验收、人工验证和性能对比都针对 GPUI 版。
2. **不再对 `GPUI` 分支上的 Tauri 版做人工验证。**任务卡和报告中不再列“在 Tauri 版中手工验证”“附操作录屏”“[人工] Tauri 界面”这类项；已有的这类项视为取消，不需要补做。执行者也不需要以隔离标识启动 Tauri 版。
3. **不再为分支上的 Tauri 版单独测性能。**例如 P1-06 那样的改动前后吞吐与内存对比。
4. **自动化检查照旧。**AGENTS.md “Before you finish” 的全部检查和 CI 仍然必须通过：仓库规则要求，而且这些测试大部分在测 core 逻辑，GPUI 版也要用。为了让检查通过，Tauri 代码要能编译、现有测试要能跑。但不必再为保持 Tauri 版的事件名、payload、command 签名额外设计核对手段，例如 P1-07 计划中的 `command-signatures.mjs`。改了它们以后前端测试或类型检查失败，就照常修。
5. **仍然针对 Tauri 版的例外：**
   - 发布线上（dev 与正式发布）的 Tauri 版照常测试。
   - P1-12（localStorage 迁到后端）与 P5-03（Tauri 版升级到 GPUI 程序的过渡版）必须随一个正式的 Tauri 版本发布，验证按各自任务卡在发布线上做。
   - W0-05 等对比的参照端渲染的是 Tauri 前端，那是 GPUI 版的参照，不受影响。
   - 最终的统一性能对比（P5-07）用发布线上的 Tauri 版作基线。
6. **真实数据的保护不变。**执行者仍然不得以 `com.stone.tTerm` 或 `com.stone.tTerm.dev` 运行任何版本，也不得读写这两个目录（dispatch.md 第 5 节）。

## 影响

- P1-03 至 P1-08 报告中待做的 Tauri 界面人工验收全部取消。
- P1-07 计划第 4 节的“人工”与 `command-signatures` 两项取消。骨架批次已经派出，评估时按本决策处理。
- 风险：Tauri 胶水层（`event_sink`、`session_sink`、平台 trait 的 Tauri 实现）里没被测试抓到的问题不会被发现。这一层最后会删除，可以接受。core 层的问题会在 P2、P3 用 GPUI 界面走同样流程时暴露。
