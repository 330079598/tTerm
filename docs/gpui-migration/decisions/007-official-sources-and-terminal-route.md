# 007 只用官方来源，终端以官方 Alacritty 为内核自己搭建

- 日期：2026-11-05
- 决策人：stone
- 状态：已决定（替代[技术选型](../tech-selection.md)初稿第 3、5 节中“使用 nyaterm 的分支组合、整体复用 nyaterm 终端”的方案）；第 3 条的净室规则由[决策 008](008-zed-terminal-reading.md) 替代

## 背景

初稿选择 nyaterm 作者（GitHub `nyakang`）的 Zed、gpui-kit、Alacritty 分支，并整体复用 nyaterm 的两个终端 crate。决策人担心依赖个人维护的非官方仓库，日后可能无人维护。2026-11-05 的核对结果：

| 分支                | 比官方多                    | 内容                                                                                         |
| ------------------- | --------------------------- | -------------------------------------------------------------------------------------------- |
| `nyakang/zed`       | 38 个提交，+7,607 行        | 主要是嵌入原生子窗口（nyaterm 的 RDP、VNC）与文件拖出；另有 Windows 输入法、图集分配等小修复 |
| `nyakang/gpui-kit`  | 37 个提交，约 +1,000 行代码 | 大多是让组件库跟随上面的 GPUI 分支，以及 nyaterm 自己的外观调整                              |
| `nyakang/alacritty` | 2 个代码提交，+121 行       | 滚动计数与屏幕版本号，只为 nyaterm 终端模型的滚动锚定服务                                    |

另外核实：

- nyaterm 终端绘制层没有使用 nyakang Zed 分支独有的接口。
- Zed 自己的 Alacritty 分支只改了启动 PTY 时的信号屏蔽，tTerm 用不到。
- nyaterm 项目 2026-04 创建，6 个月约 3,900 次提交，48 个未关闭的 bug；终端代码测试充分，但大文件多，需要大改才符合本仓库规则。
- Alacritty 不是用 GPUI 写的，它的绘制层不能直接使用；它的应用层代码是 Apache-2.0，可以复制。

## 决定

1. **只用官方来源，不 fork 任何仓库，不引入 git 依赖：**

   | 依赖     | 来源                                                                        | 停止维护时的退路                             |
   | -------- | --------------------------------------------------------------------------- | -------------------------------------------- |
   | GPUI     | crates.io `gpui-pre =0.3.11`（官方 `zed@f816e1f` 的快照），经 gpui-kit 带入 | 直接依赖官方 `zed-industries/zed` 的固定提交 |
   | 组件库   | crates.io `gpui-kit =0.9.0`（Longbridge 团队）                              | Apache-2.0，fork 后自己维护用到的部分        |
   | 终端内核 | crates.io `alacritty_terminal =0.26.0`，不打补丁                            | 官方长期维护的项目；必要时向官方提交补丁     |

2. **终端自己搭建，按来源分四块：** 内核用官方 Alacritty；模型、绘制元素、滚动、输入法自写，架构按净室流程参考 Zed；按键与鼠标协议、内置字形、链接识别从 Alacritty 应用层复制改写；关键词高亮等独立模块从 nyaterm 挑选，先过质量关卡。细节见[技术选型第 5 节](../tech-selection.md#5-终端)。
3. **Zed 净室规则**（2026-11-07 由[决策 008](008-zed-terminal-reading.md) 替代）**：** 只有 P0-27 的执行者阅读 Zed 终端源码，产出纯文字设计说明；实现终端的执行者不得阅读，报告中声明。
4. **需要给 GPUI 打补丁时**（最可能是 Windows 输入法），用 `[patch.crates-io]` 替换同版本的 `gpui-pre` 源码，不 fork 整个 Zed。P0-06 先实测这条退路。

## 影响

- 任务卡：P0-06、P0-07、P0-09、P0-10、P0-12、P0-13、P0-19 改写；新增 P0-27（净室设计说明）、P0-28（移植 Alacritty 应用层）、P0-29（nyaterm 模块挑选）。
- 决策人不需要 fork 任何仓库。
- 工作量：终端部分比整体复用 nyaterm 多约 4–8 周，总量约 110–155 人周。
- 自写的终端代码从第一天起遵守全部仓库规则，不再需要验证分支上的大小豁免；只有原样复制的第三方代码仍可暂放 `migrate/spike`。

## 风险

- **回滚区写满后的锚定**没有内核支持，P0-12 要找到不改内核的做法，或向 Alacritty 官方提交补丁；在此之前行为以 xterm.js 为准。
- **Windows 输入法**可能需要 nyakang 那个补丁的等价修复，届时按第 4 条处理。
- **`gpui-pre` 由第三方打包。** 代码是官方的，但发布节奏取决于 gpui-kit 维护者；停止发布时按第 1 条的退路切换。
