# 009 重启后自动续接 AI 会话

- 日期：2026-11-07
- 决策人：stone
- 状态：已决定

## 背景

使用者在 tTerm 中运行 Claude Code 或 Codex 时，不小心完全退出了 tTerm（关闭窗口、从托盘或菜单退出），重新打开后希望回到原来的会话。

现有的会话恢复（`TTermApp/useSessionRestore.ts`）会恢复标签、分组、分屏，并在开启“恢复终端内容”时回放关闭前的屏幕内容，但 shell 与 SSH 连接都是新建的。tTerm 退出时 PTY 关闭，其中的 AI 工具进程随之结束，对话无法继续。

可以做到三个层次：

| 层次 | 效果                                                                           |
| ---- | ------------------------------------------------------------------------------ |
| L1   | 现状：恢复布局与屏幕内容，下面是新的 shell                                     |
| L2   | 在 L1 之上，重开后在原来的目录中用 AI 工具自己的续接命令打开同一个会话         |
| L3   | 由后台的会话宿主进程持有 PTY 与 SSH 连接，退出界面不结束进程，重开后重新接上它 |

## 决定

1. **做 L2，不做 L3。** 重开 tTerm 后，退出时仍在运行 AI 工具的标签，在原来的工作目录中执行该工具的续接命令，接上同一个会话的对话。进程是重新启动的：退出那一刻正在生成的回答或正在执行的工具调用会中断，这是可以接受的。
2. **本地终端与 SSH 会话都要支持。** 本地包括 macOS、Linux 的 shell，Windows 的 PowerShell、cmd 与 WSL。SSH 会话在重新连接并认证成功后续接。
3. **至少支持 Claude Code 与 Codex。** OpenCode 与 pi 有可靠的续接命令时一并支持，没有时在报告中说明。
4. **按会话 ID 续接，不用“最近一次会话”。** 同一个目录里可能有多个标签运行同一个工具，“最近一次”会接错会话。会话 ID 来自 tTerm 已经装进这些工具的钩子（`src-tauri/src/agent_integration/`）。
5. **用户退出了工具的标签不续接。** 只有 tTerm 退出时工具仍在运行的标签才续接；用户自己退出工具后，标签按 L1 恢复。
6. **可以关闭。** 设置中提供开关，默认开启。
7. **按执行规则第 9 条处理。** 这是迁移期间的新功能：先在 Tauri 版实现，判断与构造命令的逻辑写在可以移入 core 的 Rust 模块中，登记到 `feature-matrix.md`；GPUI 版在 P3-10 中按同一保存格式实现。任务卡为 [N-01](../new-features.md#n-01-重启后续接-ai-会话)。

## 影响

- 架构约定 A2、A5、A6 不变：不做 L3，会话仍由界面进程持有，不需要跨进程的会话接口。
- 保存的工作区为终端标签增加一个可选字段，记录续接所需的信息。这是执行规则第 4 条所说的持久化格式变化，N-01 要同时提交兼容说明与测试：旧版本读到新字段时忽略它，新版本读到没有该字段的旧文件时按 L1 恢复。
- P3-10 增加对应的工作与验收。

## 风险

- **续接命令由各工具决定。** Claude Code、Codex 的命令与参数可能随版本变化。N-01 以实现时官方文档与本机实测为准，在报告中记录测试过的版本；命令写在一处，便于以后修改。
- **恢复时自动执行命令。** 在远程服务器上自动执行命令要谨慎：只执行 tTerm 自己构造的续接命令，参数经过校验与按 shell 转义，不执行任何保存下来的任意文本。
- **钩子没有安装时无法续接。** 会话 ID 依赖 tTerm 的 AI 工具集成；没有安装集成的工具、或远程主机上没有安装集成时，该标签按 L1 恢复。
