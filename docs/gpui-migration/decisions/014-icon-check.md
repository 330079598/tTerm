# 014 图标用独立检查代替逐像素比较

- 日期：2026-11-09
- 决策人：stone
- 状态：已决定

## 背景

P0-24 对比 PasswordInput 的眼睛图标和 Select 的下拉箭头时，屏幕颜色门槛每屏有 57–142 个像素超限，最大 CIEDE2000 约 2，全部落在图标笔画的边缘上。评估者核对后确认：两端的墨量（像素与背景的 Lab 距离之和）相差 0.1%–2%，墨量重心相差不到 0.01 个物理像素。也就是说形状、大小、位置都一样，差别只在 WebKit 的 CoreGraphics 与 GPUI 的 resvg 对笔画边缘做抗锯齿的方式不同，和文字字形的光栅化差异是同一类。之后几乎每个组件都有图标。

## 决定

1. 参照端的每个可见 `<svg>` 都记为图标（布局 JSON 的 `icons`：位置、`color` 与有效不透明度）。图标框及其外 2 个物理像素不参加逐像素的屏幕颜色门槛。遮文字后的 SSIM 仍然包括图标。
2. 每个图标改用三项检查，都在参照图标框内，对两张截图做：
   - 墨量：两端之比在 1 ± 0.03 之内；
   - 墨量重心：相差不超过 0.25 个逻辑像素；
   - 笔画实色：参照端完全覆盖的像素（墨量达到最大值的 90% 以上）取平均颜色，两端的 CIEDE2000 不超过 1。
3. 只有参照端记录图标，GPUI 端不记录，所以检查不会采信被检查一方的自报数据。图标画错位置会使框内墨量减少；画到框外会被逐像素门槛抓到。
4. 门槛数值不变。这是比较规则，不是例外，不在 `parity/exceptions.md` 登记。

## 影响

- 图标的形状细节（例如换成墨量与重心都相近的另一个图标）不再逐像素比对。反向探测表明，把 Eye 换成 EyeOff 时墨量差 14%，仍然会失败。
- Windows 通道的 Edge（Skia）同样适用这条规则。
- 实现见 P0-24 的 `compare/icons.rs`，规则说明在 [parity/README.md](../parity/README.md) 第 7 节。
