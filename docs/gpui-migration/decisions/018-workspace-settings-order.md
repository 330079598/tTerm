# 018 先补界面对照，再走通设置与终端的日常操作

- 日期：2026-11-23
- 决策人：stone
- 状态：已决定。调整 W0-05、P2、P3 与 P4 设置的实施顺序，不改变视觉目标和 G2～G4 的通过条件。

## 为什么改顺序

设置按钮已经可以打开页面，返回时也能恢复原窗格，但页面只有返回按钮、标题和回滚行数。P3-09 的路由测试证明了会话没有丢失，不能证明原版侧栏、搜索和内容区已经还原。[W0-05](../reports/W0-05.md) 的工作区参照原定在 P3 前完成；现有标题栏和端口转发截图不能代替整批基线。

## 实施顺序与交付物

1. **下一张：W0-05 工作区与设置首页参照首批。** 对照[逐屏清单](../parity/screens.md)和 `parity/screens.json` 盘点 B1 外壳、B2 标签、B3 分屏、B4 关闭保护与浮层：区分可复现、缺夹具、须人工的状态，不重做已有参照。首批复现 `workspace.titlebar.default`，新增 `settings.layout.default` 和 `settings.search.results` 的原版参照（含输入搜索词、选择结果的操作）。交付 manifest、隔离夹具、截图、布局 JSON 和复现命令；记录平台、窗口尺寸、主题、风格与缩放。其余 B1～B4 缺口按原批次补齐；这张卡不改 GPUI 产品页，也不把三屏算作 W0-05 完成。
2. **界面线：从设置返回同一个运行中的终端。** 有上述参照后，以 P3-02 的配置状态、P3-05 的主题和 P3-06 的组件为基础，只提前实现 P4-15 中这条流程所需的设置外壳、侧栏、搜索和内容区。用已接入的回滚行数验证：从原窗格打开设置，找到该项，修改并保存，运行中的终端无需重启即生效；返回时焦点、后台输出和非均分布局不变，重新打开仍能读到保存值。不摆放不能用的操作。按相同条件比较两端截图及布局，列明尚未实现的分类；局部通过只认对应部位，不认整屏或整张卡通过。
3. **终端线与界面线并行。** 先收 P2-06 回滚与滚动，再接依赖它的 P2-07 搜索；可独立推进 P2-11 输入法、P2-21 重连、P2-22 重排、P2-12 → P2-24 协议兼容。工作区优先验证 P3-10 实机重启恢复、补 P3-12 关闭保护。使用隔离实例验证中文输入、SSH 重连、分屏缩放和退出恢复。会丢输入、丢会话或覆盖工作区的问题优先于新页面入口。
4. **收尾 P2/P3，再做完整业务页。** P3-09 的日志、托盘、通知入口与实际可用的能力一起验，不为凑入口数制作空页面。其余 P2/P3 任务与 G2/G3 的一周日用验收照旧。两关通过后，优先完成 P4-15 设置框架和常用设置，以及连接管理 → 认证 → SFTP → 传输。其余设置随对应能力迁移，P4-25 仍等 P5-03 更新器接口。
5. **发布顺序不变。** P4-27 仍逐项核对功能矩阵；保留 P5 的升级、数据回退、统一性能对比、灰度与 G4 正式切换。Tauri 退役不提前。

## 验收与风险

提前的是一条设置操作，不是整个 P4。P4-15 仍依赖 G3，其余设置仍依赖完整框架；提前实现的部分在正式卡中复用并补验，不另做一套设置界面。平台按[决策 016](016-mac-windows-either.md)记录，原版参照按[决策 017](017-gpui-branch-tauri-untested.md)取自前端。不得以无界面测试、单端截图或路由通过替代[视觉对齐](../ui-parity.md)和桌面验收。
