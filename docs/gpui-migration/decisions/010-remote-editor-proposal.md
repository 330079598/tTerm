# 010 远程编辑器候选方案与限制

- 日期：2026-11-08
- 决策人：待评估者及决策人确认
- 状态：提议
- 依据：[P0-20 报告](../reports/P0-20.md)，gpui-kit 固定 0.9.0，无新增依赖。

## 决定草稿

建议普通文件采用 gpui-kit 自带 `Editor`，保存层独立管理原始字节、编码和换行。此草稿不授权依赖变更、不改变现有 Tauri 或 SFTP 行为。逐项结论限定于本轮 Windows 11 的测试上下文和本地临时文件：

| 项 | 结论 | 证据与替代方案 |
| --- | --- | --- |
| 撤销与重做 | 满足 | `undo_redo_and_search_replace` 通过；真实窗口快捷键焦点仍需人工复核。 |
| 查找替换 | 满足 | 同测试覆盖大小写、单次、全部和 Unicode 替换；不承诺 CodeMirror 的全部高级搜索行为。 |
| CSS 高亮 | 不满足 | 默认组合零高亮跨度；先保留纯文本，后续审批 gpui-kit 内置 tree-sitter-css 特性所需传递依赖，或调用外部编辑器。 |
| HTML 高亮 | 不满足 | 同上，候选 tree-sitter-html；嵌套 CSS/JS 另验。 |
| JavaScript 高亮 | 不满足 | 同上，候选 tree-sitter-javascript；现有 TS/TSX 等扩展名别名另验。 |
| JSON 高亮 | 不满足 | 同上，候选 tree-sitter（含 JSON）；JSONC 另验。 |
| Markdown 高亮 | 不满足 | 同上，候选 tree-sitter-markdown；内嵌代码另验。 |
| Rust 高亮 | 不满足 | 同上，候选 tree-sitter-rust。 |
| YAML 高亮 | 不满足 | 同上，候选 tree-sitter-yaml。 |
| 50 MB 文件打开与滚动 | 部分满足 | 50 MiB/51,200 行在关闭折行的测试布局中可访问中部和末尾；真实 GPU、峰值内存、其他行分布未验证。建议大文件先拒绝内置编辑并调用外部编辑器，不能把只读开关视为已经解决布局开销。 |
| 中文输入法 | 部分满足 | 预编辑协议模拟通过；真实候选框、平台转译与输入法恢复 `[人工]` 未验证。补验前可使用外部编辑器，不宣称支持真实 IME。 |
| 编码与换行格式的保留 | 部分满足 | UTF-8/BOM、UTF-16 LE/BE BOM × 三种统一换行的本地往返和修改通过；未知编码、混合换行拒绝并转外部编辑器。生产编码探测不在本卡。 |
| 保存时的冲突检测 | 部分满足 | 本地保存前比对原始字节，拒绝同尺寸外部改写；有检查/写入竞态。建议生产保存保留现有基线校验，并在单独任务中评估远程条件写入或明确提示；不保证原子 CAS。 |

## 影响与风险

- 当前默认组合不能达到七语言高亮；审批并固定所需传递依赖、完成真实窗口验证之前不能把本提议当成完整替换方案。没有必要引入新的编辑器 crate。
- gpui-kit 自述面向约 50K 行简单编辑；本轮 51,200 行的成功样例不能外推所有 50 MB 文件。正式阈值需要真实渲染与内存数据，不能从本轮测试时间推导。
- 字号、主题、行号栏按 ui-parity 第 3 节后续对齐；其余编辑器交互接受差异。未引入新的界面一致性例外。
- 不读写正式数据目录。本轮不修改生产 SFTP 保存，不连接远程主机。Windows 原生窗口、macOS/Linux 与真实输入法尚未验证；步骤见独立示例 README。
